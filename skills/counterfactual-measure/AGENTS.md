# counterfactual-measure — 반사실 측정 캠페인 (교정 → 측정 → 재개)

> **대상**: 저비용 에이전트로 실행 가능하도록 **재량을 제거한 절차**. **아래 순서를 벗어나지 말 것.**
> 전제: 레포 루트에서 실행 · `PYTHONPATH=src` · `.venv` 파이썬.
> 설계 배경: BACKLOG 반사실 하네스 항목 · 철칙 3(엔진=결정적)·철칙 4(PoB는 검증기가 아니다)·철칙 5(강제 지점).
> **저장 위치**: 계획·체크포인트·결과는 전부 **데이터 repo**(`artifacts/ingest-raw`, `poe2-ai-wiki-data`)다.
> 사용자 결정 2026-08-13 — Windows·Mac 양쪽이 이어받아야 하므로 gitignore인 `artifacts/`·`var/`는 쓸 수 없다.

## 이 캠페인이 무엇을 만드나

래더 빌드에서 노드를 **빼거나 바꿔** PoB로 다시 재서 `(문맥, 행동, Δ보상)`을 쌓는다.
코퍼스는 **채택된 것**만 알려 주고(positive only), 이것은 **버티는 것**을 알려 준다.
둘을 곱하면 「전원이 찍지만 빼도 손실 0.1%」= **메타 습관**이 드러나고, 그게 곧
갈아탈 수 있는 예산이다(BACKLOG #62).

**오래 걸리고 중간에 멈춘다.** 그래서 이 절차의 절반은 재개 규약이다.

---

## P0. 교정 — 게이트 (건너뛰기 금지)

측정 전에 **계기를 믿을 수 있는지** 먼저 재고, 축마다 쓸 수 있는 표본 수를 확정한다.
델타는 기준선에 상대적이라, 기준선이 원본과 다르면 델타는 유효하지만 **귀속이 거짓**이
된다("래더가 찍은 이 노드가 죽어 있다"가 실은 "보조가 빠진 약한 빌드에서 죽어 있다").

```bash
python -m pok.engine.corpus_fidelity survey --season 0-5 \
  --out artifacts/ingest-raw/counterfactual/0-5/fidelity.json
```

PoB도 LuaJIT도 필요 없다(복원은 base64+XML뿐) — **수집 전용 PC에서도 돈다.**

### Exit 기준 — 셋 다 통과해야 P1로 간다

| 검사 | 통과 조건 | 실패하면 |
|---|---|---|
| **① 복원** | `restore_failed == 0` | 실패 목록을 사람에게 보고. 표본에서 빼고 진행할지는 **사람 판정** |
| **② 축별 표본 수** | `usable.damage_comparable`을 계획에 그대로 쓴다 | 실측 2026-08-13: **231벌 중 46벌**뿐이다. 231로 계획하면 안 된다 |
| **③ 전제 스탬프** | `provenance.pob_commit`이 비어 있지 않다 | 스냅샷을 설치한다(`pob-snapshot` 스킬). 스탬프 없이 측정하면 재개 시 무효 판정을 못 한다 |

- ⚠ **`faithful`을 게이트로 쓰지 말 것.** 실측 2026-08-13: **0/231**이다. 231벌 전부가
  `stat_set_index`를 가정하는데(PoB 공유 코드가 계산 모드를 남기지 않는다) 형식의 정보
  손실이라 **어떤 빌드도 통과할 수 없다.** 이걸 게이트로 걸면 캠페인이 영영 시작되지 않는다.
- ⚠ **비교 가능성은 축마다 다르다.** `damage_comparable`은 「부여 그룹이 보조와 함께
  빠졌나」 하나로 딜만 본다. 그런데 실측에서 빠진 그룹이 `Purity of Fire`·`Raise Shield` —
  **방어 스킬**이었다. 방어 축을 잴 거면 `dropped_granted`의 **스킬 이름을 직접 보고**
  판정한다(엔진은 어느 축인지 판정하지 않는다 — 철칙 3).

### ②를 그래프와 대조한다 (하네스 도착 후)

`removable_nodes`가 "빼도 안전"이라 한 후보 전량에 대해 측정 결과의 `pruned`가 실제로
비는지 **일치율을 낸다**. 어긋나면 우리 트리 그래프가 PoB의 트리와 다르다는 뜻이다
(전례: BACKLOG #41 전직 트리 `connections` 빈 배열 · 블러드 메이지 시작 링크 누락으로
전직 권역이 통째로 고아였다). 일치율 100%가 아니면 **측정하지 말고 보고**한다.

## P1. 계획 — 완전성 기준을 먼저 고정한다 〔구현 대기: 하네스 병합 후〕

`fetch-plan`/`fetch-status` 패턴을 그대로 쓴다(`kb-ingest`와 같은 이유 — PC 간 충돌
회피가 이미 검증됐다).

- `counterfactual/<season>/measure-plan.json` — **작업 목록**(빌드 × 섭동 종류 × 후보).
  한 번 만들면 불변이다. 이것이 **완전성 기준**이고, 나중에 "다 했나"를 여기에만 묻는다.
- 계획에는 P0의 `usable` 수치와 `pob_commit`을 **박아 넣는다.** 계획이 어느 전제에서
  만들어졌는지가 없으면 재개 판정을 할 수 없다.

## P2. 측정 — 멱등하게, 조금씩 〔구현 대기〕

- `measure-status.json`에 완료 단위를 적고, 재실행은 **완료분을 건너뛴다**(멱등).
- 결과는 **빌드 단위 append**. 한 파일에 전부 쌓지 말 것 — 중단 지점에서 파일이 깨진다.
- 모든 측정 레코드에 **필수 3종**:
  1. `pruned` 비었는지 (비어 있지 않으면 **값을 쓰지 않고** 실패로 기록 — 철칙 4)
  2. `coverage: {measured, candidates}` — 부분 데이터셋이 **전량으로 읽히는 것**을 막는다
  3. `pob_commit` — 무효화 키

## P3. 체크포인트 push — 측정 직후 〔구현 대기〕

```bash
git -C artifacts/ingest-raw add -A
git -C artifacts/ingest-raw commit -m "counterfactual: <season> 측정 진행 (done=N/M)"
git -C artifacts/ingest-raw push
```

**측정하고 push 안 하면 다른 PC가 같은 것을 다시 잰다.** 래더 원시와 같은 규율이다.

## P4. 집계 — 부분 데이터셋을 정직하게 읽는다 〔구현 대기〕

- 노드 가치 집계에는 **신뢰도를 함께** 낸다. 3벌에서 나온 값과 30벌에서 나온 값이 같게
  읽히면 안 된다(`ladder_aggregate._wilson_low`와 같은 이유·같은 방식).
- 소비 지점(트리 설계 도구)에 **자동 부착**한다 — 세션이 커버리지의 존재를 몰라도 보이게
  (철칙 5. `connect_anchors`가 `corpus`를 자동으로 붙이는 것과 같은 자리).

## 재개 규약 — 다음 세션이 이어받을 때

1. `git -C artifacts/ingest-raw pull` — **체크포인트가 먼저다.**
2. `measure-plan.json`의 `pob_commit`과 **지금 스냅샷을 대조한다.**
   - 같으면 → `measure-status.json`의 pending부터 이어간다.
   - **다르면 이어가지 말 것.** 서로 다른 계산기로 잰 값이 한 데이터셋에 섞인다.
     사람에게 보고하고, 새 계획으로 다시 시작할지 판정을 받는다(BACKLOG #58과 같은 형태 —
     검사가 스냅샷만 보고 출처를 안 보면 조용히 틀린다).
3. P0을 **다시 돌린다** — KB가 갱신됐으면 `usable` 수치가 바뀐다(싸다: PoB 불필요).

## 중간 산출물을 엔진이 쓸 때

- 부분 데이터셋은 **쓸 수 있다**(그게 이 설계의 목표다). 단 `coverage`를 보고 쓴다.
- ⛔ **`coverage` 없는 레코드를 전량으로 취급 금지.** 같은 형태의 사고가 이미 있었다 —
  프로파일 목록이 `min_count=3`으로 잘려 있었는데 선언을 안 봐서 멀쩡한 래더 빌드의
  목적지 **49%가 「표본 밖」으로 오탐**됐다(BACKLOG #67). 그때 배운 것: **선언만으로는
  안 막혔고 기본값을 뒤집어야 닫혔다.**
- 측정값이 나온다고 인게임에서 만들 수 있다는 뜻이 아니다(철칙 4). 반사실이 낸 「개선」은
  적법성 게이트를 **다시** 통과해야 한다.

## 금지 사항

- ⛔ P0 Exit 미통과 상태에서 P1 진입.
- ⛔ `pruned`가 비지 않은 측정의 값을 쓰기(그건 「A를 뺀 효과」가 아니라 「A + 알 수 없는
  N개를 뺀 효과」다. 겉보기가 정상이라 반드시 코드가 막아야 한다).
- ⛔ `knowledge/`(정본)에 측정 결과 쓰기. 측정은 재생성 가능한 파생이고, 정본 커밋을
  측정 로그로 덮는다.
- ⛔ 어느 노드를 뺄지 **엔진이 고르게** 하기(철칙 3). 후보 열거는 연결성이라는 결정적
  규칙으로만 하고, 우선순위·표본 선택은 호출자(스킬·에이전트)가 한다.
- ⛔ 체크포인트 push 없이 측정 종료.
