# 격노 아이스샷 재검증 — 새 기록에서 탐색

2026-11-05 사용자 지시. 기존 비교 이후의 알려진 회귀 시험이며 미공개 홀드아웃이 아니다.
기존 결과/평가 계획은 수정하지 않고 보존한다. 이번 결과로 일반화나 과적합 해소를 주장하지 않는다.

## 변경과 경계

- #221: 호스트가 받은 원문만 user.request로 고정한다. 모델의 user_fixed 생성·승격과
  호스트 원문 수정/삭제를 저장 전에 거부한다. 구현 선택은 다른 역할로 자유롭게 개정한다.
  기존 봉인 기록의 잘못된 역할을 자동 변환하거나 진짜 사용자 보호를 해제하지 않는다.
- #66: get_entry가 고유/함양 템플릿의 변이 조회 경로와 한계를 자동 부착한다.
  get_variant_pool은 이미 수록된 carrier_route의 공용 풀을 검색/페이지 조회한다.
  정본 형식·관계·저장 위치는 변경하지 않는다. 개별 아이템의 적격성·확률·공존을
  판정하지 않으며 전용 풀 매핑이 해결됐다고 주장하지 않는다.
- 탐색: 선택한 투자가 다른 스킬/보조/방어/자원으로 이어지는 보상 사슬을 조사하고,
  서로 필요한 부품을 함께 바꾸는 조합을 비교한다. 특정 정답 이름·상품 수는 넣지 않는다.
  이 의미 판단은 에이전트 책임이며 지침만으로 수행이 보장되지는 않는다.

## 실행 전에 고정할 것

입력은 이전과 같은 세 조건(젬링 리저네어·아이스샷·격노 스태킹)뿐이다.
새 빈 기록에 호스트 원문만 저장하고 새 native 모델 세션에서 시작한다.
이전 결정/앵커/초안·레퍼런스·비교표·누락 이름·수리 제안은 생성 세션에 전달하지 않는다.
운영자는 참고자료를 이미 아는 상태이므로 완전한 지식 차단 시험이라고 부르지 않는다.
일반 KB/인사이트/공개 웹은 허용한다. 로컬 파일·셸·앱은 기존 격리를 적용한다.

gpt-6-astra/ultra, 전체90분·턴30분 이내, stop-after3, planning-v2.
코드/방법/원문/비교 기준의 해시와 실행 전 커밋을 manifest로 동결한다.
실행 중 코드·후보·입력 변경이나 운영자 구제는 하지 않는다. 실행기에 이미 구현된
체크포인트 재개만 같은 기한 안에서 허용한다. 핵심 실험 승인 필요 시 사용자에게 제출하고
종료한다. 시간 종료·미완료도 그대로 보존한다. 단계4/새 후보 PoB 생성은 범위 밖이다.

## 판정 — 기존 결함과 새 문제를 모두 본다

기존 기능별 비교 축(고정 조건·격노·공격·치명타·아이템/주얼·스킬/보조·방어/회복·
마나/운용·정신력·구현 제약)을 유지한다. 최종 체크포인트를 동결한 뒤 이전 동결안과
사용자 레퍼런스를 비교한다. 각 행은 같은 기능/기능적 대안/누락/후보만/부적합 가능/
판정 불가를 구분한다. 동일 상품 비율이나 저장 DPS로 품질을 대신하지 않는다.

추가로 다음을 명시한다: 사용자 고정 오분류, 변이의 적용 가능성 과장, 공유 투자 활용,
채택·기각의 기회비용, 새로 생긴 적대/미공급 의존/과한 필수 조건, 시간·도구 비용,
불완전한 계산·출처, 개선 때문에 잃은 기능, 이번에 처음 발견된 모든 결함.
새 문제는 기존 항목에 억지로 넣지 말고 별도 행으로 보존한다.
검사 통과와 설계 품질은 구분한다. 알려진 목걸이 부여 정신력 결함은 채점하지 않는다.
미측정 우열은 미측정으로 남긴다. 결과가 원본과 가까워졌다는 사실만으로 성공은 아니다.

최종 보고에는 메커니즘·상세 앵커와 선정 이유, 기존 대비 변화, 새 문제와 미해결을
함께 제공한다. 동결 후 생성안을 고치지 않고 사용자 판단을 기다린다.
