# PoK 재설계 R1 — 첫 과제의 기술 검증(평가 진행 중)

2026-10-31. 정책: [BLUEPRINT](BLUEPRINT.md). 실행: [Current Plan](CURRENT-PLAN.md).
실험/한계: [검증 원장](POK_REDESIGN_VALIDATION.md). #188의 해결·품질 개선 보고가 아니다.

8회 중7회는 최종 응답과 명시된 저장 산출물이 있고1회는 시간 초과·미제출이다.
미제출의 중간 파일을 좋은 최종안으로 골라 승격하지 않았다. 아래7행은 명시된 저장 코드의 공통 검사다.

## 같은 검사로 확인한 범위

- 시안마다 독립 MCP/캐시에서 원본 코드를 복원하고 계산했다. `assume_first_stat_set=false`를 명시했다.
- 원본 조건의 계산7개, 아이템/주얼119개 개별 검사, 트리 연결·일반123/123·전직8/8·소켓 검사를 확인했다.
- 각 시안의 동일 입력을 새 PoB 프로세스5회로 추가 계산했다. 총35회가 해당 최초 계산값과 일치했다.
- 5회 일치는 그 표본의 안정성 관측이며 알려진 상류 비결정성 #132의 해결/부재 증명이 아니다.
- 검사기 통과는 모든 획득 경로·인게임 상호작용·조작감·조건 유지나 전체 빌드 품질의 보증이 아니다.

## 진단과 전달을 빌드 품질과 분리

- Wind Dancer의 자체 Gale Force를 빈 메타 젬으로 오인하는 경고를 실제 MCP/KB로 확인해 #203에 등록했다. 해당 경고를 시안 결함으로 채점하지 않는다.
- sample-07의 Herald of Thunder에 연결된 Shock Siphon은 고정0.5.4b에서 사용자 승인으로 제외된 미획득 보조다. 정본 누락/타입 오류가 아니며, 계산 진단이 이 알려진 제외 사유를 내지 않는 문제를 #204로 등록했다. 아이템119개 검사 통과와 이 보조의 획득 판단을 혼동하지 않는다. 원본은 수선하지 않았고 검토 ZIP에 별도 메모를 포함했다.
- Ghost Dance의 고정 KB description과 stats에는 회복 방식의 차이가 있다. 어느 쪽이 실제인지나 PoB 미모델링 범위는 이 대조만으로 확정하지 않는다.
- 응답의 공유코드 필드2개는 압축 해석이 실패하지만, 명시된 저장 코드7개와 추가로 확인한 원응답 링크 코드 파일5개는 해석 가능하다. 파일 링크와 코드 필드를 구분하며 이2개를 빌드 자체 불성립으로 세지 않는다.
- 검토용 XML 저장의 Windows 개행 변환은 표시 자료에서 수정했다. 원본208파일과 Notes 밖 게임 입력은 보존했다.

## 평가의 한계와 남은 작업

- 원래 #188 브리프는 복구하지 못했다. 이 과제는 새 고정 브리프 내부의 비교다.
- 원자료 참고군의 KB와 자료 동등성은 미증명이며 순수 KB 인과 대조로 쓰지 않는다. 각2회는 통계적 확증이 아니다.
- 운영 중 UI 의존성/검사/빌드의 호스트 부하가 있었고 영향은 미측정이다.
- 한 시안의 clock 사용 자기보고를 확인할 실제 호출 이벤트는 없었다. 자동 감사0은 기록된 MCP 범위이며 모든 내장 도구의 불사용을 인증하지 않는다.
- AI 기술 검토는 운영 감사와 같은 세션이다. 고유 호출 수와 설계서의 방법 설명으로 군을 추론할 수 있으므로 완전 맹검으로 표시하지 않는다. 사용자 검토 묶음에는 군 대응표를 넣지 않았다.
- 첫 기본값 복원 요청에서 false 인자를 빠뜨린 운영 실수는 초기 기록과 erratum으로 보존했다. 이 표에는 false를 명시한7개 실행만 사용했다.
- 같은 config의14개 측정은 별도로 완료했다. 합법성 이상의 메커니즘/장비/패시브/유틸/공동 재설계/과제 적합성 평가와 사용자 선호 평가는 남아 있다.
- 추가 두 과제와 별도 앵커 기록 시험, R2~R7의 계약·구현·실제 UI 통합은 미완료다.

근거는 기존 artifacts 영역의 `redesign-r1-evaluation/measurements/baseline-summary.json`과
시안별 MCP 요청/응답·전체 계산·개별 검사·35회 안정성 기록이다. 원본 조건과 이후 비교 조건은 별도 리비전으로 유지한다.
