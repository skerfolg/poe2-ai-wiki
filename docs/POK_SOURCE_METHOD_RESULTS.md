# 웹참고방법과 PoK 설계·웹 검증 방법 — 진행 결과

2026-11-05. [사전 정책과 비교 한계](POK_SOURCE_METHOD_COMPARISON.md).
기존안은 웹참고방법으로 보존했다. 새 방식은 별도 기록·모델 세션에서 같은 세 조건
(젬링·아이스샷·격노 스태킹)만 받고 출발했다. 이 문서는 생성기에 제공하지 않는다.

## 같은 설계 단계 비교

| 항목 | 웹참고방법 | PoK 설계·웹 검증 방법 |
|---|---|---|
| 선정 정보원 | PoK와 사용자 빌드/가이드가 혼재 | PoK 게임 사실·관계로 먼저 공급자와 이유 기록 |
| 웹 접근 | 일반 검색, 다른 사용자 세팅까지 읽음 | 선행 선택한 기재의 데이터/패치 원문만 조회, 일반 검색 비활성화 |
| 격노 공급 | 부재 목걸이의 영원한 격노 | 동일한 공급원, 부여12레벨·3/s와 시작 대기 명시 |
| 추가 격노/공격 축 | 치장한 자+타락 마법 루비, 눈알 왕관+신비한 격노, Fox Idol | Battle Trance·Unforgiving·광폭 품질, 고물리/기본 치확 활·말리가로 |
| 몸통/허리띠/회복 | 몽상·샤브론의 가방·생명력 플라스크 회복을 ES에도 적용 | Morior·Mageblood·도둑의 고통, 적중 회복·재생·주기 회복 결합 |
| 치명타 | 가루칸의 투지+초치명타 잠정안 | 말리가로의 고정 보너스+활 기본 치확+다이아몬드 |
| 주력 보조 | 냉기 조율·냉기 관통·초치명타·가루칸·연속 공격 | 냉기 조율·툴·바타이르·냉기 노출·효율II |
| 조립 전 기록 | 상세 앵커13묶음·결정44·근거148 | 상세 앵커16묶음·결정38·근거104 |
| 3단계 제출 | 시간 초과, 최종 제출 미완료 | 복구를 포함해 제출·검사 완료, 당시 스냅샷 보존 |
| 사용자 평가 | 아이템 선정 이유의 질적 개선을 사용자가 확인 | 아직 사용자 평가 전 |

개수는 품질 점수가 아니다. 두 결과는 서로 다른 묶음이며, 새 방식이 레퍼런스나
다른 빌드를 복사하지 않고도 여러 고유·혈통 보조·주얼 후보를 선택한 것은 관측됐다.
그러나 선정의 고점·전체 성능·일반화는 이 표로 입증되지 않는다. 효율II 채택은
새 방식에서도 남았다. 마나 자연회복을 유일한 해결책으로 강제했는지와 실제 대가는
최종 비평에서 구분해야 한다. 초치명타를 치확 증가로 오독한 이전 주장은 재사용하지 않는다.

## 실제 조립에서 드러난 문제

새 방식은 실제 초안 조립까지 진행했다. 첫 계산의 힘28 부족은 속성 배분과 장비
접사 수정으로 해소됐다. 선택형 고유 몸통의 실제 네이티브 옵션을 검사기가 UNKNOWN으로
거부한 것은 일반 선택 범위 검증(#223)으로 수정했다. 원래 실패는 보존했다.

두 번째 블록에서 실제 `assemble_pob` 성공과 공유 코드가 생성됐다. 당시 초안은
아이스샷 화살 CombinedDPS 약23,137, 생명력3,289, ES348, 명중100%, 치확38.325%였다.
연결 트리·아이템 검사도 통과했지만 이것은 최종 품질 평가가 아니다. 단일 대상
파편 다중 명중을 임의로 합산하지 않았으며, 실제 방어 하한·조건 유지와 비평이 남아
4단계 최종 제출은 끝나지 않았다. 기존 방법에는 완성 PoB가 없어 DPS 우열을 계산하지 않는다.

## 실행·개입 기록

- 최초 동결 `be6edb3`: 첫 블록 약89분13초, 단계1~3 완료, 단계4 시간 초과.
- 두 번째 동결 `886ef9e`: #223 일반 선택형 고유 검증 보완 후 추가30분 상한.
  기존 선택·아이템 원문을 바꾸지 않았고 동일 입력을 재검사했다. 단계4 시간 초과.
- 세 번째 동결 `ce85b23`: 기존 PoB 설정 카탈로그의 키·라벨·관련 조건 조회 도구를
  노출한 뒤 추가30분 상한으로 같은 세션 재개. 관련 단위7개 통과. 설정을 자동으로
  켜거나 높은 상태를 기본으로 바꾸지는 않는다.
- 세 번째 블록은4단계 제출/검사와5단계 비교·비평까지 진행했다.5단계는 약7분 뒤
  `incomplete`를 제출했다. 최종 추천2회는 비교 계약 입력 형태와 `user.request`의
  required review 때문에 거부됐다. 비평에서 Pinpoint의 피해+19.6%와 마나 비용,
  희귀 주얼·가벼운 방어 묶음의 생명력−480을 비교하고 현재안을 유지했다.
- 네 번째 동결 `7e803e3`: #224의 원문 불변 재검토 메타데이터 갱신과 기존 v2 추천
  계약 안내를 보완하고 같은 세션 재개.8단위·백로그14 통과. 사용자 요구·아이템·패시브
  정답을 보충하지 않았다. 최종 추천 거부를 이전 블록의 통과로 소급하지 않는다.

이는 변경 없는 코드의 단일90분 완주가 아니다. 일반 인터페이스·검사기 수정과
추가 시간을 포함한 복구 시험이다. 새 설계 정답·레퍼런스·기존 비교표를 전달하지
않았으며, 최초25건의 원문 영수증은 선행 공급자·PoK 근거·본문 해시와 함께 감사됐다.

## 남은 작업

네 번째 블록도 `incomplete`로 종료했다. 누적 모델 실행은9,382.36초(약2시간36분23초)이며
중간 수정·감사 시간은 별도다.4단계 초안·실제 공유 데이터와5단계 비평은 보존됐지만
최종 추천 검사는 통과하지 못했다. 프로세스 정리와 동결 소스 감사가 끝났고 원문25건,
실행 명령9개에서 출처 정책 위반은 발견되지 않았다.

최종 차단은 둘이다. 첫째, upsert가 병합 방식이어서 review 필드 생략은 삭제가 아니었다.
이 잘못된 보완은 실패 기록에 남겼고, 이후 required→reviewed만 명시적으로 바꾸며 나머지
원문·역할·공급자·review 이유/리비전을 보존하도록 고쳤다. 실제 저장 함수를 통한 회귀를
포함한9단위가 통과했지만 이 수정본으로 모델을 다시 실행하지는 않았다.
둘째, 말리가로의 `Your Critical Hit Chance cannot be Rerolled`를 PoB가 해석하지 못해
저장 비교3구성 모두 `items_pob_gaps`가 남았고, v2 추천 검사는 이를 미완료 측정으로
거부했다. 옵션 삭제·경고 제거·검사 면제로 통과시키지 않았다.

현재 초안의 준비 상태는 Life3,302, 보수 상태(전직 부여 방어막 효과 제외·바람의 무희0)는
Life3,009/ES258/물리 최대피격3,875다. 화살DPS23,137, 격노59, 명중100%, 치확38.325%,
원소저항75%, 카오스저항50%, 정신력29 여유다. 조건부 노출·동결 보상은 기본 계산에서
끄고 파편 중첩은 합산하지 않았다. 보수 상태 마나는 명중95% 산술에서 초당약4.63 부족하고
시작 마나634만으로 약137초를 계획했다. 유한 플라스크까지 고려한 원시 공급 상한은
낭비·피격·이동·충전 획득을 반영한 실전 지속시간이 아니다.

**판정**: 다른 사용자 빌드를 읽지 않고 구체적인 고유·보조·주얼 앵커를 정하고 실제
PoB까지 만드는 경로는 관측됐다. 그렇지만 이 초안은 낮은 피해/생존 수치,2접사 희귀
주얼과 비효율 경유, 조건부 보조의 효용 미검증을 남겼다. 웹참고방법보다 강한 빌드,
일관된 완전자율 완주, #188 해결 또는 실전 고점 달성으로 보고하지 않는다.

로컬 검토 파일은 분석 폴더의 `latest-valid-draft-code.txt`(공유 코드)와
`latest-valid-draft.xml`이다. 전달 준비 도구가 내보낸 별도 PoB 파일도 로컬에 보존했다.
메커니즘·세부 앵커는 같은 분석 폴더의 `STAGE3_ANCHOR_REVIEW.md`, 비교 전 정본은
`stage3-frozen-record.json`, 조립 초안은 `stage4-frozen-record.json`, 마지막 실패/비평은
`block-9-frozen-record.json`에 보존했다. 모두 기존 `artifacts/reviews/` 내부이며 gitignore다.
goal은 아직 완료 처리하지 않는다. 남은 추천 검사 경로와 실제 전달 검증을 이어가되,
이번 시험의 실패를 지우거나 개선 효과를 소급 주장하지 않는다.
