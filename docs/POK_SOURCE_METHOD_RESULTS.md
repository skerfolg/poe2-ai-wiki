# 웹참고방법과 PoK 설계·웹 검증 방법 — 진행 결과

2026-11-05. [사전 정책과 비교 한계](POK_SOURCE_METHOD_COMPARISON.md).
기존안은 웹참고방법으로 보존했다. 새 방식은 별도 기록·모델 세션에서 같은 세 조건
(젬링·아이스샷·격노 스태킹)만 받고 출발했다. 이 문서는 생성기에 제공하지 않는다.

## 같은 설계 단계 비교

| 항목 | 웹참고방법 | PoK 설계·웹 검증 방법 |
|---|---|---|
| 선정 정보원 | PoK와 사용자 빌드/가이드가 혼재 | PoK 게임 사실·관계로 먼저 공급자와 이유 기록 |
| 웹 접근 | 일반 검색, 다른 사용자 세팅까지 읽음 | 선행 선택한 기재의 데이터/패치 원문만 조회, 일반 검색 비활성화 |
| 격노 공급 | 부재 목걸이의 영원한 격노 | 동일한 공급원, 부여12레벨·3/s와 시작 대기 명시 |
| 추가 격노/공격 축 | 치장한 자+타락 마법 루비, 눈알 왕관+신비한 격노, Fox Idol | Battle Trance·Unforgiving·광폭 품질, 고물리/기본 치확 활·말리가로 |

| 치명타 | 가루칸의 투지+초치명타 잠정안 | 말리가로의 고정 보너스+활 기본 치확+다이아몬드 |

| 3단계 제출 | 시간 초과, 최종 제출 미완료 | 복구를 포함해 제출·검사 완료, 당시 스냅샷 보존 |
| 사용자 평가 | 아이템 선정 이유의 질적 개선을 사용자가 확인 | 아직 사용자 평가 전 |

개수는 품질 점수가 아니다. 두 결과는 서로 다른 묶음이며, 새 방식이 레퍼런스나
다른 빌드를 복사하지 않고도 여러 고유·혈통 보조·주얼 후보를 선택한 것은 관측됐다.
그러나 선정의 고점·전체 성능·일반화는 이 표로 입증되지 않는다. 효율II 채택은
새 방식에서도 남았다. 마나 자연회복을 유일한 해결책으로 강제했는지와 실제 대가는
최종 비평에서 구분해야 한다. 초치명타를 치확 증가로 오독한 이전 주장은 재사용하지 않는다.

## 실제 조립에서 드러난 문제

새 방식은 실제 초안 조립까지 진행했다. 첫 계산의 힘28 부족은 속성 배분과 장비
접사 수정으로 해소됐다. 선택형 고유 몸통의 실제 네이티브 옵션을 검사기가 UNKNOWN으로
거부한 것은 일반 선택 범위 검증(#223)으로 수정했다. 원래 실패는 보존했다.

두 번째 블록에서 실제 `assemble_pob` 성공과 공유 코드가 생성됐다. 당시 초안은
아이스샷 화살 CombinedDPS 약23,137, 생명력3,289, ES348, 명중100%, 치확38.325%였다.
연결 트리·아이템 검사도 통과했지만 이것은 최종 품질 평가가 아니다. 단일 대상
파편 다중 명중을 임의로 합산하지 않았으며, 실제 방어 하한·조건 유지와 비평이 남아
4단계 최종 제출은 끝나지 않았다. 기존 방법에는 완성 PoB가 없어 DPS 우열을 계산하지 않는다.

## 실행·개입 기록

- 최초 동결 `be6edb3`: 첫 블록 약89분13초, 단계1~3 완료, 단계4 시간 초과.
- 두 번째 동결 `886ef9e`: #223 일반 선택형 고유 검증 보완 후 추가30분 상한.
  기존 선택·아이템 원문을 바꾸지 않았고 동일 입력을 재검사했다. 단계4 시간 초과.
- 세 번째 동결 `ce85b23`: 기존 PoB 설정 카탈로그의 키·라벨·관련 조건 조회 도구를
  노출한 뒤 추가30분 상한으로 같은 세션 재개. 관련 단위7개 통과. 설정을 자동으로
  켜거나 높은 상태를 기본으로 바꾸지는 않는다.

이는 변경 없는 코드의 단일90분 완주가 아니다. 일반 인터페이스·검사기 수정과
추가 시간을 포함한 복구 시험이다. 새 설계 정답·레퍼런스·기존 비교표를 전달하지
않았으며, 최초25건의 원문 영수증은 선행 공급자·PoK 근거·본문 해시와 함께 감사됐다.
