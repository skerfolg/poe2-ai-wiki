## 3. 실험 설계

### 3.1 먼저 도구 표면과 실행 환경을 동결

정확한 도구 이름·입출력 스키마·서버 커밋·KB/PoB 해시를 manifest로 저장한다.
도구군은 이름 패턴이 아니라 실제 등록된 callable의 허용 목록으로 구성하고,
합성 호출이 숨겨진 최적화/조립 절차를 실행하는지도 확인한다.

| 군 | 도구 | 생성 절차/추천 관문 | 질문 |
| --- | --- | --- | --- |
| R 참고군 | 공통 원자료와 동일한 기본 PoB 입출력·계산 경로, PoK 탐색/최적화 없음 | 없음 | 과거 A 우위가 재현되는가 |
| F 기본 기능군 | KB/인사이트 조회, XML/스펙 변환, 명시적 변경·계산·비교·진단 | 기존 생성 스킬·최적화 실행 의무 없음 | 지식/계산 지원만으로 설계가 개선되는가 |
| O 선택 최적화군 | F + 현행 최적화 도구 | 선택 사용, 기존 생성 절차/최종 관문 없음 | 최적화 도구 제공이 탐색과 품질에 미치는 효과 |
| P 현행 절차군 | O와 같은 도구 | #149 기준 정상 생성·추천 절차 | 절차·증빙 부담의 합성 효과 |

주 비교는 F/O/P다. R은 원시 자료 탐색 방식의 정성적 참고군이다.
원문 브리프와 모든 서술 원문의 대응이 복구되지 않아 과거 A의 재현군이나 동등 자료의 순수 대조군으로 부르지 않는다.
F/O/P는 같은 현재 KB를 제공하고, R은 복구된 raw repo와 고정 PoB를 직접 탐색한다.
이 자료 표현/범위 비대칭을 공개하고 R/F로 KB의 순수 인과 효과를 주장하지 않는다.
R/F의 접근 경로 차이는 지식 표현·검색 비용도 포함하므로 순수 KB 효과로 부르지 않는다.
O/P 차이는 스킬·관문 묶음의 효과다. 차이가 나면 후속 실험에서 둘을 따로 분리한다.
O에서 최적화를 안 썼다면 도구 사용의 효과를 측정했다고 주장하지 않는다.
군별 지침은 과제·공통 안전/사실 규칙·군 차이 외에는 동일하게 한다.
공통 진단 호출은 허용하지만 F/O의 계산을 추천 관문으로 막지 않는다.
평가자가 종료 후 모든 군에 같은 검사를 적용하고 실패도 그대로 보존한다.

### 3.2 첫 과제와 확장

첫 과제는 기존 이동 맵핑 과제를 사용한다: 레벨100·고투자·근접 공격 번개,
이동과 짧은 공격 기회 및 처치 없는 보스 지속성. 클래스·스킬·장비는 자유다.
원래 브리프는 다른 PC에 있어 현재 제공할 수 없다고 사용자가 확인했다(2026-10-30). [새 공통 브리프](POK_REDESIGN_BRIEF.md)를 실행 전에 해시 동결한다. 새 실험 내부의 동일성만 비교하며 기존 A/B/C 원본의 재현이라고 부르지 않는다.
모든 군을 독립 새 세션에서 각 2회 실행한다. 모델은 `gpt-6-astra`, 추론 `ultra`,
하위 작업 포함 90분 상한을 유지하고 모델 가용성/실행기 지원을 먼저 확인한다.
다른 모델로 몰래 대체하지 않는다. 군별 시작 순서는 교차하고 공유 PoB 상태를 격리한다.
동일 호스트의 부하·병렬 정책도 고정한다. 중간 결과를 보고 조기 종료하거나 군 지침을 바꾸지 않는다.
순서는 F1/O1/P1/R1/R2/P2/O2/F2, 각 실행은 순차 진행하며 artifacts와 파생 캐시를 독립시킨다.
P는 생성 스킬 전문과 필요시 읽는 조립/설계 문서의 동결 사본을 제공한다.
F/O/R에는 그 절차 문서를 주입하지 않는다. 공통 파일 I/O와 사실 검증은 공유한다.

첫 과제의 결과와 실행 신뢰성 검토 후 다른 두 과제로 확장한다:
핵심 아이템 변경으로 여러 부위 재배분이 필요한 과제, 상태 전이/조건 유지가 중요한 과제.
과제와 판정 기준을 실행 전 고정한다. 첫 과제만으로 보편적 우열을 선언하지 않는다.
2회 반복은 큰 편차와 실패 패턴 탐지용이며 통계적 유의성의 보장이 아니다.

### 3.3 동일성·실패·예산

- 엔진/KB/PoB/모델/추론/원자료 범위/브리프/출력 요구를 보존한다.
- 군별 토큰·비용·대기·계산·조회·복구·문서화 시간을 가능한 범위에서 기록한다.
  제공자가 주지 않는 항목은 미측정으로 둔다. 같은 시간은 같은 추론량이 아니다.
- 새 세션의 프로젝트 지침·MCP 노출·스킬 자동 주입을 확인한다.
  F/O에 기존 생성 절차가 상속되면 해당 실행은 프로토콜 위반으로 보존하고 재실행한다.
- 모델이 쓴 대안·기각·묶음 변경은 도구 기록과 공개된 설계 설명으로 추적한다.
  내부 사고 내용을 요구하거나 추정하지 않는다.
- timeout·미제출·not_ready·부분 XML도 결과다. 사후 수선한 것을 원본 성공으로 세지 않는다.
- 실험 중 엔진 오류가 나타나면 입력·실패를 보존한다. 버전을 바꾼 반복은 별도 블록으로 분리한다.

## 4. 품질과 실행 신뢰성은 별도로 평가

군 이름을 가린 최종 XML/PoB와 같은 형식의 설명을 평가한다. 사용자가 주요 판정자다.
다음 각 축을 0~4로 평가한다(0 없음/중대 실패, 1 큰 결함, 2 기본 성립·미흡,
3 목적에 맞는 일관된 구성, 4 실물 대안과 대가까지 설득력 있음).

| 축 | 보는 것 |
| --- | --- |
| 메커니즘 | 실제 연결, 발동 주체·조건·비용·유지, 미검증 구분 |
| 장비 | 역할·획득 가능성·선택 근거·기회비용, 다른 부위 재투자 |
| 패시브/주얼 | 현재 장비·젬과 정합성, 이동 비용·죽은 투자·대안 |
| 젬/유틸 | 주력 외 이동·회복·버프, 조작과 유지 부담 |
| 전체 재설계 | 핵심 선택 변경 뒤 접사·노드·보조를 함께 조정했는가 |
| 과제 적합성 | 맵 이동·공격 기회·보스 지속성 등 브리프에 맞는가 |

점수는 근거 링크와 결함을 함께 남긴다. 총점 하나로 치명적 메커니즘 실패를 숨기지 않는다.
사용자 선호 순위와 축별 평가를 함께 보존한다. 호출 수·고유 수·포인트 소진은 품질 점수가 아니다.
계산 비교는 동일 config의 별도 재측정으로 하며 원본 config도 보존한다.
PoB 미모델링 효과와 인게임 체감은 미측정으로 남긴다.
별도 실행 지표: 제출 여부, 원본 복원, 아이템 편집/왕복, 오류·복구 시간,
검증 거짓 차단, 근거 누락, 반환 크기, 실제 변경안 재사용, 반복별 편차.

### 평가 묶음의 원본·익명성

전체8회의 실제 종료와 사후 입력 검사를 확인한 뒤 평가 묶음을 만든다.
익명 표본 ID의 대응표와 도구 이력은 실물 평가 자료와 분리하고, 원본 파일/응답의
해시·출처를 별도로 보존한다. 결과를 보고 표본을 제외하거나 순서를 골라 배치하지 않는다.
군/반복 이름이 제목·Notes·설명에 노출될 수 있으므로 실제 노출 여부를 검사한다.
식별자를 가리기 위한 표시용 편집은 그 범위와 원본을 기록하고 게임 입력을 바꾸지 않는다.
완전히 가리지 못했으면 그 표본의 비맹검 한계를 공개하며 익명 ID만으로 맹검을 인증하지 않는다.

최종 응답이 없는 실행도 하나의 표본으로 포함한다. 최종 공유코드/선언된 산출물과
중간 파일을 구분하고, 중간 산출물은 전수 목록을 남겨 좋은 것만 사후 선택하지 않는다.
원본의 결함을 수선한 뒤 성공으로 채점하지 않는다. 공통 config의 별도 측정은 원본 config의
측정과 구분하고 변경 내역을 남긴다. AI의 기술 검토와 사용자의 선호/실물 평가는
분리해서 기록하며 사용자 평가를 AI의 추정으로 대신하지 않는다.

## 6. pok-ui를 포함한 호환성 계획

UI의 현재 원본 보존 XML 편집·정적 트리 렌더링은 즉시 제거하지 않는다.

PoK 결과에는 입력 식별/버전/해시와 진단을 보존하는 방향으로 계약을 설계한다.

기존 도구/필드는 이번 문서 작업에서 변경하지 않는다. 후속 변경은 추가형 우선,
명시적 capability/schema 협상·구버전 지원 범위·폐기 일정·UI fixture를 먼저 마련한다.
런타임 capability는 목표 설계이며 현재 지원 기능이라고 표시하지 않는다.

필수 UI 회귀 시나리오: 가져오기→활성 세트 선택→계산→늦은 결과 격리,
제안 검토→적용→undo, 미지원/손실 진단 표시, 원본/비활성/미지 필드 보존,
엔진 재연결/취소/timeout, 구버전 런타임의 명시적 호환 오류.
개인 XML을 공개 fixture로 복사하지 않는다. 합성/공개 허용 fixture를 사용한다.
UI 세션은 현행 계약으로 작업을 계속할 수 있다. 새 최적화 절차를 UI에 하드코딩하지 않는다.
