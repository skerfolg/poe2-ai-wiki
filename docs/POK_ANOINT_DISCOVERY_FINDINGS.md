# 성유 후보 누락 — 획득 경로와 최종 트리의 기회비용

2026-11-06 사용자 후속 검토. Unforgiving은 최종 트리에서4포인트로 도달할 수 있다는
사용자 관측과, 자로크의 선물 등 히든 후보가 검토되지 않았다는 지적을 받았다.
기존의17은 시작점 기준 경로 길이이며 최종 트리의 증분 비용/절약량이 아니다.

## 확인된 데이터와 누락

KB0.5.4b의 Passive 획득 경로는 일반 `anointable`867개, `anoint-only`17개다.
자로크의 선물(`passive.zarokhs-gift-11184`)은 `kind=jewel-socket`, 연결선0,
`acquisition=anoint-only`, `sinister=true`, `no_radius=true`로 이미 수록돼 있었다.
데이터 부재가 아니다. 노터블/트리 경로만의 후보군으로는 이 부류를 놓친다.

조회에서도 acquisition은 FTS 문구가 아니어서 이름을 모른 채 query="anoint-only"로
검색하면0건이었다. 더구나 기존 서비스의 최소 목걸이 검사에서
`Allocates Zarokh's Gift`는 UNKNOWN/"성유 노터블이 KB에 없음"으로 재현됐다.
검사기는 노터블만 조회하고 acquisition=anointable만 허용했다. 전용 노터블과 전용
주얼 홈의 두 경로를 모두 막을 수 있는 독립적인 조회/할당 판정 결함이었다.
이 결함들이 과거 선택의 원인이었다고 인과를 확정한 것은 아니다.

## 보완한 경로

- `search_kb(type="Passive", acquisition="anoint-only")`: 전용 후보를 이름 없이 조회.
- `acquisition="anointable"`: 일반 성유 가능 후보, `"anoint"`: 둘의 합집합.
- SQL에서 limit 전에 필터하며 기존 JSON을 읽으므로 DB 스키마/정본을 바꾸지 않는다.
  히트의 acquisition/passive_kind로 주얼 홈도 구분하고 get_entry로 효과/제약을 읽는다.
- 새 PoK 자율 경로의3~5단계 입력에 전용 후보 목록을 자동 제공한다. 이름·kind·
  획득 경로인 사실 목록이며 특정 노드의 채택/순위나 게임 성립을 인증하지 않는다.
- 성유 할당 조회를 과대망상 노터블 풀과 분리하고 anoint-only를 인정한다.
  일반 성유·미확인 이름·부여 불가 노드·중복·과대망상 주얼 홈 금지는 유지한다.

## 가치 평가와 후속 범위

성유는 초기 후보로 두고 최종 트리에서 실제 추가 경로 비용과 함께 재평가한다.
일반 노드 직접 할당으로 성유 자리를 회수한 구성, 먼 고성능 후보, 전용 후보를
비교하되 여유 포인트·공유 경로·능력치 요구·자원/장비 재배분까지 포함한다.
거리 하나로 최종 순위를 만들거나 성유만 바꾸고 트리는 고정하지 않는다.

자로크는 빈 홈 자체의 DPS가 아니라 삽입 주얼과 함께 평가한다. 현재 원문상 Sinister
홈에는 고유 주얼을 넣을 수 없고, 홈 효과 증폭과 반경 효과도 적용되지 않는다.
[자로크 원문](https://poe2db.tw/us/Zarokhs_Gift),
[Sinister 제약](https://poe2db.tw/us/Sinister_Jewel_Sockets).
따라서 이번 구성의 합법적인 추가 희귀 주얼과 Unforgiving 직접 할당을 묶은 안은
검토 후보지만,17개 전용 후보 중 최선이라는 측정은 아직 없다.

이번 보완은 후보 조회·입력 제공·성유 할당 문구 검사 범위다. 실제 주얼 삽입/적용과
Sinister 제약, 성유/트리 재배분의 전체 성능 비교는 채택 전에 별도로 확인한다.
기존 PoB의 성유를 최적이라고 소급 인증하지 않는다. 기본 연결 MCP는 기존 루트 판으로,
로컬 수정본의 새 인자는 해당 판 반영·서비스 재시작 후 사용해야 한다.
