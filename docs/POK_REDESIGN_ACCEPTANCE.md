# 재설계 완료 판정의 증거 범위

2026-10-31 작성. [BLUEPRINT](BLUEPRINT.md)와 [ROADMAP](ROADMAP.md)의 요구를
최종 감사에 연결하는 표다. 요구나 완료 기준을 새로 축소하지 않는다.
진행 상태와 다음 실행의 정본은 [Current Plan](CURRENT-PLAN.md), 개별 결함 상태는
[BACKLOG](BACKLOG.md)다. 여기의 초기 관측은 해당 시점의 감사 기록이다.

완료 판정 때는 각 행의 실제 파일·실행·결과를 다시 읽는다. 테스트 이름이나 문서의
완료 표시만으로 충족했다고 간주하지 않는다. 한 행의 증거로 다른 행을 대신하지 않는다.

## 현재 증거의 범위

- `artifacts/reviews/redesign-r0/unit.xml`을 직접 읽으면 2026-10-30 기준
  tests2002/failures0/errors0/skipped2다. 이 과거 결과는 향후 구현의 검사 통과를 보장하지 않는다.
- 첫 과제의 원본 상태는 `artifacts/reviews/redesign-r1/cohort-summary.json`,
  기술 검토는 [원본 조건 결과](POK_REDESIGN_RESULTS.md), [공통 조건](POK_REDESIGN_COMMON_CONFIGS.md),
  [품질 검토](POK_REDESIGN_QUALITY_REVIEW.md), [가설 대조](POK_REDESIGN_FIRST_TASK_FINDINGS.md)에 있다.
  실제 기술 평가v1 JSON과 공통 config 입력의 존재도 확인했다. 사용자 평가나 일반 품질 효과로 승격하지 않는다.
- 추가 블록의 manifest와 프로토콜은 [수행 원장](POK_REDESIGN_VALIDATION.md)과
  [추가 비교](POK_REDESIGN_FOLLOWUP_PROTOCOL.md)에 연결되어 있다. 실행 중이라는 사실은 성공 제출의 증거가 아니다.
- UI 소비의 감사와 별도 저장소 증거는 [계약 감사](POK_UI_CONTRACT_AUDIT.md)와
  [인계 문서](POK_UI_REDESIGN_HANDOFF.md)를 따른다. 최종 감사 때 실제 UI HEAD/PR/검사를 다시 확인한다.

계산된 값은 게임 성립을 인증하지 않는다. 인게임에서만 확인할 수 있는 주장은
관측자·조건·패치·대상 범위를 기록하고 미확인 범위를 완료로 감추지 않는다.
