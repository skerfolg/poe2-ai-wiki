# #188 실전 기준 — 격노 아이스샷 젬링 복원 감사

사용자 제공 `artifacts/ice_shot_build.txt`를 실전 기준 사례로 삼았다. 기존 H1/H2의
패시브·고가치 조합·실전 성능이 부족하다는 사용자 평가를 채택한다. 이전 초기 기술
평가와 동결 캠페인은 보존하며 계산 재현을 생성 품질 향상으로 승격하지 않는다.

## 원문과 실제 결함

공유코드 SHA256은 `fed34048201dd8615f6ffe6e2301fd643b8de94438a53d06806a7d26197f6742`,
XML SHA256은 `f08559b62e0f5f1d46a1d2ce1b12e4da43dbb5fc7287640638235f317f7a8c59`다.
원본98레벨 젬링의17번 Ice Shot / Arrow 계산은 약1,022만 CombinedDPS다. 원래 config의
주력 표기값이며 전체 회전·모든 스킬 합계나 실제 보스 지속 DPS 인증은 아니다.

복원기가 일반 `Spec.nodes`에 없는 소켓 매핑을 버려15주얼 중4개가 빠졌다.
원문 native 영수증의 allocated_nodes146개에는11184/23960/26178/62152 네 소켓이 모두
실제로 배정돼 있다. 단순 비활성 저장 매핑을 정리한 것이 아니었다. 이4주얼만 제거한
원문 진단은 DPS -32.87%, 최대 격노72→61이었다. 대체품/재투자는 하지 않았다.

또한 비활성 무기 슬롯을 버리고 활성 교체 무기를1세트로 접었으며, WeaponSet1/2의
`nodes` 속성을 자식 원소 개수로 잘못 검사해 손실도 신고하지 않았다. 슬롯 없는 스킬을
Weapon 1로 바꾸고 젬의 세트별 활성 플래그를 버리는 문제도 있었다.

## 수정한 계산 표현

- 두 무기 슬롯을 원래 이름으로 보존한다. `weapon_set`은1/2 선택이며,
  `weapon_set_1_nodes`/`weapon_set_2_nodes`는 원래 전용 할당이다. 빈 장비 세트의2번
  선택도 보존한다. 예전처럼 접거나 전용 노드를 일반 노드로 바꾸지 않는다.
- 일반 노드 목록 밖 저장 주얼은 `preserve_socket_mapping=true`로 매핑을 유지한다.
  유료 포인트를 추가하지 않고, 실제 적용은 native PoB가 결정한다. 이 표시는 게임
  적법성·소켓 활성의 인증이 아니다. 새 일반 구성의 무배정 소켓 검사는 유지한다.
- 슬롯 없는 스킬은 슬롯 없는 상태로 남기고 젬의 `enableGlobal1/2`를 보존한다.
- `assume_first_stat_set=False`는 원문의 생략을 명시 빈 effect map으로 표현한다.
  `{}`는 native 기본 선택의 보존이며, 인자 자체의 미지정이나 최적 모드 선택과 다르다.
  새 구성에서 모드 결정 자체를 빠뜨린 경우의 검사는 유지한다.

이후 같은 daemon의 원문 대 복원본 **689개 숫자 스탯 차이0**을 확인했다.
수정한 공개 MCP `restore_pob_spec → compute_pob(input_policy='explicit')`도 성공했고
위 기준과689개 모두 일치했다. 원래 거부/시간 초과와 중간 진단 실패는 별도로 보존한다.

## 정신력: 이미 확인된 사실을 계산 반환에도 연결

목걸이 베이스의 부여 인스턴스는 무료이고 직접 등록 젬과 별개라는 사실은 이미
`mechanic.item-granted-skills`와 #167의 인게임 확인 및 KB 조회 자동 부착에 있었다.
이번 사용자도 원문의 음수 정신력이 그 부여 스킬에 대한 PoB 오점유라고 재확인했다.
이를 다시 사용자 검증 대기나 빌드 성립 차단 사유로 올린 것은 평가자의 오류다.

공개 스펙 계산과 원문 XML 계산/영수증에 `granted_skill_instances`를 자동으로 붙이고,
관련 음수가 있으면 `known_pob_limitations`에 기존 확인을 연결한다. 원시 수치를
바꾸거나 같은 스킬의 직접 젬 점유·다른 점유 부족까지 면제하지 않는다.

## 조건 진단의 반복 조회 비용

기존 `_condition_sources`는 모든 젬에서 공개 `index.get_entry`를 반복 호출했고,
미설정 조건/유지 비용에서 같은 수집을 다시 수행했다. 이 사례의 별도 계측은
미설정 조건101.766초·유지 비용89.093초였다. 호출당 한 번 검증된 canonical Store를
읽도록 바꾸어 인덱스 자체 복구·불필요한 부여 인스턴스 확장을 반복하지 않는다.
캐시의 검증을 끄거나 조건 검사를 생략하지 않는다. 수정 전후 이 사례의 두 진단
결과는 정확히 같으며, 실제 공개 MCP 전체 계산 경로도 완료됐다.

## 검증 기록과 남은 범위

실물/실패/측정 근거는 기존 `artifacts/reviews/final-quality-initial-technical-audit/`의
ice-shot-reference-v1/v2/v3에 있다. 사용자 원문·전체 입력이나 원시 모델 로그를 이 문서에
복사하지 않는다. 원문 공유코드는 수정하지 않았다.

초기 개발 전량 단위2753개는2716통과/33skip/4실패였다. 실패는 수정하지 않은 프로세스
종료·1.5초 identity 시간 검사다. 같은 조건 단독 검사와 실제 Python 실행기 대조에서도
일부가 재현돼 무조건 부하 탓이나 전량 통과로 보고하지 않는다. 테스트 한도를 늘리거나
조건을 완화하지 않았다. 최종 고정 소스 검증 결과는 후속 기록에 구분한다.

새 회귀의 첫 native 실행은 기존18개 통과와 새 영수증 테스트의 호출 인자 누락1개
실패였다. 이는 진단 테스트의 결함이며 수정 뒤 별도 재검증한다. 원래 실패를 지우지 않는다.

이번 성과는 강한 구성을 읽어 측정하는 기반의 수정이다. 자동 트리 편집/최적화의
자동 소켓·무기별 예산 처리, placeholder 고유와 실제 롤의 구분, 묶음 후보 탐색·채택,
실전 회전·새 과제의 자율 생성 품질은 별도 조사 대상이다. 이 사례는 해답을 열람한
회귀 기준이며 새 heldout이 아니다. #188 해결·새 기본 경로 전환은 선언하지 않는다.
pok-ui·전역 MCP 설정·고정 PoB 스냅샷은 변경하지 않았다. 새 모델 시험도 실행하지 않았다.
