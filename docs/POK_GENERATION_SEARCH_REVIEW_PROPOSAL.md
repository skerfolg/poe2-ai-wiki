# 생성·탐색 접근 검토안

상태: 검토 제안. 기존 청사진의 책임 경계는 유지한다. 새 생성 전략·도구·모델 시험을
승인하거나 기존12회 시험 결과를 수정한 문서가 아니다. 참고 빌드 맞춤 기능 확장을
보류하고, 어떤 탐색 방식이 실제 선택을 개선하는지 먼저 분리한다.

## 지금 확인한 것

| 사례 | 관측 | 지지하는 원인 | 아직 입증하지 못한 것 |
|---|---|---|---|
| H1 고정 반지 개정 | R/N의 공동 재투자는 재현됐으나 기존 경로·장비 틀의 넓은 대안 비교는 부족 | 초기 선택 재개방·후보 범위 문제 | 재투자 성공이 고투자 빌드 경쟁력이라는 주장 |
| H2 상태 소비 회로 | 낮은 준비 축적 값이 N에 전달됐는데도 핵심 소비 구조를 유지. R은 의존을 낮춤 | 정보의 의미·공급/소비·선택 연결 문제 | 단순히 자료를 더 주면 해결된다는 주장 |

Voices 진단은 같은 패시브/config/외부 장비를 고정했으며 추가 주얼 비용을 가격으로
맞추지 않았다. 아이스샷은 해답을 이미 읽은 회귀 기준이다. 평가용 비공개 과제로
재분류하지 않는다.

## 재검토할 단위

판단은 에이전트, 기록·조회·편집·측정·진단은 코어가 맡는 기존 원칙을 바꾸지 않는다.
검토 대상은 개별 함수의 개수보다 **후보를 만들고 폐기하는 방식과 측정의 의미**다.

1. 사용자 고정·성립 필요조건과 현재 공급자를 계속 구분하는가. 초기 구현을 바꿔도
   요구 자체를 잃은 것으로 처리하지 않는가.
2. 후보가 새 슬롯·자원·경로·한계·소비 조건을 열면, 그 공급을 실제로 쓰는 구성을
   함께 제안하는가. 단독 손해를 완성 패키지의 기각 근거로 쓰고 있지 않은가.
3. 경쟁 가설·아직 필요한 재료·중간의 불리함·완성 후 손익이 설계 기록에 남는가.
   기존 design record로 표현할 수 있는지부터 확인하며 새 대형 상태 체계를 만들지 않는다.
4. 사건 피해와 실제 반복 공급·마나·회복·조작 비용을 선택에서 함께 다루는가.
5. 최적화 도구의 종료를 선언 범위의 종료로 읽는가. 미탐색 변형·미모델링·새로 열린
   구조를 무가치 또는 전역 최적의 증거로 오독하지 않는가.

후보 수·고유 개수·필수 도구 호출·고정 순서를 늘리는 것으로 이 질문을 대신하지 않는다.
도구 추가는 접근 가능한 재료/측정/표현의 부족을 재현했을 때만 제안한다.

## 발견과 판단을 분리한 작은 평가 설계

먼저 아래 두 조건을 같은 모델·목표·소스 버전·예산·최종 출력 계약에서 구분한다.
실제 횟수/모델/상한은 아직 정하지 않았으며 실행하지 않는다.

| 조건 | 제공할 것 | 제공하지 않을 것 | 판별할 능력 |
|---|---|---|---|
| 재료 제공 | 사용할 수 있는 구체 부품·수치/효과·제약과 계산 경로 | 완성 조합·선택 답안·최종 우열 | 조합 제안·재개방·측정 해석·선택 |
| 자율 탐색 | 동등한 사실 범위의 조회/출처와 계산 경로 | 선별 부품 목록·완성 조합·답안 | 발견에서 조립·선택까지의 전체 흐름 |

미리 완성 패키지와 점수를 나열해 높은 것을 고르게 하는 시험은 생성·탐색 평가가
아니다. 재료 제공에서도 조합과 필요한 재배분은 에이전트가 만들어야 한다.

서로 다른 구조의 사례를 선정해 개발용/평가용을 결과 열람 전에 분리한다. 예를 들어
슬롯/용량을 여는 구조, 여러 부위의 전환·스케일링, 반복 공급·소비·회복을 요구하는
구조를 포함한다. 평가용 완성 참조는 개발 에이전트에 노출하지 않는다. 자료/출처가
모자라면 이를 기록하며 다른 자료 조건의 실패를 순수 추론 실패로 부르지 않는다.

현 KB·native의 고정 패치와 평가 사례가 맞는지도 먼저 확인한다. 현재 사용자 참고의
존재를 오래된 템플릿/검사기의 불일치만으로 부정하거나, 그 반대로 계산 성공을 실제
획득/운용 인증으로 쓰지 않는다.

## 결과에 따라 고칠 위치

| 결과 | 우선 수정 대상 |
|---|---|
| 재료가 있어도 약한 구성/선택을 유지 | 탐색 지침·경쟁 가설·판단/목표 해석 |
| 재료 제공은 성공, 자율 탐색은 실패 | 검색·후보 범위·연계/구체화 경로 |
| 좋은 후보를 만들었으나 표현/계산/왕복이 막힘 | 해당 코어 능력의 구체 결함 |
| 계산/기록 평가는 좋지만 사용자 실물 평가는 낮음 | 품질 기준·운용 모델·비교 기준 |

한 결과를 이유로 모든 층을 동시에 고치지 않는다. 변경한 메커니즘이 다음 설계에서
실제로 더 나은 선택으로 연결됐는지를 확인한다. 효과가 없으면 도구/규율을 계속
덧붙이지 않고 해당 가설을 폐기하거나 수정한다.

## 성공과 실행 경계

실제 최종 PoB의 메커니즘·장비·패시브/주얼·젬/유틸·자원·운용을 사용자 목적에 맞게
평가한다. 생성물/실패·미완료와 보존된 원문·가정을 함께 읽으며 단일 DPS·테스트 수·
문서 분량으로 점수를 대신하지 않는다. 투자·대상·조건·예산을 맞추지 못한 비교는
그 한계를 표시한다. 필요한 유지 조건을 가진 약한 대안보다 실물에서 더 나은 선택을
했다는 근거가 있어야 개선이라고 부른다.

진행 중인 #156 통합/CI와 변경 기록은 정리한다. 참고 재현을 위한 추가 기능 확장과
대규모 새 캠페인은 시작하지 않는다. 과거12회 승인에 새 모델 호출을 덧붙이지 않는다.
새 실행은 이 검토에서 판별할 질문과 비용/범위를 구체화한 뒤 별도로 결정한다.
단위 검사는 사용자 지시에 따라 변경 관련 최소 범위를 우선한다.
