# 웹참고방법과 PoK 설계·웹 검증 방법

2026-11-05 사용자 지시. 기존 방식을 **웹참고방법**, 새 방식을 **PoK 설계·웹 검증 방법**으로 부른다.
사용자는 새 기록/세션에서 설계부터 PoB 완성까지 진행하도록 선택했고, 메커니즘의 웹 검증은
허용하되 다른 사용자의 빌드/세팅을 가져와 앵커를 정하지 말라고 명확히 했다.

## 기존 방식의 정보원 감사

웹참고방법은 `autonomous-rage-ice-shot-v2`와 동결 revision
`03b5dd5f1d2031931347e622519304dbdac9aab59af0f2d2903fcda5b257ae70`다.
입력은 새 세션의 세 고정 조건뿐이었지만 일반 웹검색으로 사용자 빌드/세팅 자료를 읽었다.
따라서 **입력 초기화는 맞지만 정보원까지 독립된 설계 시험은 아니다.** 앞서 쓴
‘제로 베이스’는 이 차이를 충분히 전달하지 못했다. 원본 기록/시험 결과는 바꾸지 않는다.

기존안에 대한 사용자의 긍정적 선정 평가도 보존하되, 그것을 PoK 독립 설계 능력의 증거로
소급 해석하지 않는다.

## 새 방법의 도구 경계

- 같은 젬링·아이스샷·격노 스태킹 세 조건, 새 기록·새 native 모델 세션.
- 이전안/레퍼런스/비교표/누락 이름을 새 세션에 전달하지 않는다.
- PoK의 게임 사실·관계·메커니즘 인사이트로 후보·공급자를 먼저 선택하고 기록한다.
  전체 Build/UsageProfile·서술형 빌드 문서는 조회 대상에서 제외한다.
- 일반 native 웹검색은 비활성화한다. 임의 URL·빌드 사이트를 읽는 경로를 노출하지 않는다.
- 웹 검증은 `workflow_primary_source`로 이미 기록한 claim/provider를 조회한다.
  이번 구현은 해당 기재의 PoE2DB 데이터 원문에 한정한다. 추천 보조·관련 목록·다른 탭을
  제거하고 URL·응답/본문 해시·선행 설계 ref·claim/provider·관측 시각을 영수증으로 남긴다.
- 영수증 없이 외부 근거를 추가할 수 없고, 외부 빌드 가이드 URL을 근거로 저장할 수 없다.
  영수증은 실제 자료를 읽었다는 증거이지 해석의 진실성이나 게임 성립 인증이 아니다.
- 직접 원문으로 결론이 안 나는 핵심 연결은 미확인으로 남기고 필요한 성립 가정만
  사용자에게 확인한다. 네트워크 실패를 기재 부정/실험 검증/수집 누락으로 바꾸지 않는다.

웹 검증을 금지한 시험은 아니다. **선정 정보원과 검증용 원문 경로를 제한한 시험**이다.
외부 자료가 페이지 링크/추천을 통해 새 빌드 구성으로 번지는 경로를 제한한다.

## 단계와 완료 범위

1. 잠정 메커니즘과 핵심 연결을 PoK로 탐색. 모든 장비/완성 수치 계산을 미리 끝내지 않는다.
2. 선택한 기재의 핵심 연결만 웹 원문으로 검토. 강화 후보 전체 우열은 여기서 확정하지 않는다.
3. 공격/방어/자원 필수 앵커·현재 구현·강화 후보를 구체화한다. 알려진 불가능을 숨기지
   않되, 남은 포인트 전체 배분·완성 트리·최종 수치 최적화는 조립 과제로 남긴다.
4. 앵커를 실제 구성으로 조립하고 경로/속성/장비/점유/자원·적법성을 계산해 수정한다.
5. 초안의 무효 기재·조건 유지·실사용 비용·완성 조합을 비판하고 최종 PoB 공유 데이터를 제공한다.

사용자는 정상1~5진행을 승인했다.3단계에서 다시 일반 진행 승인을 요구하지 않는다.
새 실험적 핵심 가정·실제로 정해지지 않은 사용자 선호는 구체적인 선택 자료로 확인한다.
`build-generation`과 `build-assembly`의 기존 소유/저장/엔진 경계를 유지한다.

## 사전 확인과 비교

새 세션 시작 전 출처 차단·사전 선택/영수증·편집 연산 안내·작은 반환·단계 전환을
최소 검사하고 실제 MCP/웹 원문/조립 경로를 확인한다. 코드를 동결한 뒤 실행하며
원래 실패/시간 초과/복구와 추가 투입 시간을 보존한다. 특정 아이템 정답은 넣지 않는다.

편집 계약·응답 크기·단계 경계도 함께 보완하므로 이 비교는 정보원 하나만 바꾼
통제 실험은 아니다. 무엇이 달라졌는지 각각 기록하고 순수 웹 차단의 인과 효과로 확대하지 않는다.

비교는 동일한1~3단계의 메커니즘·세부 앵커·기재의 인과/기회비용·채택/기각 이유·
포인트/자원 전제·정보원·소요시간·새 문제를 먼저 본다. 기존 웹참고방법은 완성 PoB가
없으므로 새 완성물의 DPS/EHP와 직접 우열 비율을 만들지 않는다. 새 PoB는 별도의
출고·실현 가능성·조건 유지 범위로 평가한다. 단일 사례로 일반화/인과를 입증하지 않는다.

현재 상태: 소스 경계·작은 기록 영수증 구현, 관련22단위 통과. 실제 scoped MCP에서
빌드 조회 거부·선행 PoK 선택·외부 원문 영수증·작은 저장 반환을 확인했다. 일반 스킬과
공식 패치 원문 조회가 동작했다. 별도 최소 입력으로 실제 PoB 계산→현재 설계의 측정
근거 부착까지 확인했다. 이 사전확인용 입력/통계는 새 생성기에 제공하지 않는다.
새 생성은 소스/입력을 동결한 뒤 시작하며, 실제 에이전트의4~5완주는 아직 검증 전이다.
