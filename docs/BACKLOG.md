## 운용 — 누가 관리하고 어디로 보내나

**백로그 관리는 역할이지 특정 세션이 아니다.** 세션은 컨텍스트가 차면 끝나므로,
"그 세션에 보내라"로 고정하면 이 파일을 만든 이유(상태가 세션 기억에만 있으면
소멸한다)가 그대로 재발한다.

### 세션 구분 — 제목 접두

세션에는 원래 종류 구분이 없다(사용자가 만들면 그냥 세션이다). 그래서 **제목 접두로
기계적으로 찾을 수 있게** 한다.

| 접두 | 역할 |
|---|---|
| `[엔진]` | 엔진·KB 수정, **백로그 관리**, 작업 지시서 생성 |
| `[빌드]` | 빌드 생성·검증. 도구를 **쓰다가** 막힌 지점을 보고한다 |

찾는 법: `list_sessions` → `[엔진]` 접두 중 **가장 최근 활동**. 없거나 애매하면
**추측하지 말고 사용자에게 묻는다.**

⚠ 세션은 **자기 제목을 못 바꾼다**(`set_session_title`은 타 세션 전용). 사용자가
생성 시 붙이거나, 다른 세션이 붙여 준다.

### 역할 분리를 유지하는 이유

`[빌드]` 세션이 결함 12건을 찾아낸 것은 **도구를 만들지 않았기 때문**이다. 실제
빌드를 만들려다 벽에 부딪혀야 "조용히 빈 값이 온다"가 보인다. 도구를 만든 세션은
자기가 무엇을 넣었는지 알아서 그걸 못 본다. 실증: `radius-grant` 519건은 엔진
세션이 붙이고 "실규모"라 기록했는데, **오염된 한글에 매칭된 결과라는 걸 빌드
세션이 찾았다.** 두 역할을 섞으면 이 교차 검증이 사라진다.

### 접수는 2단계 — 즉시 등재, 검증은 착수 시

검증이 이 역할의 값어치지만(이관 3건이 틀렸다) **컨텍스트를 많이 쓴다.** 접수마다
재현하면 관리 세션이 금방 죽는다.

1. **접수 시** — 즉시 등재하되 `검증: 미검증(보고 원문)`으로 **명시**한다. 싸고,
   아무것도 잃지 않고, 거짓 확신도 안 생긴다.
2. **착수 시** — 실제로 작업할 때 재현·대조하고 `검증:` 칸을 채운다. 보고가 틀린
   것은 이때 드러난다 — 어차피 코드를 봐야 하니 비용이 중복되지 않는다.

### 인계

관리 세션의 컨텍스트가 차면 **이 파일에 상태를 반영하고** 끝낸다. 다음 `[엔진]`
세션이 이 파일을 읽고 그대로 이어받는다. 인계 메모를 따로 쓰지 않는다 — 그게
또 세션 밖에 있어야 할 상태를 세션 안에 두는 짓이다.

## 기재 규약

각 항목에 **반드시** 넣는다 — 없으면 다음 세션이 처음부터 다시 조사한다.

| 필드 | 왜 |
|---|---|
| **상태** | 미착수 / 조사중 / **원인규명** / 해결 / 기각 / **판정대기** |
| **실측** | 규모·수치를 **잰 값**으로. "많다"가 아니라 "1,536건" |
| **검증** | 무엇을 확인했고 **무엇을 가정했는가**. 이 구분이 오판을 막았다 |
| **근거 위치** | 파일·줄·레코드 id. 다음 세션이 바로 찾게 |

⚠ **보고를 그대로 옮기지 말 것.** 이관 3건이 실제로 틀렸다(아래 「검증으로 뒤집힌
보고」). 재현·대조 후에 적는다.

## 0. 반복되는 형태 — 새 결함을 만나면 여기부터 대조한다

해결분 본문을 지우면서 **교훈만** 남긴다. 이번 큐에서 같은 형태가 여러 번 나왔고,
다음에도 나올 것이다.

⚠ **각 형태는 「강제」 줄을 반드시 갖는다** — 철칙 5를 이 절에 자기적용한 것이다.
형태를 적어 두는 것만으로는 다음 세션이 대조하리라는 보장이 없다. 강제 지점을 적으면
①있는 것은 심볼이 사라질 때 테스트가 깨지고 ②없는 것은 **「문서뿐」이라고 눈에 보이게**
남는다. 강제가 있다고 착각하지 않는 것이 절반이다.
검사: `tests/unit/test_backlog_hygiene.py`.

### ① 선언이 없으면 **조용한 0** (3회)

PoB는 값을 붙이기 전에 **선언**을 읽는다. 선언이 없으면 오류가 아니라 **과소 계상**이다.

| 사례 | 없을 때 | 있을 때 |
|---|---|---|
| 룬 증폭 (#33) | Δ +26.5 | `Sockets:`+`Rune:`+시드 줄 → Δ +79.4 (**3.00배**) |
| 반경 주얼 (제안 B) | Δ 0 | `Radius: Very Large` → CritChance 10.44 → **15.84** |
| 룬 시드 줄 (#33) | Δ 0 | 선언만으론 모자라다 — 문구 줄도 있어야 한다 |

세 조각이 **각각** 필요하다 (실측 2026-08-09, `Greater Body Rune` ×2 · 룬 효과 +200%):
`Sockets:`+`Rune:`+시드 = **ES +300** · `Rune:` 없음 = +100(**3배 과소**) ·
`Sockets:` 없음 = **+0**(통째로 사라진다) · 시드만 = +100.

→ **텍스트를 손으로 조립하지 말 것.** `render_runed`·`render_radius_jewel`을 쓴다.

**강제**: `src/pok/engine/jewels.py::needs_radius_declaration` ·
`src/pok/engine/runes.py::needs_rune_declaration` — 손으로 적어도 `check_item_legality`가
**구조 오류로 낸다**. ("쓰라"는 문서 규율이었고, 안 쓴 채로 두 번 출고됐다.)

### ② 축이 측정에 없으면 **점수 0** (3회)

가중치에 없는 축은 재지도 않으니 "값어치 없음"과 구분되지 않는다.

- #18 방어 유니크 — 허리띠 20종 중 12종이 EHP를 올리는데 채택 가능 **0건**
- #25 이동속도 — 시장 가치와 정반대 결론
- #22 퀄리티 축 — 접사 82건 중 **32건(39%)**이 PoB 미측정

→ 방어·유틸 축은 **가중치와 무관하게 항상 잰다**(PoB 1회가 619개 스탯을 준다 — 비용 0).
→ 못 재는 것은 `unmeasurable`·`pob_gap`으로 **말한다**.

**강제**: `src/pok/engine/items.py::_DEFENSIVE_AXES`(가중치와 무관하게 측정) ·
`tests/integration/test_axis_names_exist.py`(오타 축은 조용히 0이 된다 — `MovementSpeed`가
실제로 그랬다). ⚠ **일반화(`unscored_axes`)는 아직 없다** — §2에 열려 있다.

### ③ PoB가 못 읽으면 **델타 0** (제안 D)

트리 노드 **501건**(10.2%) · 아이템 접사 **1,864건**이 문구를 못 읽혀 0으로 나온다.
델타 0은 "값어치 없음"이 아니라 **"측정 안 됨"**이다.

**강제**: `src/pok/pob/parse_gaps.py::apply_parse_flags` ·
`src/pok/pob/item_parse_gaps.py::apply_item_parse_flags`
— 레코드에 `pob_modeling`을 붙이고 도구 결과에 `pob_gap`을 실어 보낸다.
갱신 누락은 `tests/integration/test_tree_parse_gaps.py` ·
`tests/integration/test_item_parse_gaps.py`가 잡는다.

### ④ 판정 주체가 둘이면 **어긋난다** (#23)

그리디는 **후보 단위**로, 검사기는 **모드 id 단위**로 셌다 — 3개를 골랐는데 5개로
세졌다. 개수를 맞추는 게 아니라 **판정 주체를 하나로** 만든다(조립하면서 검사기에게 묻기).

**강제**: `src/pok/engine/rares.py::_assemble_text`가 조립하면서 검사기에게 묻는다(#23).
⚠ **일반 가드는 없음(문서뿐)** — "두 곳이 같은 것을 센다"를 기계가 알아볼 방법을 못 찾았다.
새 카운터를 만들 때 기존 검사기를 부르는지 사람이 봐야 한다.

### ⑤ 게이트가 **정상을 막으면** 신호가 죽는다 (#24·#26·#30)

- #26 두 검사가 서로를 막아 어센던시 빌드를 **하나도** 조립 못 함
- #24 12자 문턱이 `Onslaught`(9자)를 걸러 **Helmet 슬롯 전체**가 죽음
- #30 스펙 줄을 모드로 오독 — 진짜 실격 4건과 오탐 6건이 한 목록에 섞임

→ 게이트를 만들 땐 **양방향**을 잠근다: 위반이 걸리는가 **그리고** 정상이 통과하는가.

**강제**: 없음(문서뿐) — "이 테스트가 통과 방향도 재는가"는 기계가 못 읽는다. 다만
개별 게이트에는 통과 방향 테스트가 붙어 있다(`tests/unit/test_runes.py`의 다른 이름 룬
병용, `tests/unit/test_clusters.py`의 다른 전직 제외 뒤에도 결과가 남는지).
**새 게이트를 만들 때 통과 케이스를 같은 테스트에 넣는 것은 사람이 지켜야 한다.**

### ⑥ 도구 갭은 **확인해야 닫힌 걸 안다** (제안 C)

"`find_clusters`가 생기면 자연히 해소된다"고 적혀 있었는데 **안 닫혔다** — 개별 노드
좌표가 없어 여전히 파일을 뒤져야 했다. 도구가 생겼다고 갭이 닫히는 게 아니다.

**강제**: 없음(문서뿐) — 갭이 닫혔는지는 **그 갭을 만든 질문을 다시 해 봐야** 안다.
차선으로: 갭을 닫았다고 적을 땐 §4 표에 **재현한 질문**을 함께 적는다.

- **상태**: 미검증(보고 원문) · 3차 이관 2026-08-10 (⑪과 ②는 같은 건)
- **보고**: `optimize_rare(slot="Helmet", base_type="Grinning Mask")`가 `legal=True`로 낸
  text를 `assemble_pob`에 그대로 넣자 거부 —
  `137% increased Evasion and Energy Shield → modifier.localevasionand…1/2/3: 수치 [137.0] 가 티어 범위 밖`
- **보고된 원인**: #23을 「조립하면서 검사기에게 묻기」로 고쳤는데

  — **규율과 도구가 서로를 막는다**(§0 ⑤)
- **실측 규모**: 7슬롯 중 `legal=True`인데 조립 거부 1건(투구) · `legal=False` 1건(벨트,
  `unmeasurable=17`) → **2슬롯이 조립 불가**라 측정이 5슬롯 기준으로만 나왔다
- **요청안**: `optimize_rare`가 조립기와 **같은 검사 경로**로 롤 값까지 보거나, 최소한
  반환에 `assemble_ready: false` + 사유를 실을 것
- **근거 위치**: 같은 빌드 폴더 `spec_geared3.json`·`spec_geared7.json` · `design.md` §11.8-a

### #62 〔신규〕 ⛔ 엔진이 **「무엇을 만들 수 있나」에 못 답한다** — 발상 도구 부재
- **상태**: 사용자 지적 2026-08-11 · `[빌드]` A분기 세션이 1차 구현 착수(사용자 승인,

- **사용자 지적**: "새로운 아이디어는 내가 계속 내고 너는 검증 정도밖에 도움이 안 되고
  있어. 엔진에서 기대했던 건 새로운 아이디어를 추천받는 건데, 엔진 구현 후 지금까지
  주문 토템쪽 기재는 한 번도 추천받지 못했다"
- **이관 이력이 뒷받침한다**: 1~6차 이관 **전부 검사·게이트**였다(statSet 선언 의무·
  색 원장·룬 값·계열 배타·출처 표기·정지). 엔진이 답하는 것은 「내가 맞게 만들었나」이고
  「무엇을 만들 수 있나」는 **비어 있다**. §4의 해결분 목록도 전부 같은 쪽이다
- **왜 기존 도구로 안 되나**: `discover_mechanics`는 **호출자가 키워드를 알아야** 돈다.
  보고자가 `"totem"`을 넣은 것은 사용자가 먼저 말했기 때문이다. 그리고 도구가 스스로
  밝힌 한계 — "사전 매칭이라 문구에 키워드가 없는 암묵 상호작용은 못 찾는다" — 가
  결정적이다: **「주문 토템에 무엇을 넣을 수 있는가」는 어느 레코드 문구에도 없다.**
  PoB의 `requireSkillTypes`/`excludeSkillTypes`에만 있다
- **실증**: `passive.empowering-infusions-8782`("주입을 최근 소모했으면 주문 피해 35%
  증가") 계열 6건이 KB에 있었는데, 주입을 세션 내내 다룬 보고자가 **한 번도 못 봤다**
- **1차 조치 완료(2026-08-11, `[빌드]` 구현 + `[엔진]` 리뷰)**: `engine/hosting.py` ·
  `catalog.skill_gates()`. 판정은 `CalcTools.lua`의 `doesTypeExpressionMatch`·
  `canGrantedEffectSupportActiveSkill` **전사**다(계산이 아니라 카탈로그 질의 —
  쌍마다 PoB를 돌리면 수만 회다). 구형 번개 담체 247건 · 주문 토템 페이로드 46건.
  ⚠ 요구/배제는 **후위(RPN) 식**이라 집합 포함이 아니다: `{Spell, Totemable, AND}`는
  "둘 다"지만 `{Spell, Totemable}`는 "둘 중 하나"다
- **리뷰에서 고친 것 3건**: ① `mypy --strict` 실패(보고자는 안 돌렸다) ②
  **소환수 타입 축 누락** — PoB는 요구 판정에만 `minionSkillTypes`를 함께 보는데
  빠져 있어 **6,335쌍**의 판정이 틀렸다(스킬 42종 보유·보조 150종이
  `ignoreMinionTypes`) ③ 통합 테스트 5건이 CI에서 전부 깨졌다(CI엔
  `Data/Skills/sup_dex.lua` 하나뿐) — 데이터 없는 규칙 시험을 `tests/unit/`로 분리
- **1차 조치 원문**: `find_carriers(skill=)` / `find_payloads(carrier=)` —
  문구가 아니라 **타입 시스템**으로 담체↔페이로드를 전수 열거. `catalog.py`에
  `skillTypes` 파싱 추가
- **착수 시 볼 것**: **배제 사유를 함께 내는가.** 「후보에 없다」와 「이 이유로 배제됐다」는
  다르고, 후자여야 사용자가 게임 지식으로 뒤집을 수 있다(`carrier_unknown`·
  `defensive_only`가 유용했던 것과 같은 이유). 그리고 이 1건으로 계열이 닫히지 않는다 —
  「무엇을 만들 수 있나」축의 나머지를 여기서 계속 관리한다

### #58 〔신규〕 ⛔ 검사가 **스냅샷만 보고 출처(provenance)를 안 본다** — 계열 보고
- **상태**: 미검증(보고 원문) · 5차 이관 2026-08-11 · **개별 결함이 아니라 계열**
- **문제 제기(사용자)**: "엔진에 계속 결함을 업데이트하고 도구 수준에서도 개선했는데,
  왜 새 세션에서 빌드를 만들려고 하면 계속 멍청해지냐"
- **실측**: 한 세션이 **같은 실패를 3연속**했고 **세 번 다 도구가 통과시켰다**

  | 축 | 계승한 것의 실제 상태 | 도구 판정 | 발견자 |
  |---|---|---|---|
  | 스킬 | 주력기가 스펙에 **없음** · CoEA에 아무것도 미연결 | `items_legal ✅` `pruned []` | 사용자 |
  | 장비 | 유니크 전수 열거 **미실시** · 스킬레벨 **그룹 중복** · 접두 2칸씩 공란 | `items_legal ✅` | 사용자 |
  | 트리 | 기반 97노드가 **선행 문서가 스스로 「무효」로 판정한 것** | `pruned []` `tree_connected ✅` | 사용자 |

- **진단(보고자)**: 지금의 강제 지점은 전부 "이 스펙이 **지금** 적법한가"를 본다
  (`items_legal`·`req_shortfall`·`pruned_nodes`·statSet 선언·룬 표기·색 원장) —
  **전부 잘 동작했다**. 그런데 세션을 건너오는 것은 **스펙 파일**이고 결정은
  **design.md**에 쌓이는데 **둘을 대조하는 검사가 하나도 없다.** 스펙은 언제나
  「적법」하므로 이어받은 세션은 그 위에 얹고, 사용자 피드백은 문서 본문에만 남아
  **매 세션 증발**한다
- **덧붙임(보고자, 2026-08-11)**: **게이트의 침묵을 통과로 읽었다.** `items_legal: True`가
  실제로는 「검사가 돌았다면 통과했을 것」이었다(#60 — 선언형은 판정 0건이었다). 그 목걸이의
  계열 중복이 딜을 **1.54배** 부풀리고 있었다: `CombinedDPS 364,538 → 237,278`. 사용자에게

  **결정과 스펙이 갈라진 정확한 증거**

  1. ✅ **해결(2026-08-11)** — `engine/integrity.py::spec_integrity`. `compute_pob`·

## 2. 기능 제안

### 〔제안 F〕 「소모하지만 소모하지 않은 것으로 간주」가 **반복 축인데 조회 경로가 없다**

- **상태**: 미착수 · 빌드 세션 2026-08-10 발의 · **근거는 실전 빌드 대조**
- **실측**: 같은 형태의 품질 문구가 **한 세션에서 여섯 번** 조회됐는데, 매번 "그 스킬의
  부수 옵션"으로만 읽히고 **축으로 인식되지 못했다**:

  | 스킬 | 품질 문구 |
  |---|---|
  | `skill.ice-nova` | `(0—40)% chance to not remove an Infusion but still count as consuming them` ← 최댓값 |
  | `skill.firestorm` | `(0—20)% chance to not remove an Infusion but still count as consuming them` |
  | `skill.hollow-form` | `(0—10)% chance to not remove a Power Charge but still count as consuming it` |
  | `skill.bonestorm` · `skill.glacial-lance` · `skill.explosive-spear` | `(0—20)% chance to not remove Charges on use` |

- **왜 결함인가**: 자원이 병목일 때 세션은 **공급을 늘릴 궁리만 한다.** 실전 빌드
  (젬링 무한격분 CoC/CoA 폭발창)는 같은 문제를 **소비를 0으로 만들어** 풀었다 —
  *"충전 소모 X 대체퀄리티 + 충전 제거하지 않고 소모한 걸로 간주 = 99 이상"*.
  우리 세션은 `skill.explosive-spear`의 20%를 **인용까지 하고도** "광포 충전 수급이
  6~8초당 1개라 즉발 상시화 불가"로 결론냈다. 축이 있는 줄 몰라서 못 쌓았다.
- **검증**: 위 여섯 건은 KB 레코드에서 **직접 확인**했다(품질 문구 원문). 실전 빌드의
  "99 이상" 달성 경로(젬 품질 40 초과·보조·장비·패시브 합산)는 **미검증** — 외부 글의
  주장이고 우리가 재현하지 않았다.
- **요청안**: 문구 형태를 축으로 묶는 조회 경로. 예 — `scan_synergies`의 subject_key에
  `self.resource.not_consumed` 류를 세우거나, `describe_kb`가 품질 문구의 반복 패턴을
  집계하거나, `find_by_value`가 `quality_stats` 텍스트에도 닿게 하는 것
- **성격**: §0 ②(「축이 측정에 없으면 점수 0」)의 **탐색판**이다. 그쪽은 PoB가 안 재서
  0이었고, 이건 **조회 경로가 없어서 축이 안 보인** 것이다. 철칙 5대로면 문서 규율
  ("자원 병목이면 소비 제거를 먼저 보라")로 남기지 말고 도구에 넣어야 한다
- **근거 위치**: `artifacts/builds/20260810-인퍼널리스트-화염파-mom-섀시설계/design.md`
  §1(주입 경제) · §7.3-a(격분 수급 원장) · §9.3(혜성 트리거 실측).
  대조한 실전 빌드: dcinside poe2 갤러리 388193
- **이관**: `[빌드] A분기` 세션에 적용 각도로 전달함(2026-08-10) — 얼음 폭발 40%가
  주입 순환의 공급 병목을 바꿀 수 있다
