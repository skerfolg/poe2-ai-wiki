> **문서 상태**: v0.1 (2026-08-07) 신설.
> **목적**: **어느 세션이든 이 파일 하나로 이어받는다.** 결함 큐를 대화나 세션 간
> 메시지에만 두면 그 세션이 끝날 때 사라진다 — 실제로 이관 6차까지 매번 지시서를
> 손으로 다시 써야 했다. 규율을 문서에만 두면 안 지켜지듯(철칙 5), **상태를 세션
> 기억에만 두면 소멸한다.**
> **ROADMAP과의 차이**: ROADMAP은 **단계**(P0~P6)와 Exit 기준, 여기는 **큐**다.
> 단계 진행과 무관하게 들어오고 나간다.
> **변경 규칙**: 항목 추가·상태 갱신은 자유. **삭제는 해결·기각 사유를 남긴 뒤에만.**

## 기재 규약

각 항목에 **반드시** 넣는다 — 없으면 다음 세션이 처음부터 다시 조사한다.

| 필드 | 왜 |
|---|---|
| **상태** | 미착수 / 조사중 / **원인규명** / 해결 / 기각 / **판정대기** |
| **실측** | 규모·수치를 **잰 값**으로. "많다"가 아니라 "1,536건" |
| **검증** | 무엇을 확인했고 **무엇을 가정했는가**. 이 구분이 오판을 막았다 |
| **근거 위치** | 파일·줄·레코드 id. 다음 세션이 바로 찾게 |

⚠ **보고를 그대로 옮기지 말 것.** 이관 3건이 실제로 틀렸다(아래 「검증으로 뒤집힌
보고」). 재현·대조 후에 적는다.

### #8-b `skill.malice` stats 오염
- **상태**: 조사중 — **출처 미궁**
- **실측**: stats 19줄 중 8~18번이 다른 스킬 것(오라인데 물리 피해·투사체 5발·냉기 변환)

- **다음**: #12에서 수집 경로를 훑을 때 함께 드러날 가능성. 단독 조사 비용 불확실

### #3 `mechanic.elemental-archon` 지속시간·회복 기간 미수록
- **상태**: 미착수 — **출처 확인 선행 필요**
- **왜**: 유지율 = 지속 ÷ (지속 + 회복)인데 분자·분모가 둘 다 없다. 트리에 집정관
  클러스터가 통째로 있는데 **투자 값어치를 계산할 수 없다**
- **성격**: 쿨다운 건과 동형 — 수정 모드(집정관 지속 15% 증가 등)는 수집되는데
  **수정 대상 기저값이 없다**
- **선행**: poe2db에 그 수치가 있는지 먼저 확인. 없으면 수집 갭이 아니라 **출처 갭**이고,
  커뮤니티 실측값(지속 10초/회복 20초)을 정본에 넣을지는 **판정 사항**
- **묶기**: `far_clusters` 작업과 같은 레코드를 만짐 → 함께 처리 권장

### #4 아이템 부여 스킬과 젬 스킬이 구분되지 않음
- **상태**: 미착수 — 게임 지식 판정 일부 필요
- **실측 사례**: `skill.purity-of-fire`·`skill.malice`를 젬 오라로 오인 → 정신력 배분표에
  넣음. 실제로는 셉터 부여라 젬으로 못 켜고 **셉터당 하나만** 고를 수 있어 배타
- **단서는 있었으나 표식이 아님**: 젬 스킬은 `tier`·`reservation` 보유, 이 둘은 둘 다 없음
- **요청안**: `source: gem | item-granted | ascendancy-granted` + `granted_by: [item ids]`
  (Modifier엔 이미 있는 필드) + 부여 스킬의 **정신력 점유량 수집**
- **묶기**: `far_clusters` 작업과 함께

### #2 `acquisition: liquid-emotion`의 의미가 오독을 유발
- **상태**: 판정대기 (게임 지식) + 필드 설계
- **실측 오판**: "성유로만 얻는 무작위 노드 = 트리에서 못 찍음"으로 읽어 **틀린 설계
  판단**. 사용자 정정: "성유로 **부여도 가능**하다는 뜻이지 전용이 아니다.
  실제로 찍을 수 있는 노드다"
- **혼동 원인**: `liquid-emotion-only`(성유 전용, 트리 할당 불가 — `passive.dominion-26214`)가
  **따로 존재**하는데 이름이 비슷해 의미가 정반대인 줄 모른다
- **요청안**: `tree_allocatable: true/false` 명시 필드(파생 말고 정본), 또는
  `anointable`/`anoint-only`로 개명

### #5 `cost` 필드의 "미수록"과 "명시적 0"이 섞임
- **상태**: 미착수
- **실측**: `describe_type("Skill", field="cost")` 충전율 **63.8%**, 그중 명시적
  `{Mana, min:0, max:0}` **52건**. 나머지 36.2%는 미수록
- **실측 오판**: cost 필드 부재를 보고 "마나 소모 0"으로 단정했다가 철회
- **요청안**: 명시적 0을 전 스킬에 일관 적용하거나, 미수록을 `null`로 명시
- **선례**: 쿨다운은 이 방식으로 해결됨(`cooldown_s` 0 = 없음 / 부재 = 미수록)

## 2. 기능 제안 (실사용 세션 발의, 2026-08-07)

### 제안 A — `optimize_tree`에 밀집도·비연결 인식 **[권장 1순위]**
- **실측 근거**: 예산 87로 단독 실행 → **43포인트에서 조기 종료 · 9포인트 낭비 ·
  주얼 0개 채택 · 치명타 12.16%(목표 80%)**. 손으로 밀집도를 분석하니 병목을 정면으로
  푸는 노터블(인화성 강도 80% 등)이 나왔고 **전부 후보 반경 밖**
- **구조적 한계 2가지**: ① 먼 클러스터를 못 봄 ② 연결 비용을 **항상 지불한다고 가정**
  (제어된 변형·허무의 산물은 비연결 할당이라 **0**일 수 있다)
- **설계 결정 (엔진 세션 판단, 발의 세션 통보 완료)**: 발의는 "문서 관문으로 강제"였으나
  **자동 부착으로 바꾼다**(철칙 5). `optimize_tree`가 내부에서 스캔해 후보 반경 밖
  클러스터를 `far_clusters`로 **반환에 싣는다**. `unconnected_regions` 인자 추가.
  `find_clusters`는 독립 도구로도 노출하되 **강제는 자동 부착으로**

### 제안 B — 반경 주얼 소켓 평가
- **문제**: `Time-Lost` 접미는 **반경 내 노터블 수 × 부여값**이 가치인데, PoB
  `ModParser`에 패턴이 없어 파싱되지 않는다 → 서로 다른 소켓의 델타가 **동일**하게 나와
  "소켓 위치는 값어치 없음"으로 오독
- **방법**: KB `pob_modeling.workaround`가 이미 적어둠 — 반경 내 노터블 수를 세어 효과를
  텍스트로 합성 후 실측
- **선행**: **#12 해결 후**. 지금은 `pob_modeling`이 오염돼 판정 근거가 못 됨

### 제안 C — 좌표 대량 조회 경로 (도구 갭)
- **문제**: `AGENTS.md`가 파일 탐색을 금지하는데 **좌표를 관련성으로 거를 경로가 없어**
  세션이 `knowledge/**/*.ndjson`을 직접 읽는 것 외에 방법이 없었다
- **원칙**: 도구 갭은 규율 위반을 강제한다 — **금지하려면 대안 경로를 먼저 만든다**
  (`insight.disciplines-need-enforcement-points` 따름정리)
