# B·C 아이템 상세보기 오류: 재현·수정·완료 판정 대조

2026-10-29. 사용자 신고인 B/C 아이템 더블클릭 오류를 원본 공유코드에서 재현했다.
**생성한 문구의 결함과 이를 놓친 출고 검사가 문제였다. 사용자 PoB 설치 문제로 돌리지 않는다.**
이번 수정은 편집 가능한 산출물을 만드는 범위이며, A가 가장 낫고 B/C의 고유·패시브
최적화가 부족했다는 평가와 생성 품질 #188 미해결 상태를 유지한다.

핀 PoB와 사용자 설치본의 `Item.lua`, `ItemsTab.lua`, `ItemListControl.lua`가
줄바꿈 정규화 후 동일함을 확인했다. `ItemListControl:OnSelClick`의 실제 더블클릭은
`BuildRaw → new Item → SetDisplayItem` 순서다. 기존 계산·공유코드 압축 왕복이나
원문을 바로 `SetDisplayItem`에 넣는 검사는 첫 직렬화 단계를 빠뜨렸다.

B는 옵션 뒤에 소켓·룬 선언 한 벌이 있었고, C는 동일한 선언이 이미 두 벌이었다.
PoB는 뒤쪽 선언을 헤더 정보와 옵션 본문 양쪽에 보존하여, 다시 쓰면서 선언을 복제했다.
B 지팡이와 C 장갑의 오류 위치는 실제 실행값이다. C 갑옷이 이후 몇 홈이 될지는
파싱을 완료하지 못했으므로 관측값으로 쓰지 않았다.

검사는 최종 `to_xml` 결과를 사용하므로 주얼과 대리 측정 주입까지 실제 공유코드에
들어가는 문구를 확인한다. 실패하면 코드 발급·정상 산출물 저장 전에 중단한다.
명시적 진단용 `strict=False` 기록에는 `item_editor` 실패와 `legal=false`를 남긴다.
일반 계산·최적화의 모든 후보마다 편집기를 실행하지 않고 최종 조립에서 실행한다.
검사 통과는 알려진 편집 오류가 없다는 뜻이며 게임 획득 가능성이나 빌드 품질의 인증은 아니다.

## 사용자가 확인할 사본

[B·C 편집 오류 교정 PoB 공유코드](GENERATION_EDITOR_REPAIR_CODES.md)를 별도로 제공한다.
[원본 공유코드](GENERATION_FULLPATH_CODES.md)의 세 코드 블록은 그대로 보존했다.
원본 SHA-256이 기존 공개값과 일치하고, 사본 코드 복원 XML이 사본 파일과 바이트 단위로 같다.

B5개·C6개 아이템에서 선언 위치와 **완전히 동일한 선언 블록의 중복**만 수정했다.
나머지 옵션 줄은 순서까지 동일하고 아이템 본문 밖 XML도 바이트 단위로 같다.
C에 남긴 룬 구성은 저장된 내보내기 전 명세3종과 일치한다. 전체 옵션을 중복 제거하거나
장비·노드·스킬 선택을 바꾸지 않았다. 최종 파일에서 다시 추출한 B/C 37개 아이템도
새 출고 검사기를 통과했다. 중복을 제거한 C의 이전 저장 성능 수치는 재인증하지 않는다.

추가로 최종 XML 전체를 `loadBuildFromXML`로 불러온 뒤 실제 아이템 목록의 더블클릭을
B19/19·C18/18 모두 실행했다. `SaveDB`로 별도 사본에 저장한 후 전체 빌드 재로드도
성공했다(B2.78초·C2.69초). `ModRange`를 포함한 베이스·소켓·룬·접사 ID와 범위 값은
최초 로드와 재로드 요약이 같았다. 입력 XML 해시도 그대로다. 이 결과는 화면 클릭 검증과
구별하며, 전체 빌드의 성능·적법성·트리 최적화를 재인증한 것은 아니다.
