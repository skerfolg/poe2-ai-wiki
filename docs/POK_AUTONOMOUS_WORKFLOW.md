# 빌드 자율 실행 — 구현과 검증 범위

2026-11-05. 상태: 젬링·활 1~3단계 제출·검사 완료, 사용자 앵커 검토 대기.
빌드 품질 개선 미판정. 실제 실행에는 턴 상한 중단과 실행기 보완 후 복구가 포함된다.

## 범위와 책임

사용자가 요구를 주면 탐색 → 성립 검토 → 상세 앵커 → PoB 초안 → 비판/피드백 개정을
스킬이 이어간다. 단계는 산출물과 재개 관문이며 조회 순서·횟수·고유 개수·선택 답을
엔진에 하드코딩하지 않는다. 근거가 부족한 핵심 연결은 정확한 가정과 실패 영향을
질문하고 명시한 연결의 승인 후에만 가정으로 사용한다.

`skills/build-generation/autonomous_run.py`가 CLI와 프로세스 예산·현재 단계·사용자
응답을 관리한다. `autonomous_server.py`는 기존 제품 MCP에 단계별 표면을 적용한다.
`autonomous_contract.py`는 실제 조회/웹 호출, 근거 연결과 상세 앵커의 선언 누락을
검사한다. 판단과 선택은 에이전트의 책임이다. 새 엔진 솔버·UI 의존·저장 경계 이동은 없다.

## 정본과 실행 기록

- 설계 이유·근거·결정: 기존 immutable design record. `record_ref`로만 이어간다.
- 흐름 참조와 검토 범위: 같은 정본의 `extensions.autonomous_flow`.
- 단계·세션·승인·실행: 해당 artifacts 실행 폴더의 `workflow.json`.
- 각 개정 반환 참조: 호스트가 `context-NNN.head.json`에 기록한다. 모델이 중단되어도
  저장된 정본 참조를 회수한다. 모델은 현재 참조에서만 개정할 수 있다.
- `design.md`와 `design-record.json` 내보내기는 검토용 뷰다. 재개 입력으로 읽지 않는다.
- 원본 prompt/schema/command/events/stderr/execution은 턴별로 보존한다. 비공개 추론
  로그를 사용자 보고나 정본 문서에 복사하지 않는다.

## 강제 지점

후속 planning-v2 정책은 자원 회복의 맵핑/보스/재시동별 가용 조건과 다른 공급/소모
대안, 치명타 및 대체 성립기, 고가치 구성 묶음의 채택/기각 근거를 같은 정본의
planning_reviews에 연결한다. 자연 재생 흑자를 보편 조건으로 강제하지 않는다.
이전 기록은 정책 버전 없이 보존하며 새 기준으로 소급해 통과/실패를 바꾸지 않는다.
workflow 자체 도구에 남은 시간도 표시하고 선택적 정본 읽기를 기본 경로로 쓴다.

설계 단계에는 PoB 계산·조립·재료 부착이 노출되지 않는다. 필요조건과 정확한 공급
아이템·스킬·보조·패시브를 연결하지 않은 추상 앵커는 완료하지 않는다. 공격·방어·
자원 앵커, 장비/주얼/스킬/보조/패시브 검토, 포인트/슬롯/점유/능력치/회복/조작의
제약 검토가 필요하다. 특정 부류가 불필요하면 미채택 이유를 기록한다.

실험 승인은 호스트가 받은 실제 사용자 응답만 원장에 넣는다. 모델이 문서에서
‘승인됨’이라고 주장하거나 user_decisions 인자를 만들어도 권한이 생기지 않는다.
지문은 핵심 주장·공급자·의존 결정·연결된 근거를 포함한다. 변경되면 다시 검토한다.
가정 승인은 포인트·슬롯·점유·속성 제약이나 별개의 가정을 면제하지 않는다.

`--stop-after 3`이면 상세 앵커 검토에서 멈추고, 이 상태에 대한 실제 승인 응답 없이
4단계로 진입하지 않는다. 일반 전체 실행은 `--stop-after 5`로 지시할 수 있으나,
현재 실제 검증에서는 사용하지 않는다. 4단계에는 저장된 실제 재료와 현재 리비전의
계산 근거가, 5단계에는 초안 비판과 변경/유지 응답이 필요하다.

## 실행과 재개

레포 가상환경에서 `PYTHONPATH=src`를 설정하고 다음 명령을 사용한다.
모델과 추론 강도는 실행자가 명시하며 사용자 설정 파일은 수정하지 않는다.

```text
python skills/build-generation/autonomous_run.py --brief <요구문 파일>
  --run-dir <artifacts 내부 실행 폴더> --stop-after 3 --timeout 5400
  --model <모델> --effort <추론 강도> --codex-exe <CLI 실행파일>
```

`reply-template.json`의 정확한 상태 지문과 실제 사용자 답변/출처를 기록한 뒤
같은 폴더와 모델로 `--resume --reply <응답 파일>`을 실행한다. 응답 종류는
`approve_experiment` / `reject_experiment` / `approve_anchors` / `feedback` /
`accept_build`다. 실험 응답은 정확한 claim_ids를 포함한다. `--last`로 세션을
추정하지 않고 저장된 정확한 세션 ID를 재개한다. 동시 실행은 배타 잠금으로 막는다.
실패 실행의 임의 재시도나 잠금 강제 삭제는 하지 않으며 원인과 프로세스 소유를 확인한다.
저장된 진행과 종료 소유가 확인된 턴 상한은 같은 전체 기한 안에서 자동 재개한다.
이전 코드로 종료된 timed_out 실행은 `--recovery-note <점검 기록>`을 명시해 회수할 수
있다. 잔여 전체 예산만 부여하며 새 후보·정답을 주입하지 않는다. 재개 시
`workflow_read_record`로 같은 정본의 필요한 결정·근거만 읽는다. 일반 생성의 기본
종료 단계는5이며 이번 검증만 명시적으로3을 사용했다.

## 확인한 것과 남은 것

- 최소 단위 13개: 상세 공급자 누락, 실험 승인 범위·변경 만료, 제약 면제 방지,
  고유/주얼 부류 검토 누락, 오래된 응답 거부, 정확한 세션 재개/웹 설정,
  PoB 표면 차단·권한 위조 거부, 실제 호출 관측, 1→2→3 자동 연결/4 진입 차단.
  추가로 종료 확인·진행·잔여 기한이 있는 timeout만 계속하는 조건, 승인 후 단순
  설명/비용/재료 바인딩으로 재승인을 요구하지 않는 조건, 잘못된 흐름 형식의 진단,
  4단계 측정 부착이 같은 현재 참조를 전진시키고 오래된 참조를 거부함을 확인했다.
- 새 Python 3개 Mypy 통과. Ruff 통과.
- 실제 MCP: 설계 단계 36개 도구, PoB 계산/조립 없음, 실제 카탈로그 해시 생성,
  실제 정본 개정과 호스트 체크포인트/현재 참조 전진 확인.
- 첫 실제 모델 시도 v1은 추론 전 strict output schema의 `uniqueItems` 거절.
  로그를 보존하고 응답 스키마만 호환 형식으로 수정했다. 품질 시험 실패/성공으로
  계산하지 않는다.

v2는1·2단계 완료 후3단계 턴30분 상한에 도달했다. 종료 소유와 명시 체크포인트를
확인하고 복구·선택 읽기·중복 검증을 보완했다. 같은 세션·설계에서 최초90분 상한의
잔여851초만 부여해3단계를 마쳤다. 운영자가 메커니즘·앵커를 고르거나 수정하지
않았으나 실행기 코드 보완과 복구 개입은 있었으므로 무중단·무개입 완주라 하지 않는다.

최종 상태 `waiting_anchor_review`, 정본 결정66·근거171·상세앵커36(채택26/후보6/
보류3/기각1), 선언 누락0·카탈로그 참조 무결성 통과, PoB 생성0이다.
검토 뷰는 `artifacts/reviews/autonomous-gemling-bow-v2/ANCHOR_REVIEW.md`, 정본 참조와
실행 이력은 같은 폴더의 `workflow.json`에 있다. 제출 리비전은
`sha256:ae591ba62a55c10c2410cdda54e12c5d2ceb3e73d910b932f3de275c1fd77f4b`다.
최종 감사는 같은 폴더의 `final-audit.json`이다. 처음3턴의 `source-snapshot.zip`과
복구 턴의 `recovery-source-manifest.json`을 구분한다. 실제 모델 실행/정리 합계는
4,874.203초이고, 단계4 계산·조립/재료 부착 호출은0이다. source_supported와
완료 검사 통과를 사용자 품질 승인으로 바꾸지 않는다.

1~3 실제 산출물의 사용자 품질 판단, 4~5 실제 PoB 조립·피드백 왕복은 아직 남아 있다.
실제 웹 호출과 source_supported 라벨을 함께 검사해도 문장 해석의 정확성이나 전체
메커니즘의 성립을 기계적으로 입증하지 못한다. 소스 버전·적용 범위·실사용 증거와
상호 모순은 에이전트가 해석하고 사용자가 최종 설계를 검토해야 한다.

웹/재개 연결은 [공식 CLI 문서](https://learn.chatgpt.com/docs/cli/reference)와
[웹 검색 문서](https://learn.chatgpt.com/docs/web-search)를 확인하고 기존 로컬 실행기를
재사용했다. 실행이 진행됐다는 사실을 빌드 품질 개선이나 #188 해결로 보고하지 않는다.
