# R5 제품 비교 실행기 사전 감사

현재 구현/관측과 남은 실행을 구분한다. 본 평가는
[고정 프로토콜](POK_REDESIGN_HELDOUT_PROTOCOL.md)을 따르며 이 문서가 브리프·예산·순서나
평가 기준을 바꾸지 않는다. 보류 과제 모델 실행은 아직 시작하지 않았다.

## 확인한 공백

| 현재 경로 | 실제 관측 | 필요한 보정/검증 |
|---|---|---|
| codex_runtime.build_command | `--ephemeral`을 넣고 새 exec만 생성 | H1은 기록을 유지하고 이벤트의 정확한 session ID로 재개. 다른 세션을 고를 수 있는 `--last` 사용 금지 |
| redesign_run | F/O/P/R의 독립 단발 실행, 자동 재시도 없음 | H1 단계별2400/3000초·같은 시험의 문맥/산출물·숨긴 후속 입력, H2의5400초를 보존하는 제품 비교 실행기 필요 |
| redesign_server | R1 TOOLS/REFERENCE_TOOLS로 표면을 제한 | R5는 각 제품의 정상 도구 전체를 사용. 새 기록/복구 도구를 옛50개 카탈로그로 제거하지 않음. 웹/거래/셸 금지는 동일 실험 정책으로 구분 |
| paths/artifact/cache | R1은 서버 import 전 공통 paths를 실행별로 바꿈 | 제품 코드·KB·PoB 선택을 바꾸지 않고 같은 시험의 단계만 산출물/캐시를 공유. 다른 시험과 격리 |
| check_frozen_inputs | 저장소 밖으로 resolve되는 경로를 일괄 거부 | 동결 기준판의 명시 junction 매핑과 대상 전체 해시를 별도 검증. 무조건 외부 경로 허용으로 완화하지 않음 |
| native 프로세스 정리 | 이전 실행기의 직접 Popen/사후 트리 종료 경로 | 공통 controller의 소유 Job/group·절대 기한·종료 확인 적용. 두 제품에 같은 수집/종료 정책 사용 |

모델이 사용하는 제품 기능과 시험 진행을 위한 파일 읽기/지침 전달을 구분한다.
baseline 소스는 변경하지 않고 외부 실행기가 각 제품을 실행한다. 정해진 후속 메시지를
참가자가 먼저 읽을 수 있게 전체 운영 문서/후속 폴더를 노출하지 않는다.

## 문맥 재개에 관한 확인

[공식 비대화형 문서](https://learn.chatgpt.com/docs/non-interactive-mode)는 명시 세션 ID를
사용한 `codex exec resume`를 설명한다. [CLI 명령 참조](https://learn.chatgpt.com/docs/developer-commands?surface=cli)와
현재 동결한 실행 파일의 `exec resume --help`도 재개·JSON 이벤트·출력 스키마를 지원한다.
이는 도움말/계약 확인이며 실제 모델의 문맥 보존·MCP 재연결·두 번째 단계 성공 증거가 아니다.

동결 manifest의 CLI SHA256은
`9d563ee4e0441ff9d59d612013e0460ddf8e5709735c2d9f6b98b7ef8ca4eb42`다.
도움말은 종료0이었고 기본 sandbox에서는 임시 PATH alias 생성/정리의 권한 경고가 있었다.
본 실행 전 같은 바이너리 해시와 실제 노출 설정을 재확인한다. 도움말 실행은 인증 파일을
읽어 출력하거나 다른 세션을 재개하지 않았다.

## 본 평가 전 필요한 증거

- 비게임 장난감 입력의 단계1→명시 ID 재개→단계2 결과와 같은 시험의 산출물 회수.
- 단계1에는 없는 후속 파일이 단계2에서만 보이는지, 다른 시험/운영 문서는 읽지 못하는지.
- 정상 제품 표면의 실제 카탈로그·스킬·로드 소스 식별, 첫 단계와 재개 뒤에도 같은 제품인지.
- 종료/취소 때 소유 프로세스 정리와 부분 로그/응답 보존, 시작/재개 비용까지 포함한 절대 예산.
- 기준판/개선판의 같은 수집기·모델·바이너리·KB/PoB와 입력 무결성. 개선판의 별도 동결.

현재 R3/R4 전체 단위 검사 중이므로 구현을 유지한 채 이 공백만 확인했다.
장난감 모델 실행·제품 비교 controller·개선판 동결·R5 본 실행은 미완료다.

파일 보조 도구의 쓰기 경계도 제품 도구와 구분한다. 기존 artifact_file은 inputs 외의
임의 산출물 경로에 쓸 수 있으므로 그대로 노출하면 기계가 발행한 builds/sessions까지
수정할 수 있다. R5의 공통 보조 쓰기는 명시한 작업 메모/초안 공간에 한정하고,
기계 근거·체크포인트·동결 입력/참고 지침은 이 도구로 덮어쓰지 못하게 해야 한다.
이는 과거 시험에서 위조가 관측됐다는 판정이 아니라 새 수집기의 신뢰 경계 요구다.

## 서버 어댑터 1차 실제 검증

skills/build-generation/product_server.py는 정상 제품 도구를 유지한 채 trial 경로와
공통 파일 보조만 구성한다. R1 arm/configure를 호출하지 않는다. 작업 메모는 work/에만
쓰며 inputs/reference/builds/sessions를 덮어쓸 수 없다. 동결 checkout과 trial 저장소가
겹치는 설정을 거부한다. 관련10검사 및 CI와 같은 strict mypy6소스 통과.

artifacts/reviews/r5-product-surface-probe-v1/result.json에서 실제 stdio로 기준판/현재판을
각2회 시작했다. 제품 도구50/73개에 공통 보조1개만 더한51/74개가 실제로 노출됐고
두 번째 서버에서도 목록·메모가 유지됐다. 기계 근거 쓰기는 MCP 오류로 거부했다.
기준판 archive manifest의921파일을 전후 검사해 변경0을 확인했다.
현재판은 improved-working 관측이며 아직 R5 동결 개선판으로 부르지 않는다.
이 결과는 MCP 서버 재연결/namespace의 증거이고 CLI 모델 문맥 재개/행동 증거가 아니다.

## 실제 Astra 2단계 문맥 재개

r5-resume-toy-v1/result.json: 기준판/현재 작업판 모두 passed. 동결한 CLI·code-mode host·
LuaJIT 해시를 확인하고 gpt-6-astra/ultra로 제품별2턴을 순차 실행했다.
첫 턴에서 대화에만 주어진 값이 MCP 저장소에 복사되지 않았음을 검사했다. 명시 세션 ID로
재개한 둘째 턴에서 그 값과 기존 작업 메모, 첫 턴 종료 뒤에만 제공한 새 파일 값을 모두
확인했다. 각 턴 실제 MCP2호출·정상 종료/owned cleanup 확인, 기준판921파일 변경0.
CLI 재개 성공과 MCP 재연결을 별도 증거에서 함께 확인했으며 --last로 선택하지 않았다.
비게임 toy라 H1/H2나 그 해답은 사용하지 않았다. 일반 빌드 자율 진행·품질의 증거는 아니다.

수집기는 총 예산 안에 최대5초 정리 여유를 두고 입력/출력을 파일로 보존한다. schema-valid
응답만으로 성공을 판정하지 않고 실제 turn.completed/단일 세션 ID를 확인한다.
짧은1.5초 테스트의 정리0.14초 실패는 미확인 상태로 보존했고, 짧은 예산 정리 여유를
보정한 뒤 실제 프로세스/부분 로그/후속 차단 포함32검사 통과했다.
기준/개선판 본 캠페인의 무결성 매핑·개선판 동결·시행/평가는 여전히 미완료다.
