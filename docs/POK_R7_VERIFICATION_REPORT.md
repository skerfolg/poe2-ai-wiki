# R7 근거·완료 범위·남은 작업

2026-11-04. 전체 R0~R7 완료는 아직 입증되지 않았다. 이 문서는 빌드 품질과 기술 검증, 실제 UI 적용을 구분한다.

## 품질 판정

승인된12회 R/B/N×H1/H2×2회는 수집을 마쳤다. 첫 인프라 중단을 재시도하지 않았고 남은11회는 원래18시간 상한 안에서 종료했다. 유효 최종 응답8개(자체 완료6·미완료2), 미제출4개를 모두 남겼다. 코드·ready·문서량·DPS로 품질을 대체하지 않는다.

실물8개를 동결 엔진/PoB로 독립 계산하고6축 초기 기술 평가를 기록했다. H1 재투자 비교6개는 재현됐지만 H2 최신안의 반복 공급·실전 회전은 미입증이다. 준비기의 낮은 축적 값이 실제 반환 페이지까지 전달된 사례도 있어 정보 부재만으로 원인을 설명할 수 없다. 사용자 선호는 아직 받지 않았다.

**#188은 미해결로 유지하고 새 경로의 전반적 우월성이나 기본 전환을 선언하지 않는다.** 이후 코드 수정이 원래12회 결과를 개선한 것처럼 소급하지 않는다.

## 발견·수정과 실패 보존

- #209: 탄약 효과에 공격 모드2를 지정한 두 원본 실패를 재현했다. 단발/상주 오류 안내에 알려진 활성 효과·MAIN/CALCS 모드와 명시 입력 경로를 붙이고 원래 원인/입력을 보존했다.
- 이 후속 안내가 독립 worker에서 KB를 읽은 회귀를 실제 stdio 시험으로 발견했다. worker는 KB 안내를 명시적으로 끄며 패키지 부재에서도 원래 오류를 유지한다. 최초 실패와 수정 검증을 모두 남겼다.
- #214: 전체 소스 복사 번들의 Node 경로에서 개발 Export/Rares.txt 읽기 실패가 났다. 표준 읽기 API 대조에서도 재현됐고 원래 OS 원인은 미확정이다. upstream 공식 배포 목록에 없는 개발 자료까지 묶던 자산 범위를 수정했다. 검사 예외·권한 변경·읽기 실패 무시를 넣지 않았다.
- 최초 fixture/인용 오류, 중단한3131 전량 실행, 원래 전송 오류·누락 파일·서로 다른 진단안 비교를 보존했다. 좋은 중간안이나 나중 수정으로 바꾸지 않는다.

## 현재 제품 선택
