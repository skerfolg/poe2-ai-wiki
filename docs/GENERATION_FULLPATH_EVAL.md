# 동일 원자료 범위의 직접 대화·기존 PoK·수정 PoK 비교

작성: 2026-10-20. 상태: **실행 조건 검증 완료·본 실행 직전 — 결과 없음**.

이 비교는 앞선 [국소 지침 실험](GENERATION_CONTROLLED_EVAL.md)을 대체해 원래 질문을
시험하기 위한 새 실행이다. 앞선 점수나 답안을 입력·정답·대조 결과로 재사용하지 않는다.
새 모델 실행 전에 자료·조건·변경안·완료 기준을 동결한다.

## 비교 대상

| 조건 | 실제 사용 경로 |
| --- | --- |
| A 직접 대화 | 일반 Codex의 파일 검색·코드 실행과 stock PoB. PoK 스킬·KB 가공 결과·MCP를 제공하지 않음 |
| B 기존 PoK | `61167b1`의 정상 생성·조립 스킬과 전체 PoK 도구. 반복·최적화·계산·조립 사용 가능 |
| C 수정 PoK | 같은 기반 도구·원자료에서 선택적 연속 조회를 실제 MCP에 추가하고, 질문·조립 결과로 돌아가는 탐색 변경안을 적용 |

C의 변경은 `skills/build-generation/native_server.py`와
`skills/build-generation/adaptive-discovery.md`다. 기존 3단계 실행기를 호출하지 않는다.
새 MCP 진입점은 기존 도구를 모두 유지하고 `search_and_read`만 추가한다.
검색 순위는 추천 순위가 아니며 미열람·오류·실제 내부 조회 수를 반환한다.
일반 생성의 기본 경로로 승격한 것이 아니라, 이번에 시험할 변경안이다.
지침과 조회 기능을 함께 바꾸는 조건이므로 둘의 개별 효과를 분리해 주장하지 않는다.

## 공통 과제와 종료 조건

새 컨셉은 **직접 시전 냉기 주문을 주력으로 하는 맵핑 빌드**다. 클래스·전직·
주력 스킬·고유 아이템·방어 축은 정하지 않는다. 이동 중 다음 팩 대응과 짧은
공격 기회에서의 응답성을 중시하며, 처치가 없는 보스에서도 공격·자원을 유지해야 한다.
기존 젬링 혼돈 점화, 석궁, 창 실험의 답안을 참고하지 않는다.

백지 신규이며 후보 선택과 일반적인 구성 판단은 각 실행에 위임한다.
레벨 100의 고투자 완성안을 목표로 하고, 하위 티어를 만드는지와 내부 탐색 순서는
각 경로에 맡긴다. 현재 패치의 합법적 고유·희귀를 사용할 수 있으며 실거래 가격
조사와 시세 예산은 요청하지 않는다. 합성 희귀는 가능한 접사·티어와 획득 가정을
설명해야 한다. DPS·EHP만으로 이동·조작·자원·세팅 여유의 가치를 대체하지 않는다.

최종 제출물은 가져올 수 있는 PoB 공유코드 원문, XML, 한글 설명이다.
설명에는 전체 장비·패시브·주얼·보조젬 구성, 핵심 작동 원리, 선택과 포기의 이유,
설정·가정·실측과 미측정·남은 작업을 담는다. 중간 JSON이나 PoK의 내부 문서
형식을 A에 강제하지 않는다. 형식 변환만 가능해도 완성 빌드로 판정하지 않는다.

## 공통 예산과 무개입

- 모델: `gpt-6-astra`, 추론 설정 `ultra`. 각 조건은 대화 이력 없는 별도 세션이다.
- 총 실행시간: 조건마다 **5,400초(90분)**. 준비·인증·무관한 예제 사전 점검은 별도다.
  본 실행의 프로세스·MCP 기동, 자료 검색·계산·조립 대기 시간은 포함한다.
- 단계 수·조회 횟수·조회 응답 크기·후보 개수·단계별 시간 배분은 강제하지 않는다.
- 같은 금액 또는 토큰 사용량을 집행한 실험이라고 주장하지 않는다.
  실제 입력·캐시·출력 토큰과 경과 시간을 실행 기록에서 별도로 공개한다.
  별도의 자동 승인 검토 사용량이 CLI 수치에 포함되는지는 확인되지 않았다.
- 같은 모델의 단일 설계자 비교이므로 별도 하위 모델을 호출하지 않는다.
  외부 최신 웹 자료 대신 고정 원자료를 사용한다.
- 부모는 개별 빌드의 해법·도구 수정·누락 보충을 실행 중 전달하지 않는다.
  각 실행 자체의 수정·재탐색·재조립은 정상 절차이며 허용한다.
- 완료 전 자발적 종료 또는 시간 종료를 그대로 기록한다. 부족한 결과만 골라
  재시도하거나 부모가 수리해 원래 결과로 제출하지 않는다.
- 실행 전 인프라 실패와 설계 도중의 좌초를 분리하고, 실패 시도도 보존한다.
- A, B, C 순서로 같은 호스트에서 병렬 기동한다. 서버 부하·디스크·CPU 경합은
  남는 환경 요인이며, 병렬 실행을 동일한 계산 처리량 보장으로 해석하지 않는다.

## 자료와 실행 환경 동결

원자료 복구·출처 대조를 완료했다. PoK가 선별한 소수 레코드나 가공된 KB를
A에도 초기 묶음으로 주는 방식은 사용하지 않는다. 게임 원본, 고정 PoB 코드,
래더 원본 및 PoK의 추가 지식에 대응하는 관측 원본의 범위를 확인한다.
복구하지 못한 자료를 있다고 가정하거나 PoK 요약을 원본으로 이름만 바꾸지 않는다.

고정 ingestion 원본 커밋은 `ae31c8567b4dedb658228648071069021ebf0e8a`다.
추가 ladder·측정 원본 커밋 `b2cf53231e0969105c69410258516faf7e7f2cd6`도
별도로 복구했으며, 적용 패치·파일별 해시·자료 범위의 대응을 기록한다.
외부 가이드 요약 Build 33개와 Insight 19개의 원본은 복구하지 못했다.
이번 비교의 공통 자료는 복구 가능한 원본 전량으로 한정한다. B/C의 실험용
KB에서도 그 밖의 자료만 근거로 한 레코드·서술·파생 참조를 같은 출처 규칙으로
제외한다. 혼합 출처와 필수 계산 규칙은 먼저 원본을 필드별로 검증한다.
생산 KB는 변경하지 않으며, 이 자료 제한에서 생긴 공백을 생산 PoK의 공백으로
귀속하지 않는다. 필터링한 KB를 A에게 선별 자료로 제공하지도 않는다.

기본 원본 2,243파일, 추가 원본 23,191파일, stock PoB 1,896파일의 경로·크기·
SHA-256·Git blob SHA를 기록했다. 래더 원코드 5,497개는 모두 XML로 풀렸고,
UsageProfile 110개의 원본 query가 대응한다. 집계값을 전부 재산출한 검사는 아니다.

B/C는 원문과 문서 판본이 대응하는 위키 설명 34개를 그대로 유지한다.
원본 없는 설계 서술 7개·인사이트 19개·Build 33개를 제외했으며, 혼합 출처
9레코드는 독립적으로 확인한 값과 기존 해석을 보존하고 미복구 실증 주장을
제거했다. 가공·검색·집계·도구 알고리즘 자체를 공통 원자료로 만들지 않는다.
원본으로 확정하지 못한 기존 가정은 별도 원장에 남겼으며, 기존 코드·지침의
모든 해석이 정확하거나 모든 문장이 원자료로 완전히 증명됐다는 뜻은 아니다.

투영 후 양쪽 KB는 19,725레코드이며 스키마·참조와 정상 MCP 제약 검사를
통과했다. B/C 바이트 해시는 모두
`e0f95f112d7eb68fa382b69b367f9632d710c1a5968f55af2e587ce8ebb8f9db`다.
중립 검사 전후 `var`에는 `.gitkeep`만 있어 검색·PoB 캐시가 남지 않았다.
비교의 범위는 **복구한 동일 원자료를 이용하는 전체 생성 경로**이며,
생산 PoK가 가진 모든 과거 관측 지식까지 포함한 비교는 아니다.

세 실행의 결과와 캐시·도구 로그는 서로 다른 작업 공간에 저장한다.
상위 저장소의 PoK 지침, 사용자 전역 스킬, 과거 실험 답안이 A에 자동으로
들어가지 않는지 실제 입력 구성을 확인한다.

실행 전에는 빌드 선택과 무관한 빈 PoB의 저장·공유코드 변환·재입력·계산을
확인한다. A가 PoB를 사용할 인터페이스가 없어서 탈락하는 상황을 방지하기 위한
기술 점검이며 빌드 후보를 제공하는 절차가 아니다.

실행 환경의 실제 중립 모델 점검은 8회였다. A 파일 쓰기·읽기 2회와 B의 실제
MCP 호출 1회가 성공했고, 실패 5회 및 모델 전 인프라 실패 3회도 보존했다.
Windows sandbox 설정 누락, 지연 도구 검색 라우팅 오류, 모든 도구 승인을
금지한 시험용 설정을 발견했다. 최종 환경은 정상 `workspace-write`와 자동 승인
검토를 사용하며, 공통 기술 안내에는 등록 도구 목록으로 호출 경로를 찾는 방법을
명시했다. 이 점검을 빌드 생성 성공으로 세지 않는다.

최종 세 실행 위치의 무모델 입력 검사도 통과했다. 부모 프로젝트 지침·전역
스킬의 자동 주입은 없으며, B/C는 자기 사본의 정상 지침을 명시적으로 읽는다.
읽기 접근 범위는 프롬프트와 사후 도구 기록으로 감사하며, 운영체제가 다른
사본·자료의 읽기를 전부 차단했다는 주장은 하지 않는다.
사본의 Git 커밋 표시가 상위 저장소를 가리킬 수 있으므로 실제 버전은
기준 archive 커밋과 파일별 해시로 고정한다.

## 제출 후 평가

먼저 원본 제출물을 봉인하고 동일 PoB 버전으로 재입력한다. 계산에 필요한
장비·스킬·트리의 실재 여부, 포인트·장비 조건·자원, 설정의 근거와 계산 공백을
검토한다. 평가 중 발견한 결함은 결과에 기록하며 원본을 수리하지 않는다.

비교는 완료 여부와 실제 조합을 먼저 제시한다. 피해·방어 수치와 함께 이동,
첫 유효 공격, 공격 공백, 범위, 조건 유지, 자원, 조작 부담, 다른 부위의 세팅
여유를 본다. PoB가 못 재는 기재는 미측정으로 남긴다. 모델의 설명 점수를
인게임 작동이나 완성 빌드의 성능 인증으로 사용하지 않는다.

각 조건 1회의 사례 비교이므로 일반적 우열을 확정하지 않는다. 실제 자료를
받은 시점, 후보가 바뀌거나 사라진 시점, 조립·검증에서 되돌아간 지점을
공개 출력과 도구 기록으로 대조해 원인 후보를 좁힌다.
