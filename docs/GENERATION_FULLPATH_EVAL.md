# 동일 원자료 범위의 직접 대화·기존 PoK·수정 PoK 비교

작성: 2026-10-21. **세 실제 실행 종료, 원본 공유코드·XML·한글 보고서 제출 확인.**

**이번 C 수정으로 생성 품질이 개선됐다는 증거는 얻지 못했다.** A는 이동·회복·저항을
묶은 고유 조합과 마나 수지를 설계했고, B는 비용 없는 부여 주문으로 주력 지속 비용을
해결했다. C는 무료 Blink와 원거리 Nova를 구성했으나 무처치 보스에서 생명력 비용을
감당하는 문제를 남겼다. B/C의 정상 PoK 추천 상태도 모두 `not_ready`다.

[A·B·C 원본 PoB 공유코드 전체](GENERATION_FULLPATH_CODES.md)를 PR에서 직접 복사할 수 있다.
제출 후 원본을 보정하거나, 잘 안 된 방식만 다시 모델로 실행하지 않았다.
아래의 사후 도구 수정은 이 실험 C에 포함되지 않으며 **수정 후 품질 효과는 미검증**이다.

이 비교는 앞선 [국소 지침 실험](GENERATION_CONTROLLED_EVAL.md)의 범위 오류를 바로잡은
새 실행이다. 같은 `gpt-6-astra / ultra`, 같은 복구 원자료, **90분 총 실행시간 상한**을
사용했다. A는 PoK 없이 일반 도구·stock PoB로, B/C는 각자의 정상 생성·조립 절차로
연속 작업했다. 단계·조회 횟수·후보 수·중간 형식을 공통으로 강제하지 않았다.
시간 예산을 같게 한 것이며, 실제 토큰이나 금액 지출까지 같게 통제한 실험은 아니다.
원자료 미복구 범위를 제외한 제한과 한 컨셉·각 1회라는 한계도 아래에 공개한다.

## 제출물과 핵심 요구 충족

공통 과제는 레벨 100 고투자 **직접 시전 냉기 주문 맵핑 빌드**다. 클래스·전직·주력·장비는
자유이며 이동, 짧은 공격 기회, 처치 없는 보스의 지속 운용이 중요하다.

고유 개수로 우열을 정하지 않는다. **유틸리티의 작동 원리와 다른 부위의 세팅 여유를
실제 조합으로 해결했는지**를 본다. A는 Mageblood의 Quicksilver 두 개·Silver·Bismuth를
이동·속도·저항으로 연결했다. B도 높은 DPS 대안보다 주력 무소모와 응답성을 택했다.
C도 Portent의 무료 Blink를 찾았다. 따라서 “PoK가 유틸리티를 전혀 못 찾았다”는 진단은
틀리다. 반대로 B/C의 고유 미채용을 전역 비교 끝에 고유보다 낫다는 증거로 볼 수도 없다.

활성 ItemSet·Spec·SkillSet과 실제 슬롯 참조를 확인했다. 세 제출물 모두 미참조 아이템이
없고, 주얼 소켓 ID가 할당 노드에 있다. B의 양손 무기 보조 손 공란은 누락이 아니다.
일반 123·유료 전직 8포인트는 각 실행의 검사·보고에 근거하며 독립 재검산으로 포장하지
않는다. 직렬화된 노드 수 A133/B132/C134를 그대로 유료 포인트 수로 세지 않았다.
B는 재입력 시 무료 노드·부여 스킬 등이 복원되어 노드134·젬18이 된다.

## 원본 재입력과 수치의 범위

세 코드를 Base64·zlib로 복원한 XML은 각 제출 XML과 **바이트 단위로 같다**.
원본 코드·XML·보고서·실행 요약을 봉인했고 사후 계산은 사본에서만 수행했다.
공통 stock PoB 최초 재입력은 A/B 성공, C 120초 시간 초과였다.
C만 사후 추가 확인으로 같은 사본을 300초까지 허용했으나 다시 시간 초과였다.
따라서 C의 최종 저장값은 이번 독립 감사에서 재현하지 못했다.
이 시간 초과를 곧바로 인게임 불성립으로 판정하지 않는다.

**아래는 각자가 제출한 설정의 관측값이며 같은 전투 조건의 성능 순위표가 아니다.**
A는 준비된 Pinnacle 조건, B는 저주·노출·냉각·동결을 뺀 Standard Boss 조건이다.
C도 기본 Pinnacle 조건을 설명하지만 A/C의 일부 보스 값은 명시 입력보다 stock 기본값에
의존한다. B의 파편 여러 발 겹침은 게임 실측이 아닌 조건부 계산이다.

A는 준비 없는 첫 타격·Zenith 미충족 조건을 따로 제시했고, 120초 자원 사건 모형도
제출했다. 이번 감사는 기본 비용·재생을 재현했으며 그 사건 모형을 다시 실행한 것은
아니다. B는 주력 비용 0이 재현됐으므로 주력 사용 비용과 피격 회복 문제를 구별한다.
C의 저장 DPS를 지속 가능한 DPS로 검증한 것은 아니다. C 스스로 보스 흡수 저항 가정에 따라 주기가
달라진다고 밝혔으며, 핵심 요구를 만족하는 지속 주기를 확정하지 못했다.

B/C의 `FullDPS=0`은 집계 그룹 선택과 관련된 별도 값이고 주력 피해 0이 아니다.
목걸이의 무료 부여 스킬, 미측정, UNKNOWN, 시간 초과 하나를 인게임 결함의 증거로
바꾸지 않는다. 세 방식 모두 인게임 실측·실매물 조달·제작 비용은 이번 범위 밖이다.

## 어디서 선택이 좁아졌나

| 근거 수준 | 관측한 지점 | 해석 |
| --- | --- | --- |
| 실제 호출·코드 대조 | B가 마법 플라스크·참의 초당 충전 접사를 UNKNOWN 판정 때문에 포기 | 도구 오류가 실제 장비 선택을 바꿈. 출처 색인 누락을 재현했고 수정 대상 |
| 실제 호출·원 출력 | C Portent Amulet 자동 생성에 `-1 Suffix Modifier allowed`와 접미 3개가 함께 있음 | 생성기와 검사기가 베이스 한도를 같이 놓침. C가 수동으로 한 개 제거 |
| 공개 진행·제출물 | B는 고비용 Frostbolt 축에서 무소모 Freezing Shards로 바꿈 | 정상 경로에도 재설계 능력은 있었음. 모든 PoK 실행이 최초 스킬에 고정된 것은 아님 |
| 실제 계산 실패·진행 | B 아이템 후보가 주력 공급원 Gelid Staff를 제거하면 검색 전체 오류; C 네 비교가 각각 90초 초과 | 부적합한 후보와 계산 실패 처리 때문에 다른 대안을 다루는 시간·범위가 줄어듦 |
| 공개 기록·결과 | A의 최종 다섯 대안도 같은 전직·트리에서 부품/주력/보조를 비교; B/C도 동급 완성 경쟁안 전체 비교 미완료 | A까지 전직·트리·장비를 전부 재최적화한 전역 탐색은 아님 |
| 정적 코드·지침 | 정상 스킬에 고정 후보 수, 선택안 하나만 조립, 다른 후보 PoB 심화 금지 존재 | 초기에 설명으로 좁힌 뒤 비싼 완성 패키지 탐색을 꺼리는 구조. 이 문구 하나의 인과 효과를 실험으로 분리한 것은 아님 |
| 실제 C 호출 | `search_and_read` 11회, 별도 search_kb85회, get_entry221회; 중첩 `tags` 인자는 사용하지 않음 | 조회 묶음은 사용됐지만 핵심 비용 문제가 남음. 조회 타입 결함의 사후 수정이 이 C 결과를 개선했다는 근거는 없음 |
| 실제 완료 기록 | B `stale_evidence`116·`output_changed`6 등; C 자원·대안 근거 부족 | 조립·수정과 현재 구성의 증거 갱신 비용이 종료에 영향을 줌. 증거 검사를 삭제할 근거는 아님 |

같은 모델이 PoK를 사용할 때는 후보를 고르는 일 외에 계산 실패를 복구하고,
형식을 맞추고, 변경 후 증거를 다시 만드는 데도 예산을 쓴다. 이번에는 그 부담과
잘못된 후보 차단이 실제 기록에 보인다. 다만 이를 “모델이 덜 똑똑해졌다”거나
모든 컨셉에서 직접 대화가 더 좋다는 결론으로 확대하지 않는다.

기존 전체 스펙 비교 도구 `evaluate_delta`는 이미 있었다. 도구 부재가 전부가 아니라
**그 도구로 경쟁하는 완성 조합을 만들고, 실사용 핵심 실패 시 다시 여는 절차**가
약했다. 사후 수정은 이 실행 흐름과 실제 후보 반환/실패 처리를 고치며, 고유 필수 채용이나
DPS 최댓값 자동 선택 같은 새 엔진 판단을 넣지 않는다.

C의 무기 검색은 초기 장비 1개·노드 51개에서 고유 131종을 239회 계산했지만
한 라운드·체인 0회였다. 허리띠도 장비 8개·노드 51개에서 고유 20종을 비교했고
희귀 템플릿·체인 계산은 0회였다. Mageblood의 저항 +45씩이 유틸리티로 반환됐어도,
그 여유를 다른 부위의 시전·범위·회복으로 돌린 완성 대안은 관측되지 않았다.
**많이 호출한 것과 여러 부위를 다시 맞춘 것은 다르다.**

트리도 반경 목표 35에 현재 28이라 하위 목표 최적화에 진입하지 못했다는 반환을
받았다. 이후 보조 변경으로 반경 36을 만들었으나 최종 문맥의 트리 재검토를 마치지
못했다. `converged=true`는 해당 설정에서 양수 후보 소진을 뜻하며 빌드 전체의
최적화 완료 증거가 아니었다.

명령 실패는 검색 무결과·복구 가능한 오류도 포함하며 곧 빌드 실패가 아니다.
`completed`도 반환 내용의 성공을 뜻하지 않는다. 실행 요약의 `tool_execution_errors`는
라우터 stderr 오류만 가리키므로 빈 배열을 “실패 0건”으로 읽으면 안 된다.
별도 자동 승인 검토 사용량 포함 여부는 미확인이다. 공통 호스트의 병렬 실행으로
자원 경합도 남아 있으므로 처리량·금액 효율의 우열은 확정하지 않는다.

기본 원본 2,243파일, 추가 원본 23,191파일, stock PoB 1,896파일의 경로·크기·
SHA-256·Git blob SHA를 기록했다. 래더 원코드 5,497개는 모두 XML로 풀렸고,
UsageProfile 110개의 원본 query가 대응한다. 집계값을 전부 재산출한 검사는 아니다.

B/C는 원문과 문서 판본이 대응하는 위키 설명 34개를 그대로 유지한다.
원본 없는 설계 서술 7개·인사이트 19개·Build 33개를 제외했으며, 혼합 출처
9레코드는 독립적으로 확인한 값과 기존 해석을 보존하고 미복구 실증 주장을
제거했다. 가공·검색·집계·도구 알고리즘 자체를 공통 원자료로 만들지 않는다.
원본으로 확정하지 못한 기존 가정은 별도 원장에 남겼으며, 기존 코드·지침의
모든 해석이 정확하거나 모든 문장이 원자료로 완전히 증명됐다는 뜻은 아니다.

투영 후 양쪽 KB는 19,725레코드이며 스키마·참조와 정상 MCP 제약 검사를
통과했다. B/C 바이트 해시는 모두
`e0f95f112d7eb68fa382b69b367f9632d710c1a5968f55af2e587ce8ebb8f9db`다.
중립 검사 전후 `var`에는 `.gitkeep`만 있어 검색·PoB 캐시가 남지 않았다.
비교의 범위는 **복구한 동일 원자료를 이용하는 전체 생성 경로**이며,
생산 PoK가 가진 모든 과거 관측 지식까지 포함한 비교는 아니다.

세 실행의 결과와 캐시·도구 로그는 서로 다른 작업 공간에 저장한다.
상위 저장소의 PoK 지침, 사용자 전역 스킬, 과거 실험 답안이 A에 자동으로
들어가지 않는지 실제 입력 구성을 확인한다.

실행 전에는 빌드 선택과 무관한 빈 PoB의 저장·공유코드 변환·재입력·계산을
확인한다. A가 PoB를 사용할 인터페이스가 없어서 탈락하는 상황을 방지하기 위한
기술 점검이며 빌드 후보를 제공하는 절차가 아니다.

실행 환경의 실제 중립 모델 점검은 8회였다. A 파일 쓰기·읽기 2회와 B의 실제
MCP 호출 1회가 성공했고, 실패 5회 및 모델 전 인프라 실패 3회도 보존했다.
Windows sandbox 설정 누락, 지연 도구 검색 라우팅 오류, 모든 도구 승인을
금지한 시험용 설정을 발견했다. 최종 환경은 정상 `workspace-write`와 자동 승인
검토를 사용하며, 공통 기술 안내에는 등록 도구 목록으로 호출 경로를 찾는 방법을
명시했다. 이 점검을 빌드 생성 성공으로 세지 않는다.

최종 세 실행 위치의 무모델 입력 검사도 통과했다. 부모 프로젝트 지침·전역
스킬의 자동 주입은 없으며, B/C는 자기 사본의 정상 지침을 명시적으로 읽는다.
읽기 접근 범위는 프롬프트와 사후 도구 기록으로 감사하며, 운영체제가 다른
사본·자료의 읽기를 전부 차단했다는 주장은 하지 않는다.
사본의 Git 커밋 표시가 상위 저장소를 가리킬 수 있으므로 실제 버전은
기준 archive 커밋과 파일별 해시로 고정한다.

## 제출 후 평가

먼저 원본 제출물을 봉인하고 동일 PoB 버전으로 재입력한다. 계산에 필요한
장비·스킬·트리의 실재 여부, 포인트·장비 조건·자원, 설정의 근거와 계산 공백을
검토한다. 평가 중 발견한 결함은 결과에 기록하며 원본을 수리하지 않는다.

비교는 완료 여부와 실제 조합을 먼저 제시한다. 피해·방어 수치와 함께 이동,
첫 유효 공격, 공격 공백, 범위, 조건 유지, 자원, 조작 부담, 다른 부위의 세팅
여유를 본다. PoB가 못 재는 기재는 미측정으로 남긴다. 모델의 설명 점수를
인게임 작동이나 완성 빌드의 성능 인증으로 사용하지 않는다.

각 조건 1회의 사례 비교이므로 일반적 우열을 확정하지 않는다. 실제 자료를
받은 시점, 후보가 바뀌거나 사라진 시점, 조립·검증에서 되돌아간 지점을
공개 출력과 도구 기록으로 대조해 원인 후보를 좁힌다.
