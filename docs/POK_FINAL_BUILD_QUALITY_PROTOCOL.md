# 최종 빌드 품질 검증 — 실행 전 계획

상태: 2026-11-03 초안. 입력·실행기·평가 기준을 동결하기 전에는 참가자를 시작하지 않는다.
이 문서는 기존 R5 결과를 새 코드의 성공으로 소급하지 않고 별도 최종 검증 블록을 준비한다.

## 목적과 경계

최종 질문은 「최신 PoK가 실제로 더 쓸 만한 빌드를 만드는가」다. 코드 테스트·도구 호출
횟수·DPS·ready·문서 양·UI 설치 완료는 이 질문의 대체 지표가 아니다.
R5는 중간 비교, R7은 최종 품질 판정과 전환 여부를 다룬다. 운영 경로/상주 버전 정렬은
이를 지원하는 작업이며 품질 검증보다 먼저 기본 전환을 완료했다고 하지 않는다.
검증 실행기가 고정된 대상 소스로 새 MCP를 띄우므로 현재 상주 서비스 교체는 선행조건이 아니다.

자료/파일 접근은 도구 표면과 실제 callable을 동결한다. B/N의 생성 스킬 차이는 제품 처치다.
모델 이름 동일성이 원격 가중치/호스트 부하의 동일성을 보장한다고 주장하지 않는다.

## 과제와 반복

H1/H2의 입력·고정 반지 원문·40+50분/90분 예산을 기존 프로토콜과 동일하게 재사용한다.
이 과제들은 이미 결함 조사에 사용했으므로 새 heldout으로 부르지 않고 회귀 품질 과제로 표시한다.
새 과제를 추가한다면 결과 열람 전 별도 입력·기준·반복/예산으로 동결하며 기존 결과와 섞지 않는다.

완전 비교안은 3군×2과제×2회=12시험, 시험당90분 상한으로 최대18시간이다.
기존 R5의8회 실행 예산과는 별도 블록이다. 실행 횟수/상한과 새 모델 호출의 승인 범위를
확정한 뒤 순서를 동결한다. 축소하면 빠진 과제/반복의 한계를 먼저 명시한다.
임의로 원래 실패 실행을 덮거나 잘 된 군만 추가 생성하지 않는다.

각 시험은 독립 세션·산출물·캐시이고 무거운 실행은 순차 진행한다. H1 후속 입력은
그 참가자 자신의 문맥에서만 재개한다. 미완료도 정해진 후속 메시지만 제공하며 운영자가
중간 최선안을 선택하거나 다음 빌드 방향을 알려주지 않는다.

## 실행 전 필수 확인

1. 모델/추론·CLI 경로/바이너리 해시와 사용 가능성을 확인한다. 다른 모델로 대체하지 않는다.
2. 세 제품/도구 표면·실제 로드 소스와 공통 데이터/PoB·입력의 해시를 저장한다.
3. R 참고군을 최신 카탈로그에서 다시 검증한다. 오래된 R1 허용 목록의 카탈로그 일치 검사를
   건너뛰거나 신규 고급 도구를 실수로 노출하지 않는다.
4. 상속 지침/다른 MCP/셸/웹/거래/추가 모델·다른 시험의 답안 접근을 점검한다.
5. 장난감 입력으로 시작·기한/소유 종료·문맥 재개·정확한 파일 수집을 사전 검증한다.
6. 최종 답변에 긴 공유코드 문자열을 필수로 전사시키지 않는다. 모든 군에서 실제 내보낸
   PoB/XML 파일 또는 정확한 파일 참조로 제출할 수 있게 하고 실제 바이트를 평가한다.
   문자열도 제출했다면 불일치는 숨기거나 수선하지 않고 전달 오류로 별도 기록한다.
