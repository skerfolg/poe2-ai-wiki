# 새 컨셉 생성 절차 대조 실험

작성·갱신: 2026-10-20 (한국 시간). 상태: **두 실험의 생성·계획 평가 시도와 코드 검증 완료**.

이 문서는 완료된 실험과 아직 하지 않은 일을 구분한다. 기존 젬링 혼돈 점화
빌드의 정답이나 사람 빌드의 PoB는 이번 실험 입력에 사용하지 않았다.

**현재 결론은 “PoK 지침이 모델의 설계 능력을 떨어뜨린다”가 아니다.** 유효하게
집계된 석궁 답안은 직접 설계 92점, 현행 PoK 98·92점, 인과관계 우선 92점이었다.
확인된 결함은 필요한 원문을 다음 판단에 제때 전달하지 못하는 조회 절차와
이미 제공한 자료를 다시 읽는 비용이다. 이 실행 경로를 수정했으며, 별도 창
과제에서도 원문을 일찍 받아 조합의 운용을 구체화한 사례가 나왔다.

## 질문과 비교 범위

같은 모델이 직접 설계할 때와 기존 PoK 절차를 따를 때, 핵심 작동 원리와
구체적인 조합을 얼마나 잘 찾는지 비교한다. 새 과제는 석궁을 사용하는 맵핑
컨셉이다. 팩 사이 이동, 공격 중 이동, 첫 유효 공격, 재장전 공백을 목표로
삼고, 반복 공격 입력 최대 2개와 처치 없이 돌아가는 보스 공격 순환을 요구했다.
직업·전직·스킬·아이템·방어 구조는 열어 두었다.

| 방식 | 다르게 준 내용 | 공통 조건 |
| --- | --- | --- |
| A 직접 설계 | 기존 생성 스킬 지침 없이 과제를 직접 해결 | 같은 모델·초기 자료·KB 접근·출력 형식·조회 및 시간 한도 |
| B 현행 PoK 절차 | 변경 전 `skills/build-generation/AGENTS.md` 전체 | 동일 |
| C 인과관계 우선 | 플레이 목표 → 작동 경로와 구성 묶음 → 근거 확인 → 비교 | 동일 |

A도 읽기 전용 PoK 조회를 사용할 수 있다. 그러므로 이 실험은 도구가 전혀 없는
대화와 제품 전체를 비교한 것이 아니라, **같은 자료 접근 아래의 설계 절차 비교**다.
모든 방식에 초안·조회·수정·조회·최종 판단의 공통 실행기를 적용했다. 이 공통
실행기 자체가 평소 대화의 누락을 줄일 수 있으므로 결과를 제품 전체의 우열로
일반화하지 않는다.

초기 자료는 석궁 스킬 19개·패시브 대표 효과 28개·고유 19개·보조 38개·전직
노드 16개로 미리 구성했고, 추가 접근은 읽기 전용 도구 20개로 제한했다.
자료가 전혀 준비되지 않은 대화나 모든 PoK 도구를 자유롭게 사용하는 과정과는
다르다. 따라서 이번 비교에서 발견한 병목이 기존 실전 실패의 전부라고
단정할 수 없다.

핵심 조합 발견까지만 비교한다. 장비 전 부위, 연결된 패시브 트리, 주얼,
보조젬 전체의 최적화나 PoB 성능 측정·인게임 검증을 완료했다는 뜻은 아니다.

## 동결한 조건과 실제 실행

| 항목 | 조건·관측 |
| --- | --- |
| 모델·추론 설정 | `gpt-6-astra`, `ultra` |
| 반복 | 방식당 2회, 총 6회 |
| 순서 | 사전 고정: C2 → B1 → A2 → A1 → C1 → B2, 최대 3개 병렬 |
| 모델 예산 | 실행당 새 CLI 세션 3회, 회당 600초, 실행 전체 1,800초 |
| 조회 예산 | 실행당 실제 읽기 전용 MCP 조회 12회, 앞 두 단계에 각 6회 |
| 자료 | 동일한 120개 레코드 초기 묶음과 같은 고정 KB 접근권 |
| 패치 | 0.5.4b, 트리 0_5 |
| 결과 보존 | 단계별 공개 초안·후보·조회 요청·실제 응답·최종 결과·사용량·오류 |
| 생성 결과 | 6/6 완료, 18/18 단계 실행 유효, 실제 조회 72회·도구 오류 0 |
| 격리 사후 검사 | 기록된 이벤트와 stderr에서 허용되지 않은 네이티브 도구 흔적 0 |

조회 상한과 아래 횟수는 **설계 자료를 읽는 요청**이다. 서버 연결·등록 도구
목록을 확인하는 `server_info`·`list_tools` 메타데이터 호출은 사전 규칙대로
별도 기록하고 설계 조회 예산에서 제외했다.

실제 검색 대상과 읽은 문서는 각 방식의 판단에 따라 달라진다. **전체 문맥이
동일했다고 주장하지 않는다.** CLI는 전체 토큰의 강제 상한을 제공하지 않아
같은 시간·세션·조회 상한으로 통제하고 실제 토큰 소비를 아래에 공개한다.
세션 내부의 모델 샘플링 횟수와 도구 스키마의 완전한 부재는 관측하지 못했다.

| 실행 | 경과 초 | 입력 토큰 | 출력 토큰 | 출력 중 추론 토큰 | 조회 |
| --- | ---: | ---: | ---: | ---: | ---: |
| A1 | 817.890 | 233,560 | 26,575 | 14,687 | 12 |
| A2 | 984.219 | 233,470 | 29,475 | 18,518 | 12 |
| B1 | 1,012.657 | 272,084 | 30,535 | 17,030 | 12 |
| B2 | 818.079 | 270,435 | 26,858 | 14,150 | 12 |
| C1 | 863.110 | 232,465 | 27,839 | 16,552 | 12 |
| C2 | 1,110.610 | 234,649 | 34,216 | 22,117 | 12 |

추론 토큰은 출력 토큰의 부분집합이며 더해서 합계를 만들지 않는다. B는 기존
지침 전체가 추가되어 입력 토큰이 더 많았다. 시간은 최대 병렬 실행 조건에서
관측된 값이므로 방식의 고유 속도로 단정하지 않는다.

실험 v1에서는 네이티브 하위 에이전트 호출 시도가 stderr에만 남는 격리 결함을
발견했다. 최종 답안이 나오기 전에 실행 중이던 세 조건을 모두 중지·보존했다.
`agents.enabled=false`를 명시한 v2에서 여섯 실행 전체를 다시 시작했다.
좋지 않은 결과만 골라 재실행한 것이 아니다. 이 파일의 수치는 모두 v2다.

## 실제로 만들어진 핵심 조합

아래는 각 최종 답안의 잠정 주안이다. 새로운 과제는 석궁이며 직업을 잠그지
않았으므로 일부 답안이 젬링을 골랐다. 기존 혼돈 점화의 정답을 재사용한
것은 아니다. “주안”은 완성·검증된 빌드를 뜻하지 않는다.

| 실행 | 잠정 주안의 작동 경로·부품 | 구조 대안 | 남은 핵심 확인 |
| --- | --- | --- | --- |
| A1 | 젬링 단일 영구 결빙 볼트 + 마석 징·기동성·가뿐한 재장전 | 패스파인더 충격 파편 + 라타의 공격으로 Dodge 장전 | 전직 접근·실제 입력·마나 지속 |
| A2 | 젬링 충격 파편 + 라타의 공격의 탄약 공급 + 마석 징·기동성 | 패스파인더 단일 결빙 탄종 + 일반 재장전 | 수동 Dodge의 정확한 사건·공급 시점. 일반 장전 금지라 핵심 의존 |
| B1 | 패스파인더 영구 결빙 볼트 → 파편 탄환의 동결 소비 → 한탄 목걸이 부여 파편 청소부 | 라타 충격 파편 + 조건부 감전 파열 탄환 | 실제 두 버튼 운용·재장전 대상·보스 재동결·마나 |
| B2 | B1과 같은 동결 생산·소비·무료 부여 스킬 묶음 | 젬링 라타 충격 파편 + 감전 파열 탄환 | 탄약 선택/발사의 실제 두 버튼 운용·보스 순환 |
| C1 | 패스파인더 단일 영구 결빙 탄종 + 질주 공격·가뿐한 재장전·탄약 보존 II | 폭발성 사격 + 라타의 공격 | 비용 지불 시점·첫 명중·마나 수지 |
| C2 | 젬링 단일 영구 결빙 볼트 + 마석 징·가뿐한 재장전·탄약 보존 II | 패스파인더 소이 사격 + 라타의 공격 | 입력 응답·전직 비용·마나. 대안 Dodge 판정 미확인 |

한탄 목걸이는 고유 아이템이 아니라 **부여 스킬이 있는 목걸이 베이스**다.
이를 고유 채용 수로 세지 않는다. A·C는 탄약 선택과 발사의 분리를 반영해
두 탄종 교대를 보류·기각·수정했고, B는 두 탄종 주안을 유지하면서 입력
성립을 채택 전 확인 조건으로 남겼다. 따라서 B의 높은 설명 점수만으로
사용자의 최대 두 입력 조건을 실제로 만족했다고 볼 수 없다.

## 확인한 설계 축소 지점

아래는 점수나 방식의 우승 판정이 아니라 원출력과 실제 조회의 전이 관측이다.

1. **검색 결과를 얻은 뒤 본문을 읽을 기회가 끝났다.** B2는 마지막 조회에서
   `mechanic.crossbow-ammunition-skills`를 찾았지만 받은 것은 ID·이름·태그 등의
   요약이었다. 마지막 판단 단계에서는 추가 조회가 금지되어 탄약 스킬이 직접
   발사하지 않는다는 본문을 읽지 못했다. 두 탄종과 발사 입력의 관계를 미검증으로
   남긴 채 처음 주안을 유지했다.
2. **본문에 도달하면 실제로 후보를 바꿨다.** A1·A2·C1·C2는 첫 조회에서 같은
   메커니즘을 찾고 두 번째 조회에서 본문을 읽었다. A2·C1·C2는 두 탄종 구성의
   입력 제약을 반영해 후보를 보류·기각하거나 단일 탄종으로 바꿨다.
3. **현행 PoK 절차가 적용한 이득도 있다.** 무료 부여 인스턴스 정보 자체는
   공통 초기 자료에 있었다. B는 이를 조합에 적용하고 목걸이 베이스를 추가 조회해
   파편 청소부 변형과 접두어 한 칸 감소라는 대가를 구체화했다.
   다른 방식이 이 정보를 놓친 것을 PoK 절차의 실패라고 뒤집어 해석하지 않는다.
4. **검색 방식도 경로를 갈랐다.** B1은 Reload 메커니즘 검색의 빈 결과 진단에 따라
   타입을 풀었지만, 이후 모드·젬 목록으로 가면서 석궁 입력 규칙에 도달하지 못했다.
   검색 오류 0회는 결정에 필요한 사실을 모두 읽었다는 뜻이 아니었다.
5. **이미 받은 자료를 다시 읽는 데 예산을 썼다.** 반환된 JSON 구조가 초기
   레코드와 완전히 같은 상세 조회는 B1 3회, B2 4회였다. B의 조회 24회 중 7회다.
   A1·A2·C1은 각각 1회, C2는 0회였다. 재확인이 항상 무가치한 것은 아니지만,
   이 경우 새 필드는 없었고 아직 읽지 않은 핵심 규칙은 남아 있었다.
6. **같은 후보 ID가 같은 조합을 뜻하지 않았다.** C2는 마지막 단계에 대안의
   열 관리 구성을 Dodge 장전 구성으로 크게 바꾸고도 후보 ID를 유지했다.
   후보 ID 유지나 세 단계 실행 완료만으로 새 조합이 검증됐다고 볼 수 없다.

따라서 현재 근거가 지지하는 수정 대상은 “규칙을 더 많이 기억하라”가 아니라
**검색 → 상세 확인을 실제 조회 예산 안에서 연결하는 실행 절차**다.
기존 지침에도 구조가 다른 후보와 묶음 비교가 이미 있으므로 같은 문장을
추가하는 것으로 해결됐다고 판정하지 않는다.

## 독립 평가 방식

생성 결과를 보기 전에 20개 기준·100점 루브릭과 불일치 처리 규칙을 동결했다.
목표·인과 20점, 구체적 조합 25점, 구조 대안 15점, 조건·대가 15점,
불확실성 10점, 근거 정확성 15점이다. 아이템 이름 수·도구 횟수·표기 DPS에는
독립 점수를 주지 않는다.

방식 이름과 사용량을 가린 결과마다 새 평가 세션 두 개를 사용했다. 기준별
점수 차가 2점 이상이거나 핵심 오류 판정이 다르면 별도의 세 번째 평가자가
해당 항목만 판정한다. 실제 출력 구간과 자료 ID를 요구하고, 인용이 틀리거나
실행이 실패하면 원본을 남기며 점수를 임의 보정하거나 자동 재시도하지 않는다.
미검증과 실제 모순은 별도 항목이다. 문체로 절차를 짐작할 가능성은 남는다.

최초 평가 12회 중 10회가 인용·출력 위치 검증을 통과했다. A1과 C2는 각각
평가 1회가 이 검증에서 실패했다. 실패한 평가를 다시 뽑거나 0점으로 바꾸지
않아 두 답안의 최종 점수는 없다. 불일치가 있는 나머지 3개 항목은 독립
재판정 3회로 처리했고 모두 유효했다. 계획된 평가 시도와 재판정을 모두
봉인한 다음 방식 이름을 공개했다. **시도 완료와 점수 전량 확보는 다르다.**

| 실행 | 목표·인과 /20 | 구체 조합 /25 | 구조 대안 /15 | 조건·대가 /15 | 불확실성 /10 | 근거 /15 | 합계 /100 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| A1 직접 | — | — | — | — | — | — | 미집계 |
| A2 직접 | 18 | 21 | 15 | 15 | 8 | 15 | 92 |
| B1 현행 PoK | 20 | 23 | 15 | 15 | 10 | 15 | 98 |
| B2 현행 PoK | 18 | 21 | 13 | 15 | 10 | 15 | 92 |
| C1 인과관계 우선 | 18 | 23 | 13 | 15 | 8 | 15 | 92 |
| C2 인과관계 우선 | — | — | — | — | — | — | 미집계 |

유효한 네 결과 모두 평가자가 **핵심 연결의 추가 검증 필요**를 남겼다.
이 점수는 근거를 연결한 설계 설명의 품질이며, 완성 빌드가 실제 작동한다거나
사람의 빌드보다 좋다는 점수가 아니다. 높은 점수와 입력 규칙 미확인이
공존한다는 점도 평가의 한계다. 자동 평가자도 생성과 같은 모델 계열이므로
독립 세션이라는 것이 사람 평가나 독립된 오류 성향까지 뜻하지 않는다.

작은 표본과 두 점수의 결측 때문에 방식별 평균으로 우승을 정하지 않는다.
현행 PoK가 열등하다는 가설은 지지되지 않았다. 기존 절차의 조합 탐색·부여
인스턴스·대가 확인을 유지하고, 전이 기록으로 확인한 실행 병목을 수정했다.

## 별도 창 과제에서의 변경 전후 검증

석궁 결과를 보기 전에 동결한 **창 기반 이동 공격**을 사용했다. 초기 자료
80개, 반복 공격 입력 최대 2개, 처치 없는 보스 순환을 공통으로 주었다.
H1은 변경 전 B 지침과 일반 조회, H2는 새 `discovery.md`와 연속 조회다.
둘 다 실제 제품 `run.py`를 사용했고 같은 초기 필드 색인·후보 이력을 받았다.
모델·세션·시간·실제 조회 상한은 주 실험과 같고 각 1회 실행했다.

지침의 판단 순서와 조회 연산을 함께 바꾼 **수정 묶음의 검증**이다.
색인이나 연속 조회 하나에 모든 차이를 귀속하지 않는다. 석궁 실험과
합쳐 방식별 평균을 만들지도 않는다.

| 관측 | H1 기존 절차 | H2 수정 절차 |

| 완료 모델 단계 | 3 | 3 |
| 실제 MCP 설계 자료 조회 | 12 | 11 |

H2의 연속 조회 4개는 검색 4회와 상세 3회를 소비했다. 직접 조회 4회를 더해
실제 11회다. 새 연산에 무료 조회를 주지 않았다. 시간과 실제 토큰 사용은
동일하지 않으므로 비용 대비 우위를 주장하지 않는다.

**두 답안의 주안은 모두 돌개바람(Twister) + 와류 기병창(Whirlwind Lance)이다.**
H1은 마지막 조회에서 회오리 메커니즘 ID만 얻어 무충전 상태의 단계 형성을
미확인으로 남겼다. H2는 첫 조회 단계에서 검색과 상세 읽기를 연결해
“기존 회오리에 겹쳐 생성하면 기존 회오리가 이동하고 단계가 하나 증가한다”는
본문을 받았다. 다음 판단부터 무충전 준비, 회오리 외곽 이동, 경계를 넘어
붕괴시키는 행동과 돌개바람의 소비를 동시에 계산하지 않는 운용으로 구체화했다.
같은 조합 이름에서도 **실제 규칙을 읽은 시점이 조작 설계의 깊이를 바꿨다.**

H1도 유효하게 수정했다. 격분 공급원이 없는 대안에서 억제자 보조를 제거했고,
원소 쇄도 전문을 읽어 번개 창과의 연결을 보강했다. H2는 앗지리의 경멸과
혈석·돌개바람 대안, 폭풍의 창·천둥 도약 대안을 유지하면서 적립·회수와
접촉 범위가 확인되면 선택이 바뀌는 조건을 적었다. 고유의 단독 DPS가 낮거나
측정되지 않았다는 이유로 묶음을 제거한 사례는 관측되지 않았다.
다만 실제 DPS·PoB 측정은 하지 않았으므로, 수치와 유틸의 충돌 상황에서
유틸을 제대로 선택하는지나 PoB의 0을 오독하는 문제가 해결됐는지를
직접 시험한 것은 아니다.

남은 문제도 실제 기록에 나타났다.

- H2의 Bloodstone+Mechanic 검색은 다른 타입의 결과가 있다는 진단을 받았지만
  재검색하지 않았다. 자료가 없다는 결론이나 효과 0점으로 바꾸지는 않았다.
- 빈 검색이 예상보다 1회를 덜 써 예산 1회가 남았어도 마지막 단계에서는
  추가 조회할 수 없었다. **고정 3단계는 적응형 탐색 루프를 대신하지 못한다.**
- 혼돈 쇄도 상세가 보류 사유 일부를 해소했지만 정형 후보 이력 행은 초기
  상태에 남고 공개 설명만 갱신됐다. 이력 보존은 질문별 상태 자동 갱신이 아니다.
- 기폭의 상세 본문을 읽어도 정확한 접촉 범위와 보스 명중 수는 해결되지 않았다.
  첫 검색 결과의 상세 읽기를 의미상 해결이나 최적 후보 발견으로 세지 않는다.

독립 최초 평가 4회는 모두 인용 검증을 통과했다. 불일치가 있는 항목은 답안별
새 평가자 1명씩, 총 2회 재판정했다. H2는 유효하게 집계됐고, H1의 재판정은
출력 내부 경로 `/report` 대신 `/output/report`를 인용해 검증에 실패했다.
이를 사후 수정하거나 다시 호출하지 않아 **H1의 최종 점수는 없다**.
모든 계획된 시도를 봉인한 뒤에만 방식 이름을 공개했다.

| 창 실행 | 목표·인과 /20 | 구체 조합 /25 | 구조 대안 /15 | 조건·대가 /15 | 불확실성 /10 | 근거 /15 | 합계 /100 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| H1 기존 절차 | — | — | — | — | — | — | 미집계 |
| H2 수정 절차 | 12 | 25 | 13 | 13 | 10 | 15 | 88 |

H2에도 핵심 검증 필요 판정이 남았다. 평가자는 팩 전환 시 남은 설치물·투사체의
처리, 첫 유효 피해와 팩 처리 시간의 관측, 마나 고갈·회수 중 피격을 공급 구조와
연결하는 설명이 부족하다고 봤다. **원문 전달 개선이 설계 전체의 완결성을
보장하지 않는다는 결과**다. H1과의 점수 차이·우승은 산출하지 않는다.

H2의 후보 ID에는 `H2-C1` 같은 접두가 남아 있어 익명화가 완전하지 않다.
평가자는 H1/H2와 절차의 대응표를 받지 않았지만 접두·문체로 절차를 짐작할
가능성은 있다. 실행 중인 평가 입력이나 동결 규칙을 바꿔 사후 보정하지 않았다.

1개는 있었지만 시험 결과 XML은 저장됐고 시험 실패는 없었다.

Ruff 검사·포맷 334파일, 소스 strict mypy 152파일과 제공자·CLI 2파일,
모듈 의존 경계 검사, 저장소 고정 버전의 커밋 전 검사를 통과했다.
Windows에서 실제 실행했다. 다른 OS 설정의 타입 검사가 그 OS에서의
실제 모델·프로세스 실행 검증을 대신하지는 않는다.

중간 검사에서 정본 문서의 로컬 산출물 링크와 새 중단 회귀 시험의 인코딩
누락을 발견해 고쳤다. 기존 임시 폴더 접근 차단은 작업 공간 내 새 시험
폴더로 해소한 뒤 위 전체 검사를 다시 수행했다. 검사를 완화하거나 실패
항목을 제외하지 않았다.

창 실험에 사용한 제품 파일 사본·해시는 그대로 보존했다. 그 이후 실제
CLI 중단 처리와 동일 의미의 린트 표현을 수정했으며, 설계 지침·조회 연산·
평가 원본은 변경하지 않았다. 후속 수정까지 전체 시험에 포함했다.

## 재현과 보존 범위

이 보고서에는 로컬 산출물이 없어도 판단할 수 있도록 조건·관측값·한계·교정
결과를 본문에 옮겼다. 저장소의 `artifacts/`·`var/`는 git 정본 KB나 영구 보존
근거가 아니다. 전체 프롬프트·원답안·조회 응답·평가 원장은 작업 PC에 보존했으며,
이 보고서가 그 대용량 원장을 저장소에 포함했다고 주장하지 않는다.

관측을 가르는 핵심 원문은 다음과 같다.

- B2 마지막 검색 행: `mechanic.crossbow-ammunition-skills`,
  필드 `id/type/name_ko/name_en/tags/verification`. `data.stats` 없음.
- 다른 실행의 상세 반환: “The Ammunition Skill itself does not fire the
  Ammunition, only load it into your Crossbow.”
- B2 최종 보고: “효과 본문과 선행 경로는 반환하지 않았으므로 입력 방식·재동결
  제한·전직 포인트 배분을 새로 확정할 수 없다.”
- C1 최종 후보: 기존 `A-freeze-reload`는 `rejected`,
  새 `C-single-ammo-reload`는 `selected`.

실행 경로의 결정적 재현은
[실제 MCP 통합 시험](../tests/integration/test_generation_discovery.py)에 있다.
같은 `crossbow ammunition` 메커니즘 검색과 상세 조회 2회를 사용해, 본문이
다음 판단 전에 전달되는지를 기존 방식과 수정 방식에서 비교한다. 이 시험은
자료 전달의 재현이며 같은 모델 답안이나 점수의 결정적 재생을 보장하지 않는다.
