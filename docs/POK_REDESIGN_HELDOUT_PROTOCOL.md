# R5 새 보류 과제 — 튜닝 전 고정 프로토콜

2026-11-01, R2에서 준비한다. R1의 A/B/앵커 과제를 보류 표본으로 재사용하지 않는다.
R3/R4 동작 구현·튜닝 전에 아래 브리프·후속 사용자 메시지·기준·예산·순서와 공통 입력을
고정한다. 입력 동결 영수증이 생성되기 전에는 R5 참가자를 실행하지 않는다.

## 비교판과 공통 조건

기준판은 R1 종료 시 동결된 e7bd429+R0 실행 수정이다. 실제 바이트는
`artifacts/reviews/redesign-r2-baseline/baseline-source.zip`과 manifest로 보존했다.
개선판은 R3/R4 구현과 검사 후 별도 동결한다. 기준판을 최신 소스로 덮어쓰지 않는다.
두 판은 같은 고정 KB/인사이트·PoB·제작 규칙/제외 목록·모델 식별자와 예산을 사용한다.
현행과 개정 생성 스킬은 각 제품판의 일부이며 그 차이도 처치에 포함한다.
R1의 F/O/P/R 도구 제한을 이 제품 비교의 기본 규칙으로 이식하지 않는다.

모델은 기존과 같은 gpt-6-astra/ultra다. 같은 모델 이름을 사용한다는 것과 원격 서비스의
가중치/호스트 부하까지 고정했다는 것은 다르다. 같은 CLI 실행 파일과 바이너리 해시를
확인하고 도구/스킬/실제 로드 소스·캐시·산출물·네이티브 사용량/오류를 각각 기록한다.
각 시험은 독립이며 무거운 실행을 병행하지 않는다. 웹·거래·셸·추가 모델·다른 시안의
답안/평가 열람은 허용하지 않는다. 기존 공통 KB/인사이트의 일반 참고는 허용한다.

## H1 — 새 주문 빌드와 고정 반지 변경

새 레벨100 Stormweaver의 Spark 빌드를 생성한다. 완드+방패, 생명력+ES 방어,
CI/낮은 생명력 전환 금지, 일반123/전직8 이내, 원소·카오스 저항75% 이상이다.
두 반지는 처음에 희귀로 선택하며 단일 고투자 구성만 낸다. 매물/가격을 지어내지 않는다.
이동 맵핑과 처치 없는 보스에서의 마나/회복·조작 비용을 함께 다룬다.
첫 단계는 현재 가능한 초안 실물·선택 이유·미검증을 제출한다. 전역 최적화 완료는 요구하지 않는다.

그 뒤 다음 사용자 메시지를 같은 시험의 후속 입력으로 준다:

> Dream Fragments 일반판(item.dream-fragments)을 확보했다. 단계2에 제공하는 fixed-ring.txt
> 원문 그대로 Ring 1에 반드시 채용하자. cultivated판·다른 롤·타락·촉매로 바꾸지 않는다.
> 첫 단계의 ‘두 반지는 희귀’
> 조건은 Ring 1에 한해 변경하며 이 변경을 승인한다. 전직·Spark·완드+방패·생명력+ES와
> 나머지 제약은 유지한다. 단순 장착으로 생긴 공급 여유/손실을 진단하고 다른 장비·주얼·
> 패시브·보조·유틸에 필요한 재투자를 수행하라. 기존 선택을 유지한다면 새 문맥의 이유와
> 대가를 설명하라. 변경 전·단순 장착·최종안을 같은 조건과 명시된 한계로 비교하고,
> 바뀐 선택과 오래된 근거/미해결 질문을 갱신하라. 단순 장착안이 부적법하면 진단안으로
> 보존하되 완성안으로 부르지 말라. 실제 최종 PoB·XML과 대응 설계를 전달하라.

후속 메시지는 첫 단계가 끝나기 전 참가자에게 노출하지 않는다. 운영자 저장소의 전체
프로토콜/후속 파일을 참가자 입력 폴더에 복사하지 않는다. 단계별 산출물·로그는 전부
보존하고 후속 단계는 그 참가자 자신의 문맥/산출물만 이어받는다.
기준판과 개선판이 처음부터 서로 다른 초안을 고를 수 있다. 따라서 단순 장착의 순수
동일 입력 인과 대조가 아니라 전체 생성+개정 제품 흐름의 비교다.

첫 단계 기동부터2400초, 두 번째 단계 기동부터3000초, 합계5400초 이내다.
첫 단계가 미완료여도 운영자가 중간 최선안을 골라주지 않는다. 정해진 후속 메시지만
제공하며 참가자가 자신의 진행 상태에서 계속한다. 후속 native 문맥 재개·같은 시험의
근거/산출물 접근은 장난감 입력으로 사전 검증해야 한다. 그 검증에 H1 해답을 사용하지 않는다.

## H2 — 새 석궁 상태 회로와 생명력 복합 방어

새 레벨100 Witchhunter의 석궁 공격 빌드를 생성한다. 생명력+방어도+회피를 방어의
중심으로 삼고 CI/낮은 생명력 전환은 하지 않는다. 일반123/전직8 이내, 원소·카오스
저항75% 이상, 단일 고투자 구성이다. 상태 회로·주력·보조·고유 선택은 자유다.

서로 다른 상태/자원/조건의 생산과 소비가 두 기능 이상에서 연결되어야 한다.
석궁의 기본 장전/재장전 설명만으로 두 기능을 채우거나 단일 스킬의 좋은 기본 피해를
복잡한 이름으로 바꾸어 설명하지 않는다. 무조건 많은 기재를 넣는 것도 가점이 아니다.
완전 초기 진입, 다음 팩, 처치 없는 보스, 이탈/만료/소비 후 복구를 나눠 주체·대상·
횟수/쿨다운·준비·마나/장전/방어 회복과 조작 비용을 설명한다.
무적/명중 실패/위험한 근접 회수 때 끊기는 연결과 계속 가능한 대체 동작을 남긴다.
자료로 확인하지 못한 연계는 미검증으로 표시하고 그것 없이 성립하는 핵심과 구분한다.
기동부터 최종 제출까지5400초다. 미모델링 중첩·회전 추가분을 표기 DPS에 몰래 더하지 않는다.

## 반복과 순서

각 과제/제품판2회, 합계8시험이다. H1은 시험당2단계이며 단계 수를 새 독립 표본 수로 세지 않는다.
순서는 H1 기준1 → H1 개선1 → H2 개선1 → H2 기준1 → H1 개선2 → H1 기준2 → H2 기준2 → H2 개선2다.
한 시험이 끝나고 소스/입력 무결성과 소유 실행 종료가 확인된 뒤 다음 시험을 시작한다.
각 시험의 예산에는 시작/도구/모델/재개 비용이 포함된다. 진행 메시지로 절대 기한을 연장하지 않는다.

소스·자료·정책/입력 무결성 실패는 캠페인을 중단해 원본을 보존한다. 일반적인 도구
거절·모델의 미완료·기한 초과는 결과이며 좋은 중간안을 대신 제출하거나 자동 재시도하지 않는다.
버그 수정 후 같은 결과를 새 구현의 보류 검증으로 소급하지 않는다. 오염된 과제의
재사용 범위와 추가 새 표본의 필요를 명시한다.

## 출력과 평가

실제 명시된 PoB 파일/공유코드와 XML, 같은 실물의 한글 설계·손익·근거/미해결을 제출한다.
새 설계 기록이 지원되면 그 정본/체크포인트를 함께 전달한다. 구버전에 없는 JSON 양식을
강제로 손으로 흉내 내게 하지 않으며 같은 의미의 자유 서술도 인정한다.
코드 필드 문자열과 명시한 저장 파일을 구분하고 최신/최강 중간안을 선택하지 않는다.

고정6축0~4의 초기 기술 평가, 기본 적법/계산/전달·치명적 오류와 사용자 선호를 구분한다.
축은 메커니즘·장비·패시브/주얼·젬/유틸·공동 재설계·과제 적합성이다. 총 DPS·고유 수·
도구 호출 수·문서 길이·ready 도장으로 성공을 대신하지 않는다. 서로 다른 피해 단위나
과제를 하나의 DPS 순위로 합치지 않는다. 계산/왕복은 명시한 최종물과 원래 설정을 우선
검증하고 동일 조건은 입력/출력/변경 범위를 별도로 고정해 비교한다.

H1에서는 고정 변경의 준수, 재개방/공급 재투자·누락한 영향·낡은 근거·문서/실물 불일치,
미해결 질문의 처리와 정당한 사용자 결정/불필요한 진행 지시를 함께 평가한다.
H2에서는 생산/소비 주체·첫 발동·지속/소모/만료·실패 시 복구·전체 행동/자원 비용을 본다.
완주·시간·토큰/호출·회수/기록 분량은 별도 비용 기술이며 독점 원인을 추정하지 않는다.

기술 평가자는 군별 운영을 알 수 있어 완전 맹검이라고 주장하지 않는다. 표시용 검토
자료는 운영 식별자를 가리고 정확한 원본/대응표를 별도 보존한다. 사용자 체감과 인게임
유지율은 계산으로 대체하지 않는다. R5 결과와 실제 UI 검증을 통과하기 전 #188 해결이나
새 기본 경로 전환을 선언하지 않는다.
