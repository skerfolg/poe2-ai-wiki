# R1 종합 — 계약 재설계에 사용할 결론

2026-11-01. R1의 기준 실험과 초기 기술 검토를 마쳤다. 생성 품질 개선 효과나 #188 해결을
입증한 단계가 아니다. [첫 과제 대조](POK_REDESIGN_FIRST_TASK_FINDINGS.md),
[추가 과제 사실](POK_REDESIGN_FOLLOWUP_RESULTS.md), [추가 기술 평가](POK_REDESIGN_FOLLOWUP_QUALITY.md)를
함께 읽는다. 다음 단계는 R2 계약·시험 명세이며 R3~R7은 미완료다.

## 수행 범위와 한계

| 블록 | 실행 | 최종 응답 | 명시된 최종 PoB 해석 | 해석 범위 |
| --- | ---: | ---: | ---: | --- |
| 첫 신규 생성 과제 | 8 | 7 | 7 | F/O/P와 R 정성 참고, 초기 기술 평가 |
| A 장비 교체 후 공동 재배분 | 8 | 8 | 7 | 원본/단순 교체/최종, 독립 및 동일 config 검사 |
| B 상태 연계·유지 | 8 | 8 | 8 | 다른 피해 단위의 실물과 상태 전이/재시동 검토 |
| 별도 앵커 기록 비교 | 4 | 4 | 4 | 자유 서술2회/최소 기록2회, 본 비교와 합산하지 않음 |

새 블록은 gpt-6-astra/ultra, 고정0.5.4b KB·PoB·입력/도구 정책과 순차 실행을 사용했다.
후속 독립 계산19개/개별 아이템·주얼338건, A 공통 config9개를 보존했고 동결26,008파일과
실행 파일의 변경 없음을 재확인했다. 계산과 적법 검사는 알려진 범위만 입증한다.
첫 과제의35회 반복 일치는 전역 안정성 해결이 아니고, 후속19개는 각각1회 계산이다.

원래 다른 PC의 #188 브리프는 복구하지 못했다. 새 과제의 결과로 사용자의 과거 A/B/C
관측을 무효화하지 않는다. 각2회, 처치의 정보량 차이, R의 원자료 인터페이스 비대칭,
운영자와 같은 평가자의 비맹검, 첫 과제의 호스트 부하 등 한계가 남는다.
사용자 선호/실전 체감과 미모델링 상호작용은 미검증이며 R5에서 재평가한다.

## 원인 가설의 판정

| 가설 | 관측과 반증 | 이번에 정하는 것 |
| --- | --- | --- |
| H1 절차가 사고 확장을 막음 | 절차군에도 장비·트리·젬·자원 공급을 함께 재설계하고 이전 선택을 다시 연 사례가 있다. 일부는 긴 호출/마지막 증빙·전달에서 미완료다. 절차만의 순수 처치도 아니다. | 일률적 사고 저하·절차 전면 제거는 입증하지 못했다. 고정 호출 도장과 최종 근거를 분리하고 비용/기한을 명시한다. |
| H2 컨셉 운·반복 편차 | 같은 군·같은 Storm Wave 개정에서도 선택과 손익이 다르다. B도 상태 회로와 자원/방어 선택이 다르다. | 편차를 보존한다. 한 번의 승패나2회 평균으로 우열을 정하지 않는다. |
| H3 최적화 도구가 잘못 설계됨 | 기본군/선택군/절차군 모두 공동 변경이 있고 최적화 호출이 좋은 선택을 보장하지 않는다. 긴 유한 탐색은 예산을 소모했다. | 기존 도구를 폐기하지 않는다. 범위·고정 기반·종료/실패와 실제 후보를 명시하고 구성 묶음·수동 대체 근거를 허용한다. |
| H4 누적 수정/결함이 결과를 꼬이게 함 | #203 내장 트리거 오진, #204 제외 젬 누락, #205 행동 config 오거부, #206 획득 근거 복원 손실을 재현했다. 그러나 다수 실물의 계산·재투자는 동작한다. | 재현된 결함을 분리해 고친다. 엔진 전체 무효나 모든 품질 차이의 단일 원인으로 확대하지 않는다. |
| H5 사용자 목적이 DPS/ready로 축소됨 | 여러 군이 범위·회복·이동을 위해 DPS를 포기했다. 반대로 ready/호출 수는 실물의 장단점을 표현하지 못한다. | 목적과 조건·현재 구현을 기록하고 다차원 판단을 유지한다. 도구가 선택 품질을 인증하지 않는다. |

미완료의 원인도 분리한다. A/F-1과 A/P-2에는 Transport closed가, A/P-1/P-2에는
1800초 native 도구 기한 초과가 있다. B/P-1은 같은 오류가 관측된 사례가 아니다.
A/F-1 stderr의 code-mode host 종료는 PoK 서버 종료의 증명이 아니다. 호스트/MCP/계산기
중 어느 경계에서 실패했는지 포착하고 재현해야 하며 #189를 해결 처리하지 않는다.

| 채택하지 않음 | 새 거대 생성 솔버·독립 가변 설계 저장소·F/O/P/R 실험 제한의 제품 기본값화 | 판단은 AI, 엔진은 결정적 검사/변경/측정이라는 경계를 유지한다. |

앵커4회는 최소 기록의 일반 품질 효과를 입증하지 못했다. 두 방식 모두 고정 조건과
실물을 보존했고, 시간 범위가 겹치며 자유 서술도 공급자·손익을 설명한다.
기록형은 ID/참조 검사가 가능했지만 필요조건의 의미나 의존 완전성을 보증하지 않았다.
‘재생만으로 지속’ 같은 선택 전략을 보편 필수 조건으로 굳히지 않도록 범위를 표현한다.
형식 개수에 가산점을 주지 않고 같은 의미의 자유 서술/기존 문서를 보존한다.

## R2로 넘기는 출구

1. 기존 필드별 소유·ID/리비전·계산/근거 지문의 의미를 고정하고 UI 적용/undo와 연결한다.
2. 기존 경계 안에서 최소 기록·검사·렌더·체크포인트를 구현할 계약과 실패 fixture를 정한다.
3. 오진/손실·직접 편집/계산·유효한 대체 증거·취소/복구의 작은 구현 순서를 정한다.
4. 구버전 ready/purpose·MCP·UI 저장 형식을 예고 없이 제거하지 않는 매핑을 만든다.
5. R3 튜닝 전에 R5의 새 보류 과제 두 개와 기준판 재실행 경로를 고정한다.

R1의 기술 출구를 충족했다는 것과 새 계약/제품 구현·생성 품질 개선은 별개다.
효과 판단은 R5, 실제 UI 호환은 R6, 전환과 전체 검사는 R7에 남는다.
