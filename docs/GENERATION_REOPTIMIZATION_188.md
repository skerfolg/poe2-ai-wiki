## 새 실험의 조건

- 새 과제: 레벨 100 고투자 **근접 공격 기반 번개 맵핑 빌드**. 빠른 이동, 짧은 공격
  기회, 처치 없는 단일보스의 자원·회복 지속성이 목표다. 클래스·전직·주력·장비는 자유다.
- A: PoK 없는 직접 대화의 정상 절차. B: 병합된 수정 전 PoK의 정상 절차.
  C: 이번 #188 변경을 포함한 PoK의 정상 절차.
- 같은 `gpt-6-astra / ultra`, 같은 원자료 범위, 각 **총 90분 상한**을 사용한다.
  실제 토큰·금액 지출을 동일하게 맞췄다는 뜻은 아니다.
- 단계별 시간·조회 횟수·후보 수·중간 출력 형식은 공통으로 강제하지 않는다.
  A에는 PoK 스킬·KB 조회 절차를 적용하지 않는다.
- 각 방식은 정상 하위 에이전트·병렬 작업을 사용할 수 있다. 모든 작업은 같은 모델·
  추론 설정·원자료 범위와 상위 실행의 90분 상한을 공유한다.
- 기준 PoB는 `5d173cbf8c9cf394a975cbb813f19d0b6dc67ea6`이다. 기존 출처 검토를 거친
  원본 2,243개·보충 원본 23,191개·PoB 파일 1,896개의 봉인 해시를 다시 확인했다.
  B/C의 가공 KB는 같은 투영본이며 A도 그에 대응하는 원자료에 접근한다.
- B의 코드 기준은 `69867cd`이며 squash 병합 `9aa1a61`과 같은 트리다.
  C는 별도 사본에 변경 파일 해시를 고정한다. 사본에 `.git`이 없어 상위 저장소의
  커밋 번호가 표시되는 경우에는 실행 소스의 파일별 해시로 판별한다.
- 생성 중 해법·아이템·노드 힌트를 넣거나 도구를 바꾸지 않는다. 오류·좌초·미완성도
  결과로 보존한다. 한 컨셉의 각 1회이므로 일반적인 우열이나 단일 원인의 효과로 확대하지 않는다.

실험 식별자는 `20261030-generation-reoptimization-188-v2`다. 환경 사전검사와 실제
빌드 생성을 분리해 기록하며, 각 생성이 제출한 공유코드와 수행/미수행 값은 종료 후
추적되는 문서에도 옮긴다. 로컬 산출물의 존재만을 정본 근거로 삼지 않는다.

### 답안 열람 전 정한 검토 항목

1. **제출물 대응과 편집 호환성**: 원본 코드가 복원되는지, XML과 같은 구성인지,
   전체 아이템 상세보기 경로와 stock 재입력이 성공하는지 각각 기록한다. 시간 초과는
   그 검사가 미완료라는 뜻이며 코드 손상·게임 불성립의 증거로 쓰지 않는다.
2. **핵심 기재와 목표 적합성**: 피해를 만드는 연결, 짧은 공격 기회와 이동, 방어·회복,
   처치 없는 보스의 비용 지속성을 근거와 함께 읽는다. PoB에 표현되지 않은 효과는
   계산 오류와 구분한다. 설정을 켰다는 사실만으로 실전 유지가 된다고 보지 않는다.
3. **유틸과 기회비용**: 고유 아이템의 개수를 점수로 쓰지 않는다. 이동·회피·저항
   여유·자원 등 선택 이유와 그 여유를 다른 부위에 재투자한 실제 구성을 확인한다.
4. **실제로 비교한 조합과 최종 재검토**: 이름을 나열한 후보, 단일 부위 대체,
   장비·패시브·주얼·보조를 함께 바꾼 완성 구성을 구분한다. 마지막 변경 뒤 이전
   문맥의 측정을 그대로 최종 최적화 근거로 사용했는지 확인한다.
5. **발견·실행·완료 판정의 구분**: 핵심을 제안했는지, 실제 구성했는지, 재계산·
   대조했는지, 결과가 요구를 충족했는지를 따로 적는다. A에는 PoK 전용 증빙 형식이나
   도구 호출을 요구하지 않는다. 하위 에이전트 기록이 보이지 않는 경우 곧바로 미수행으로
   단정하지 않고 제출 기록·실물 차이까지 확인하며, 확인 불가를 별도 표시한다.

이 기준은 호출 수·DPS·EHP만으로 합산 점수를 만드는 기준이 아니다. 사용자가 실제
PoB를 검토할 수 있도록 원본과 결함별 근거를 함께 제공한다.

2026-10-30 00:45:27~28 KST에 세 군을 시작했다(최대 시작 차이 0.558초).
각 상한은 02:15:27~28 KST이며 실행 중에는 제품 사본·자료·프롬프트를 바꾸지 않는다.
C의 새 프로세스에서 도구 49개와 신규 입력의 노출·빈 트리 호출 연결을 확인했다.
이 연결 검사는 정상 빌드 생성이나 품질 검증을 대신하지 않는다.

독립 코드 검토에서 위 반경 보호 결함을 발견한 뒤 작업 브랜치에는 수정했지만, 진행 중인
C에는 변경을 주입하지 않았다. 따라서 이번 C 결과와 최종 PR의 소스는 이 후속 수정에서
다르다. 실험을 완성본 전체의 효과 검증으로 표현하지 않고 해당 경로의 실제 사용 여부를
종료 후 대조한다. 동결본의 실제 PoB 통합시험은 전체 100개가 통과했으며, 이는 독립 검토가
찾은 반경 보호 누락까지 보장하지 못했다.

최신 main의 #147·#148을 작업 브랜치에 통합한 뒤 실제 PoB 통합 106개가 통과했다.
동시에 실행한 단위시험은 1,905개 통과·4개 건너뜀·1개 실패였고, 실패는 위 #196의
실제 파일 충돌이었다. 이를 단순 재실행 성공으로 덮지 않고 소유권 수정과 동시성 회귀를
추가했다. 이 후속 수정도 진행 중인 C에는 주입하지 않았다.

제출물 공통 검사기도 과거 고정 산출물로 사전 대조했다. 정상 공유코드와 손상된 별도

원본을 수정하지 않으며 코드 복원·XML 대응·전체 아이템 편집·재입력 결과를 별도로 남긴다.
이는 아직 실행 중인 A/B/C 결과에 대한 검증 결과가 아니다.

## 중단한 사전 실행

재사용한 v1 실행기가 `multi_agent`를 끄고 단일 설계자만 허용한 사실을 답안 검토 전에
확인했다. 설치된 CLI는 이 기능을 지원하므로 환경상 불가가 아니라 추가 제약이었다.
사용자의 “같은 모델·원자료·총예산만 맞추고 각자 정상 절차”라는 요청을 충족하지 않아
2026-10-30 00:35 KST에 A/B의 소유 프로세스와 자식 프로세스를 중단했다. C는 아직
기동하지 않았다. 부분 산출물·로그·중단 사유를 보존하며 성공 표본·점수에 포함하지 않는다.
답안은 열람·채점하지 않았고, v2는 이 제약을 제거한 새 독립 세션으로 시작한다.
