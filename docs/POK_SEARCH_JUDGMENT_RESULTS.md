## 구체화와 검사 오류의 추가 관측

실제 실패 호출은 각 trial의 native-audit.json과 별도 failed-call-evidence.json에
보존했다. 세 실패 실행뿐 아니라 유일한 완료 실행에도 조회 limit/중첩 스킬 구조/
전직 내부 코드 오류가 있었다. 따라서 오류 발생 여부만으로 완료/품질을 설명하지 않는다.

- get_tool_result의 limit 범위 위반은 네 시험에서 초기 반복됐다. JSON mode의
  실제 chunk 크기는 byte budget이 결정하며 limit100이100자 페이지를 뜻하지 않는다.
- T2 제안군은 class 대신 class_name, gems 중첩, gem_id/name, 명시 효과 모드 등의
  수정이 필요했다. optimize_tree3회와 optimize_runes의 시간 초과도 관측됐다.
- T1 제안군은 XML 속성 변경 형식, 미지원 minion_count, 사용자 고정 변경 거부를
  만났다. XML 편집 대안이 있으므로 해당 오류를 곧바로 게임/계산 불가능으로 부르지 않는다.
- 최종 T2 기존군도 스킬 구조·전직 코드·효과 모드 오류 및 트리/룬 시간 초과를
  겪었다. 일부 국소 탐색 실패 후 명시 구성을 제출한 사실과 그 구성의 품질은 구분한다.

이 관측은 입력 계약의 발견/구체화 비용을 조사할 근거다. 정확한 스키마 안내나 효과
선택 정보가 실제로 접근 가능한지 먼저 확인해야 하며, 검사 제거·추측값 자동 교정·
전체 재작성의 근거로 확대하지 않는다. 이번4회는 준비 한계와 미제출 때문에 탐색 정책의
순수 효과를 분리하지 못했다. 추가 기능의 채택은 구체적인 재현/교정 범위를 정한 뒤 판단한다.

## 사용자 실물 검토 — 2026-11-05

사용자는 “개선 안되었다. 여전히 희귀 아이템만 채용했고 고가치 보조젬은 사용하지 않아.
주얼도 단 한개도 사용하지 않았어”라고 평가했다. 실제 제출 XML의 장비9개는 모두
희귀이며 플라스크/호신부5개는 normal, 주얼 매핑은0개다. 제출 설계도 고유 Lineage
보조 미채택과 주얼 없음 및 넓은 대안 비교의 한계를 명시한다. 고가치 여부의 사용자
판정을 임의 시세 평가로 바꾸지 않는다.

최종 제품 결과 판정은 **이번 목표의 실사용 빌드 품질 개선 실패**다. 단순히 미검증
상태라고만 보고하지 않는다. 전달/계산 일치는 실제 성과지만 사용자 목적 달성의 증거는
아니었다. 다만 유일한 제출물은 기존군이고 제안군은 최종 미제출이므로, 제안 안내의
순수 인과 효과가 없다고 증명한 실험으로 확대하지 않는다.

문제는 고유/주얼 개수 자체가 아니라, 고투자 목적에 맞는 강력한 선택들을 발견·구체화하고
패시브/점유/다른 장비까지 재배분한 경쟁안을 최종 선택에 반영하지 못했다는 것이다.
주얼0개도 충분한 동예산 대안 비교 끝에 효율이 낮아 기각했다는 근거가 없다.
고유 개수나 가격을 강제하는 규칙으로 해결했다고 하지 않는다.

#188은 미해결로 유지한다. #219 계산 출력 교정과 #220 실행기 안내 교정은 별도
신뢰성 수정으로만 채택 후보이며 빌드 품질 개선 실적으로 세지 않는다. 제안 정책의
기본 채택은 보류하고, 추가 모델 시험을 승인 없이 실행하지 않는다.
