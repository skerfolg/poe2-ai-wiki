# R4 전환 사전 대조 — 2026-11-01

전체 통합 검사 중 구현을 바꾸지 않고 현재 지침/관문을 읽어 다음 변경 위치를 식별했다.
이 문서는 원인 입증이나 R4 구현 완료가 아니다. BLUEPRINT/ROADMAP과 R2 계약을 따른다.

변경 원칙: 감지 가능한 누락/현재 입력 불일치는 도구가 신고한다. 어떤 빌드를 고를지는 AI/사용자
판단으로 남긴다. 원장/Markdown/PoB가 같은 리비전을 가리키게 하고 문서만으로 새 규율을 강제했다고
말하지 않는다. v1 폐기/기본 경로 전환과 UI 채택은 R7 검증 전 미리 수행하지 않는다.

## 첫 구현: 명시 입력 계산

`compute_pob(input_policy="explicit")`은 주어진 스펙을 자동 채움 없이 계산한다.
능력치 선택 누락과 수동 희귀 출처 누락은 `calculation_contract.procedure_diagnostics`에
그대로 남긴다. 추천 검사나 인게임 성립 인증을 했다고 반환하지 않는다. 기본값 `legacy`와
조립 관문은 유지하며 capability에서 새 경로를 명시한다. 실제 MCP 포함23검사 및 해당
두 소스 mypy/Ruff가 통과했다(`r4-explicit-calculation-v1.xml`).

이는 불완전 탐색안을 계산하는 계약이다. XML/스펙 자체가 파싱되지 않거나 native 계산이
실패하는 경우까지 성공으로 바꾸지 않는다. 추천 v2의 저장 근거 검증, 유한 탐색 감사,
공동 재투자 실물 및 생성/조립 스킬 개편은 아직 구현하지 않았다.

## 추천 v2 저장 비교 경로 — 구현 중

optimization_contract={version:2,required_components:["items"],comparisons:[{result_id,
selected:"baseline" 또는 실제 variant 라벨,reason}]}를 명시하면 저장된 evaluate_delta
원본을 내용 해시로 읽고 실제 선택 입력의 서명/config와 현재 구성을 대조한다.
실제 변경된 구성 영역만 커버하며 비교 누락/미측정/진단 미해결/빈 통계/동일 대안은 거부한다.
optimizer 호출 도장은 요구하지 않는다. 선택 이유는 호출자 판단으로 표시하며 게임 성립·
전역 최적/품질 인증은 하지 않는다. 저장소는 로컬 신뢰 경계이며 암호학적 실행 인증이 아니다.
기존 v1과 합계105검사 통과(r4-comparison-readiness-v2.xml), 해당 mypy/Ruff 통과.
이는 첫 비교 검증 경로다. 실제 MCP/native 추천·출고·수동 아이템 경로와 전체 다층 판정,
대안 재개방·유한 탐색 및 스킬 개편은 계속 미완료다. 아직 제품 기본 경로로 전환하지 않았다.

실제 통합 보강: assemble_pob(input_policy=explicit)은 수동 희귀의 실행 도장 요구와
숨은 autofill만 생략하고 능력치 선택/정적/아이템/소켓/실제 native 편집 검사와 추천 근거
검사를 유지한다. r4-comparison-native-v3.xml에서 실제 MCP evaluate_delta 저장→v2 선택→
명시 조립→공유 코드·원래 선택 장비 보존을 확인했다. 관련 단위127검사 통과.
출고 엔진에서 정규화한 스펙으로도 근거 일치를 다시 검사했다. capability에 지원 범위를
추가했다. 전체 R4나 게임 성립 검증을 완료한 것은 아니다.

## 유한 탐색 범위 감사

| 도구 | 실제 범위/고정 기반 | 재설계에서의 사용 |
|---|---|---|
| optimize_tree | 입력 노드와 필수 앵커 경로를 보호, 새 가지 성장·가지치기. 반경/후보/시간/총 포인트 제한 | 기존 트리의 제거·재성장/전체 재배분과 구분. 다른 기반을 명시해 후보로 만들고 evaluate_delta로 비교 |
| optimize_items | 요청 슬롯·공급 후보·라운드/연쇄 측정 제한, 최종 후보별 실제 대체 문구 선택 반환 | 유틸 공급 여유로 다른 접사/노드를 재배분하는 것은 AI의 구성 묶음 과제. 슬롯 탐색 결과만으로 수행했다고 하지 않음 |
| optimize_rare | 지정 슬롯/베이스/롤 안에서 단독 접사 순위와 그리디 조립 재측정 | 다른 장비·트리 고정. 전수 조합/전체 빌드 최적이 아니며 미모델링 접사는 별도 진단 |
| evaluate_bundles | 명시한 패시브 묶음의 경로/합산·개별 차이 | 아이템/스킬을 포함한 전체 구성 묶음은 evaluate_delta 사용 |
| evaluate_delta | 명시한 전체 대안들을 실제 계산, 실패/누락과 비교 범위 반환 | 제거·재성장·장비/젬 공동 변경과 중간 약화 조합의 완성안 비교. 다음 대안 생성/선택은 AI |

트리 결과에 보호 기반·제외 노드·기존 트리 재배분 미수행과 수렴 범위를 추가했다.
희귀 결과에 지정 슬롯/베이스·고정 영역·롤/조건·완료된 로컬 패스와 미모델링 범위를
기계 판독 가능하게 추가하고 같은 근거를 derived_from에도 연결했다. 보호 기반/예산/
제외/희귀 및 추천 관련146검사가 통과했다(r4-search-scope-audit-v1.xml).
단위 회귀가 실제 공동 재투자 출구 세 사례나 일반 품질 향상을 대신하지 않는다.

## 실제 공동 재투자 대조 — 현재 두 사례

r4-joint-reinvestment-v3.xml: 실제 MCP evaluate_delta 원본을 저장한2사례 통과.
마나 사례는 원래 비용 보조가 있을 때 회복21.8/초와 소모14*1.428571429≈20/초,
공급 없이 시전 보조로 먼저 교체하면19*1.642857143≈31.21/초로 부족했다.
마나/재생 접사를 적용한 뒤 같은 보조 교체는 회복32.6/초로 계산상 경계를 넘었다.
속도1.42857→1.64286의 대가로 생명력1197→1187을 보존해 보고한다.
이는 해당 고정 공격·재생의 정적 PoB 비교이며 피격/이동/다른 스킬의 전체 전투 지속 인증이 아니다.
첫 v1은 원래 회복 여유가 커 인과 대조로 약했고, v2는 최종 회복31.2가 실제 소모보다
조금 부족해 실패했다. 둘 다 보존하며 v3로 소급해서 통과 처리하지 않는다.

저항 사례는 다른 반지로 공급을 옮긴 뒤 같은 화염 저항-30을 유지하고 생명력1197→1208을
얻었다. 저항 캡을 맞춘 서비스 가능한 빌드가 아니라, 공급 재배분을 계산하고 손익을
보존하는 작은 fixture다. 공급 장비만 바꾸면 저항-10/생명력1187이므로 단순 교체와
공동 재투자를 분리했다. 원본 스펙이 변하지 않음도 검사했다.
핵심 메커니즘 변경과 완성 트리 대안의 실제 대조·기각 근거는 여전히 남아 있다.

## 핵심 선택 변경과 전체 입력 트리 교체 대조

r4-mechanism-tree-v1.xml 실제 MCP/native1건 통과. Spark/True Strike61601의 공용 연결
트리17노드에서 Controlled Destruction을 적용하면 CritChance11.7→0, DPS4.457→5.0.
그 뒤61601을 제거한16노드 안도 DPS5.0으로 같아 기존 앵커의 현재 피해 기여가 사라졌음을
확인했다. Raw Power51184 경로로 전체 입력 트리를 교체한5노드 안은 DPS6.42857,
CritChance0이며 원래 트리의 노드를 보호 기반으로 강제 유지하지 않았다.
세 대안 모두 실제 계산/진단을 보존하고 원본 스펙 불변을 검사했다. 기존 치명타 앵커 유지안은
추가 포인트에 피해 기여가 없어 이 비교의 선택 근거에서 기각할 수 있다.
이는 완성 입력 집합을 교체하는 작은 fixture다. 레벨100 포인트를 모두 최적화한 빌드나
일반 모델의 판단 개선을 입증하지 않으며 실제 전투 조작/회복은 별도다.

현재 마나/보조, 부위 간 저항, 핵심 선택/전체 트리의 세 작은 대조는 확보했다.
R4 종합 출구 감사에는 설계 기록과 최종 추천의 연결, 실제 스킬/클라이언트 호출 경로,
미측정/미해결과 최종 주장 범위의 일치까지 남아 있다. 기본 전환/품질 평가는 R5~R7이다.

## 최종 추천과 기록 결박 — 구현·검증 중

v2의 design_ref는 불변 체크포인트를 다시 읽고 material 원본을 동일 검증기로 확인한다.
현재 추천과 spec 서명/config가 다르거나 참조/현재 근거/공급자 결박이 미검증이거나
채택된 결정의 review가 required이면 최종 추천을 차단한다. 진단·열린 질문·게임 성립
미인증은 별도 층으로 보존한다. 전략의 의미나 미검증 인게임 사실을 자동 확정하지 않는다.
