# 격노 아이스샷 제로 베이스 회귀 결과

2026-11-05. [사전 계획](POK_RAGE_ICE_SHOT_ZERO_BASE_EVAL.md)에 따른 단일 회귀.

**출처 보호와 탐색 경로는 작동했고 다른 구성 묶음도 발견했다. 그러나 3단계는
미완료·시간 초과다. 상세 앵커의 완성이나 빌드 품질 향상을 입증하지 못했다.**
이전안을 고친 결과가 아니라 새 기록·새 native 세션의 결과다. 알려진 레퍼런스를
이미 검토한 뒤의 회귀이므로 일반화·과적합 해소·#188 해결로 해석하지 않는다.

생성기의 제출이나 게임 성립·최적성을 대신하지 않는다.

## 2. 선택한 메커니즘과 이유

1. **부재 목걸이의 영원한 격노**를 재생 공급원으로 쓰고 양 무기 세트에서 유지한다.
   부여 인스턴스는 무료이며 일반 젬의100정신력과 구별했다. 처치 없는 보스와 팩 사이
   이동에서도 공급 경로를 확보하려는 선택이다. 초기 충전은 별도 비용이다.
2. **신비한 격노 성유+눈알 왕관**으로 격노 투자를 주문 피해 증가에도 사용하고,
   이를 공격에 적용한다. 패시브의 추가 주문 증가와 왕관의 증가/감소 적용 문구는
   연결된다. 원래 격노의 공격 more와 이 increased를 같은 종류의 배율로 합치지는
   않았다. 효과 크기·최종 DPS는 측정하지 않았다.
   [신비한 격노](https://poe2db.tw/us/Mystical_Rage),
   [눈알 왕관](https://poe2db.tw/us/Crown_of_Eyes).
3. **광폭+전직 퀄리티+Fox Idol**, **기본형 치장한 자+타락 마법 루비5개**로
   최대 격노를 늘린다. 루비는 최대 격노와 최대 화염 저항을 함께 공급한다.
   생성기의84~85격노는 이 목표 옵션의 산술값이며 캐릭터 측정값은 아니다.
4. **몽상+비고유 생명력 플라스크+약초학II+샤브론의 가방**으로 광폭의 생명력 손실과
   ES 회복을 같은 플라스크 투자로 처리한다. 일반 생명력 플라스크의 상시 적용과
   생명력 플라스크 회복의 ES 적용이라는 문구상 연결 및 사용 보고를 근거로 선택했다.
   이 회복이 큰 최대 피격 생존량을 보장하는 것은 아니다. 몸통·허리띠의 방어/공격
   옵션과 수동 생명력 플라스크를 포기한다.
   [몽상](https://poe2db.tw/us/Reverie),
   [샤브론의 가방](https://poe2db.tw/us/Shavronnes_Satchel).
5. **연금술사의 은혜**는 충전 공급과 플라스크 효과 중 공속으로 퀄리티 투자를
   재사용한다. 마나는 유한 플라스크와 **동결의 징표–착취의 징표II–영원한 징표**를
   함께 검토했다. 물리 명중·흡수 효율·징표 조건을 남겼고, 냉기 파편을 물리 흡수
   공급으로 세거나 영원한 징표를 영구 지속으로 읽지 않았다.
6. 직접 아이스샷에 **가루칸의 투지+초치명타**를 선택했다. 분기 치명타와 일반 치명타의
   기대값을 비교했으나 최종 치확·보너스·명중·패시브 기회비용은 미확정이다.
   가루칸을 보장 치명타로 부르거나 말리가로와 동시에 채택하지 않았다.
   [가루칸](https://poe2db.tw/us/Garukhans_Resolve),
   [초치명타](https://poe2db.tw/us/Supercritical).

**선정 방향은 설명 가능하지만 우승 조합으로 검증된 것은 아니다.** 특히 신비한
격노·회복 묶음에 투자한 만큼 다른 투구/몸통/허리띠/성유를 포기하므로 완성 묶음의
공격·방어 손익을 다시 비교해야 한다. 이번에는 그 비교를 끝내지 못했다.

## 4. 이전 동결안·레퍼런스와의 기능 비교

원본의 품목을 그대로 채택했는지 대신 기능·대가·누락을 비교했다. 기능적 대안은
동등 이상의 성능을 뜻하지 않는다. 레퍼런스 저장값과 새안 산수를 나눠 DPS 비율을
만들지 않았다. 레퍼런스의30격노 config는 최대 격노가 아니며 원시 노드 수만으로
원본을 초과 포인트 빌드라고 판정하지 않았다. 알려진 부여 스킬 정신력 음수도 제외했다.

## 5. 확인된 개선·새 문제·한계

- **#221 출처 보호**: 실제 원문만 호스트가 고정하고 모델의 사용자 고정 승격을 거부하는
  경계를 단위/실제 MCP로 확인했다. 이번 생성에도 잘못된 사용자 고정·대체 -plan 복제가
  없다. 이 결과는 새 초기화 경로 범위다. 기존 봉인 기록을 자동 고치거나 이후 사용자
  피드백의 새 고정 조건을 자동 등록하는 전체 이행을 완료한 것은 아니다.
- **#66 접근 개선**: 공용 변이 풀을 Rage/Quality/maximum Rage로 세 번 조회했다.
  기본형과 희귀 함양형을 동일 아이템에 합산하지 않았다. 특정 아이템의 적격 풀·교체
  대상·공존·확률은 여전히 별도이며 #66 전체 해결이 아니다.
- **공유 투자**: 격노→주문 증가→공격, 플라스크→생명력/ES/공속/충전,
  퀄리티→격노/냉각/자원이라는 묶음을 설명하고 채택했다. 그러나 같은 투자로 열리는
  다른 공격 증폭기와의 최종 비교는 빠졌다. 기재 수 증가 자체는 품질 증거가 아니다.
- **새 인터페이스 재현 #222**: record 스키마 조회는 편집 명령 스키마가 아니다.
  update의 changes가 자유 dict라 실행기가 set_extension/set_extensions를 세 번
  추측했고 일반 Unsupported 오류만 받았다. 실제 명령은 merge_extensions다.
  성공 후 다시 코드를 수정하지 않았고 오류 원문을 보존했다.
- **검색/회수 비용**: 존재하지 않는 접사/아이템 ID를 추측한 get_entry11회, 범위를 벗어난
  get_tool_result1회도 있었다. 전체 실패15회다. 없는 ID를 곧 수집 누락으로 신고하면
  안 된다. 3단계에서 이 추측과 방어 접사 조사에 시간이 사용됐지만, 전체 시간 초과의
  단독 원인이라는 인과 증거는 없다.
- **완성 병목**: 1·2단계에 약63분, 3단계에 약26분이 쓰였다. 전체 get_tool_result90회
  중50회가3단계다. 이는 회수 호출 수이지 토큰 수/낭비율이 아니다. 이벤트 직렬화 결과는
  약2.62MB이며 실제 모델 입력·과금 토큰으로 환산하지 않았다. 조사·작성·검증을
  구분한 시간 계측 없이 어느 한 부분을 범인으로 정하지 않는다.
- **필수/현재안 세분화**: 왕관과 +4격노 증강, 전직의 핵심과 편의 선택을 같은 필수
  앵커로 묶었다. 사용자 권한 오류는 예방했지만 최소 필요조건과 현재 구현의 세밀한
  분리는 아직 약하다. 실제 엔진이 이 선택을 사용자 고정처럼 잠갔다고 주장하지 않는다.
- **검사 한계**: 선언 검사는 포인트/속성 미해결을 잡았지만, 광폭 무보조·주력 저항
  처리 변경·강화 후보 미채택의 최적성까지 판정하지 않는다. 이 차이는 의미 판단의
  책임과 도구가 검출하는 계약 누락을 나눠 개선해야 함을 보여준다.

플라스크699.49/초·마나92.2초·치명타 기대계수 등은 조건부 산술 예시다. 전체 캐릭터
계산이나 게임 실측으로 보고하지 않는다. 플라스크 품질을 회복 접사와 별도 곱으로
계산한 것 자체를 오류로 판정하지도 않았다. 공개 PoB 구현은 해당 품질 항을 별도 곱으로
사용하지만, 그것만으로 모든 글로벌 효과·정수처리·인게임 유지가 검증되는 것은 아니다.
[PoB Item 구현](https://github.com/PathOfBuildingCommunity/PathOfBuilding-PoE2/blob/dev/src/Classes/Item.lua#L2540).
